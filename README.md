# MITE: Modern

开发者：**NingMeng123**。原作 Minecraft Is Too Easy 由 **Avernite** 创作。

将 Minecraft 1.6.4 MITE R196 的生存与成长规则重实现到 Minecraft 1.21.1 NeoForge，保留现代主世界地形、材质和功能内容，并逐项调整平衡。支持单人游戏和独立服务器。

## 当前状态

项目正在建立 R196 的规则证据、现代适配规格和可运行开发工程。**目前不是完成版 MITE 复刻，不应将工程能够启动视为全部玩法已实现。**

实现与验证状态见 [实施状态](docs/implementation-status.md)。每项玩法只有完成游戏实测后才会标为已验证。

已实现并实测：生命和饱食度上限随等级成长（0 级 3 格、5 级 4 格、35 级 10 格），饥饿值大于 0 时可疾跑，清空后停止。正等级经验采用 R196 曲线：累计 20 点到 1 级、50 点到 2 级、200 点到 5 级、6650 点到 35 级；经验球、命令、附魔扣级与保存共用一致的整数经验。

普通死亡时，经验不足 20 点会再扣 20 点，最低 −800 点（−40 级）；达到 20 点则重生归零。保留背包时保留经验。负等级用红色显示，经验球可抵扣负经验，死亡界面退出重进不会跳过或重复应用惩罚。双资源营养、完整代谢及其他生存系统仍在后续实现范围内。

死亡经验球按正累计经验的三分之一掉落，在死亡位置经过 20 个可进行实体更新的 tick 后生成，立即重生也不会丢失待发奖励。球按 UUID 归属于死亡玩家，只吸引并允许所属玩家拾取，存在 24000 个实体更新 tick，且不参与合并。归属与已生成球的正常保存重进已通过实机验证；普通经验球保留新版合并和 6000 tick 寿命。

采集速度随等级乘以 `1+0.02×等级`：−40 级为 0.2 倍，0 级不变，35 级为 1.7 倍，200 级为 5 倍。等级倍率已通过真实客户端按键挖掘验证并推送（`8559ede`）；创造与旁观保留现代行为，工具及环境修正不重复计算。

R196 通用基础挖掘进度已实测并推送（`99356a6`），按原始 float 顺序计算 `(1/(硬度/强度))/512`，并保留严格瞬破边界。在挖掘计算中将草方块有效硬度设为 0.5、砂和红沙设为 0.4；0 级有食物能量时空手挖泥土需要 256 次有效进度累加。方块全局硬度、爆炸抗性、现代工具与环境修正保持原值。实测覆盖五类开局方块和 35 级泥土，见 [基础挖掘适配](docs/mining-base-adaptation.md) 与 [008 验收](docs/testing/008-mining-base.md)。

无食物能量时的采集减速已实测并推送（`9609ca3`）：当前食物条为 0 时强度先除以 5，再乘等级倍率；恢复至 1 点即解除惩罚。仍使用现代单食物条，不把现代饱和度解释为 R196 营养。规则与证据见 [饥饿采集适配](docs/mining-hunger-adaptation.md) 和 [009 验收](docs/testing/009-mining-hunger.md)。

010 燧石开局材料与短斧已推送（`3c02d75`）：4 片燧石碎片可合成 1 块燧石，也可拆回；1 张皮革制成 4 个筋；1 燧石、2 木棍与 1 个筋或线，可在背包 2×2 中合成短斧。砂砾接入 R196 的碎片/整燧石概率分支，尚未移植的矿物分支暂回退为砂砾。短斧耐久 400、采集强度 2.5；原版原木有效硬度为 1.2，每块消耗 160 耐久，第三块破坏时短斧损坏。三种新物品使用新绘 16×16 透明像素材质，原版已有物品沿用新版材质。

规则、明确的现代适配和未覆盖范围见 [燧石开局适配](docs/flint-start-adaptation.md)、[010 验收](docs/testing/010-flint-start.md) 与 [材质生成记录](docs/art/textures-010.md)。实机合成测试的起始材料由测试器提供，不将其当成随机采砂或完整开局路线验证。

011 接入原木工具门槛：空手、普通物品、错误工具与木斧不能破坏默认 40 种原版原木/木块/菌柄及去皮变体，燧石短斧与现代石、金、铁、钻石、下界合金斧可用；高等级和急迫不能绕过工具资格。服务端在最终破坏时重新检查主手，中途换错工具仍会被拒绝；受阻时显示中文提示。木板、工作台、家具与竹块继续采用当前行为。标签提供数据包扩展入口；规则见 [原木门槛适配](docs/log-harvest-adaptation.md)，证据见 [011 验收](docs/testing/011-log-harvest.md)。其他材料采集等级、石矿门槛、便携下限与完整制造时间/经验/品质系统仍待实现；现代结构木板仍可通向石斧，燧石不是唯一取得原木的路线。

012 将原木剑改为**木棒**，继续使用 `minecraft:wooden_sword` ID：竖排 2 木板加 1 木棍合成，耐久 400、基础攻击 3，每次命中消耗 25 耐久，对四类原版骷髅的基础伤害翻倍；保留现代 1.6 次/秒冷却。采用新绘 16×16 像素材质，移除剑的横扫、蜘蛛网与竹子采集特权。木镐和木斧从普通配方、创造显示/搜索及战利品中移除，已有物品和命令注册继续兼容，木铲及木锄保留。实际工作台合成、两种禁用配方、普通目标/骷髅伤害和耗损均已实测；见 [木棒适配](docs/wooden-club-adaptation.md)、[012 验收](docs/testing/012-wooden-equipment.md) 与 [材质制作记录](docs/art/textures-012.md)。首镐的完整金属成长路线、旧格挡/触及/品质仍待后续实现。

013 修复木棒的显示变换，第一人称握持恢复向上直立、物品栏柄在左下；新绘 PNG 不变。草植物采集补回 R196 的有效硬度 0.02：0 级有食物时空手或木棒需 11 次有效累加（理论 0.55 秒，首次输入和连挖冷却另计）。覆盖短草、蕨、枯灌木，以及现代双格高草/大型蕨；原版铁剪刀对这些目标采用强度 8，正常状态仍可瞬间剪取。六项真实客户端采集及木棒左右手/第三人称已验收，见 [013 修复记录](docs/testing/013-grass-and-club.md) 与 [草类证据](docs/grass-mining-evidence.md)。

014 补上**燧石工作台与木板加工门槛**：背包 2×2 上排“燧石、线或筋”，下排“木棍、原木”制作工作台，替换旧四木板配方。沿用新版工作台材质和原版注册 ID。背包不能加工木板，需要放置工作台后加工；现代自动合成器保留基础加工能力。普通原木仍出 4 板，竹块出 2 竹板。服务端普通/快捷取出和配方书都受限制，见 [规则与适配](docs/flint-workbench-adaptation.md) 和 [014 实测](docs/testing/014-flint-workbench.md)。高级金属台、刀替代配方、制造时间/经验/品质尚未实现。

## 开发环境

- Java 21（64 位）
- Minecraft 1.21.1
- NeoForge 21.1.259
- ModDevGradle 2.0.148
- Windows 使用项目自带的 `gradlew.bat`

```powershell
.\gradlew.bat build
.\gradlew.bat runClient
.\gradlew.bat runServer
.\gradlew.bat runGameTestServer
```

使用独立测试存档，不导入 1.6.4 存档。

客户端、专服、GameTest 的运行目录分别为 `run/`、`run-server/`、`run-gametest/`。当前 78 组 GameTest 包括 3 组饱食度、9 组经验、9 组死亡、8 组死亡经验球、11 组采集、5 组燧石工具合成、4 组燧石工具、3 组砂砾掉落、7 组原木门槛、8 组木制装备、5 组草类采集和 6 组工作台测试，另有 150 项 JUnit 用例；本轮构建及全部自动测试通过。GameTest 与客户端测试代码均不进入发布 JAR；自动验证不能替代游戏内显示和操作验收。

经验功能的存档转换、200 级上限及现代接口选择见 [经验适配说明](docs/experience-adaptation.md)，死亡球规则见 [死亡经验球适配](docs/death-orb-adaptation.md)，采集倍率边界见 [采集等级适配](docs/mining-level-adaptation.md)。实测证据见 [004 经验曲线](docs/testing/004-experience.md)、[005 死亡与负等级](docs/testing/005-death-experience.md)、[006 死亡经验球](docs/testing/006-death-orbs.md) 和 [007 采集等级及寿命补测](docs/testing/007-mining-level.md)。基础进度六个案例的客户端总 tick、有效进度累加次数和服务端确认见 [008 基础挖掘验收](docs/testing/008-mining-base.md)；007 保留为此前仅叠加等级倍率时的历史证据，其挖掘计时不代表当前基础公式。普通球 6000 与死亡球 24000 个实体 tick 已从 Age=0 完整加速验证，未修改球龄；两个真实客户端联机及待发队列剩余延迟的实际关服重启尚未验证。

## 每个小功能的交付流程

1. 为功能记录 R196 证据或明确的现代适配设计。
2. 实现并通过适用的编译、自动测试和资源检查。
3. 打开开发客户端，在游戏内验证该功能，记录步骤、结果与证据。
4. 修复发现的问题并复测。
5. 使用中文提交说明，将通过实测的代码推送到指定 GitHub 仓库。

仅编译成功或仅通过 GameTest 不等于完成游戏实测。测试失败或尚未测试的功能不得推送为完成项。

专用测试副本中的长时等待可通过命令栏 `/tick rate` 加速，结束或中止后恢复 `/tick rate 20`；记录实际执行的模拟 tick 数，不把加速后的墙钟时间称为正常耗时。实机挖掘速度对比保持 20 TPS。
