# MITE: Modern

开发者：**NingMeng123**。原作 Minecraft Is Too Easy 由 **Avernite** 创作。

将 Minecraft 1.6.4 MITE R196 的生存与成长规则重实现到 Minecraft 1.21.1 NeoForge，保留现代主世界地形、材质和功能内容，并逐项调整平衡。支持单人游戏和独立服务器。

## 当前状态

项目正在建立 R196 的规则证据、现代适配规格和可运行开发工程。**目前不是完成版 MITE 复刻，不应将工程能够启动视为全部玩法已实现。**

实现与验证状态见 [实施状态](docs/implementation-status.md)。每项玩法只有完成游戏实测后才会标为已验证。

已实现并实测：生命和饱食度上限随等级成长（0 级 3 格、5 级 4 格、35 级 10 格），饥饿值大于 0 时可疾跑，清空后停止。正等级经验采用 R196 曲线：累计 20 点到 1 级、50 点到 2 级、200 点到 5 级、6650 点到 35 级；经验球、命令、附魔扣级与保存共用一致的整数经验。

普通死亡时，经验不足 20 点会再扣 20 点，最低 −800 点（−40 级）；达到 20 点则重生归零。保留背包时保留经验。负等级用红色显示，经验球可抵扣负经验，死亡界面退出重进不会跳过或重复应用惩罚。018 已接入双饱食/营养、基础代谢与微量营养，等待用户手测；其他生存系统继续分项实现。

死亡经验球按正累计经验的三分之一掉落，在死亡位置经过 20 个可进行实体更新的 tick 后生成，立即重生也不会丢失待发奖励。球按 UUID 归属于死亡玩家，只吸引并允许所属玩家拾取，存在 24000 个实体更新 tick，且不参与合并。归属与已生成球的正常保存重进已通过实机验证；普通经验球保留新版合并和 6000 tick 寿命。

采集速度随等级乘以 `1+0.02×等级`：−40 级为 0.2 倍，0 级不变，35 级为 1.7 倍，200 级为 5 倍。等级倍率已通过真实客户端按键挖掘验证并推送（`8559ede`）；创造与旁观保留现代行为，工具及环境修正不重复计算。

R196 通用基础挖掘进度已实测并推送（`99356a6`），按原始 float 顺序计算 `(1/(硬度/强度))/512`，并保留严格瞬破边界。在挖掘计算中将草方块有效硬度设为 0.5、砂和红沙设为 0.4；0 级有食物能量时空手挖泥土需要 256 次有效进度累加。方块全局硬度、爆炸抗性、现代工具与环境修正保持原值。实测覆盖五类开局方块和 35 级泥土，见 [基础挖掘适配](docs/mining-base-adaptation.md) 与 [008 验收](docs/testing/008-mining-base.md)。

无食物能量时的采集减速已实测并推送（`9609ca3`）：当时使用单食物条判断，强度先除以 5，再乘等级倍率。018 接入双资源后，改为饱食和营养都为 0 才触发，任一项恢复至 1 即解除；原版饱和度不解释为 R196 营养。原阶段规则与证据见 [饥饿采集适配](docs/mining-hunger-adaptation.md) 和 [009 验收](docs/testing/009-mining-hunger.md)，当前行为见 [018 食品与营养](docs/testing/018-food-nutrition.md)。

010 燧石开局材料与短斧已推送（`3c02d75`）：4 片燧石碎片可合成 1 块燧石，也可拆回；1 张皮革制成 4 个筋；1 燧石、2 木棍与 1 个筋或线，可在背包 2×2 中合成短斧。砂砾当时接入 R196 的碎片/整燧石概率分支，其余矿物分支已在 015 补齐。短斧耐久 400、采集强度 2.5；原版原木有效硬度为 1.2，每块消耗 160 耐久，第三块破坏时短斧损坏。三种新物品使用新绘 16×16 透明像素材质，原版已有物品沿用新版材质。

## 开发环境

- Java 21（64 位）
- Minecraft 1.21.1
- NeoForge 21.1.259
- ModDevGradle 2.0.148
- Windows 使用项目自带的 `gradlew.bat`

```powershell
.\gradlew.bat build
.\gradlew.bat runClient
.\gradlew.bat runServer
.\gradlew.bat runGameTestServer
```

使用独立测试存档，不导入 1.6.4 存档。

客户端、专服、GameTest 的运行目录分别为 `run/`、`run-server/`、`run-gametest/`，可用 `-PmiteGameTestDirectory=<目录>` 隔离测试世界。当前1132项JUnit与480项GameTest全部通过，覆盖生存、采集、制造、品质、食品、地底/门、矿脉、炉温、可选JEI适配和027/028新增内容。GameTest、手测物资函数与客户端测试代码均不进入发布JAR；自动验证不能替代游戏内显示和操作验收。更新生成资源时先单独运行 `runData`，成功后再运行构建和测试。

经验功能的存档转换、200 级之后的公式和原版整数存储边界见 [经验适配说明](docs/experience-adaptation.md)，死亡球规则见 [死亡经验球适配](docs/death-orb-adaptation.md)，采集倍率边界见 [采集等级适配](docs/mining-level-adaptation.md)。实测证据见 [004 经验曲线](docs/testing/004-experience.md)、[005 死亡与负等级](docs/testing/005-death-experience.md)、[006 死亡经验球](docs/testing/006-death-orbs.md) 和 [007 采集等级及寿命补测](docs/testing/007-mining-level.md)。004/007 中的 200 级封顶断言保留为当时历史记录，当前行为以 017 验收为准。基础进度六个案例的客户端总 tick、有效进度累加次数和服务端确认见 [008 基础挖掘验收](docs/testing/008-mining-base.md)；007 保留为此前仅叠加等级倍率时的历史证据，其挖掘计时不代表当前基础公式。普通球 6000 与死亡球 24000 个实体 tick 已从 Age=0 完整加速验证，未修改球龄；两个真实客户端联机及待发队列剩余延迟的实际关服重启尚未验证。

## 每个小功能的交付流程

1. 为功能记录 R196 证据或明确的现代适配设计。
2. 实现并通过适用的编译、自动测试和资源检查。
3. 向用户提供本批变更、游戏内操作步骤和预期结果，由用户手动验收；未获明确要求时不操作、重启或关闭用户游戏。
4. 根据用户反馈修复问题，并提供复测步骤。
5. 用户确认实测通过后，将代码推送到指定 GitHub 仓库。提交采用“类型: 中文标题”，正文用中文分条说明变更和验证；新增功能使用 `feat:`，问题修复使用 `fix:`，文档、测试和维护分别使用 `docs:`、`test:`、`chore:`，按实际变更区分类型。开发者署名统一为 `NingMeng123`。

仅编译成功或仅通过 GameTest 不等于完成游戏实测。测试失败或尚未测试的功能不得推送为完成项。

专用测试副本中的长时等待可通过命令栏 `/tick rate` 加速，结束或中止后恢复 `/tick rate 20`；记录实际执行的模拟 tick 数，不把加速后的墙钟时间称为正常耗时。实机挖掘速度对比保持 20 TPS。
