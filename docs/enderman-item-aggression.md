# R196 末影物品敌视

开发者：NingMeng123。原作：Avernite 的 MITE R196。

本批复刻末影人因玩家携带末影珍珠、末影之眼而主动敌视的规则，同时修正前批把末影人诅咒误写成免除外层视线的解释。以下 R196 文件位置均相对于 `.reference/r196/decompiled/`；发布包 SHA-256 为 `fb7ad265d05749e0cd1e54938f6c36ecbe9ea1d4d90d4a04c519615e1e0218c3`。结构化规格见 [enderman-item-aggression.json](../spec/enderman-item-aggression.json)。本文件记录来源与验收方法，不代表尚未执行的测试已经通过。

## 目标选择与触发顺序

末影人先在基础 64 格范围内选取最近的合法且可见玩家，再对这一名玩家检查敌视原因。它不会先筛选所有携带者，再跳过较近的普通玩家去找远处携带者。创造、旁观、死亡或不可攻击玩家不作为本条规则的有效目标。隐身和潜行仍影响现代原版的有效目标范围。

完整来源链是 `tg.findPlayerToAttack(64F)`（`tg.java:55-72`）→ `og.findPlayerToAttack`、`getClosestVulnerablePlayer`、默认返回 true 的 `requiresLineOfSightToTargets`（`og.java:1361-1374`）→ `abw.getClosestVulnerablePlayer` 的合法性、距离、最近者与视线检查（`abw.java:4056-4084`）。这些检查在 `tg.f` 前发生。源码与发布包字节码均已核对。

候选确定后，`tg.java:75-101` 按下列顺序执行：

1. 诱饵实体不触发。
2. 先抽取 `nextInt(3)`；掷出 0 且玩家有“末影人敌视”诅咒时返回敌对。该分支不设置物品的立即锁定标记。
3. 玩家主手持有珍珠或末影之眼，立即触发。现代副手持有这两种物品也立即触发，属于本项目明确的新版适配。
4. 没有通过前述分支时，统计两种物品总量 `N`。仅 `N > 0` 时抽取 `nextInt(2000)`；结果小于 `N` 就触发。
5. 未触发时，继续原版南瓜与普通凝视判断。

因此手持或库存触发不要求玩家盯着末影人，也能越过南瓜保护；**获取候选仍必须通过视线检查**，不能因携物隔着完整遮挡锁定玩家。诅咒分支优先：已受诅咒的玩家即使手持物品，若先命中诅咒分支，本次也保留该分支的普通预警节拍，不改判成手持立即触发。

## 库存范围与概率

R196 的 `uf.getNumItems` 委托 `ud.getNumItems`（`uf.java:2593-2594`、`ud.java:827-838`）。后者扫描 36 个主背包/快捷栏槽位和 4 个护甲槽位，按物品身份累加数量；不扫描鼠标拿起的物品、合成格、打开的箱子、末影箱或物品内部容器。主手是选中的快捷栏槽位（`uf.java:1899-1900`、`ud.java:18-24`）。珍珠与末影之眼注册见 `yc.java:113,126`。

现代统计使用玩家 `Inventory.countItem`，包含主背包、快捷栏、护甲和副手共 41 个槽位。快捷栏中的主手只统计一次；副手立即触发时不再执行库存抽签。普通箱子、末影箱、合成输入/输出、鼠标携带栈以及收纳袋、潜影盒内部物品均不计入数量。打开容器时，仍在玩家自己背包里的物品照常计入。

对没有先命中诅咒或手持分支的候选，库存检查本身的触发概率按每一次候选检查计算；下表不包含后续普通凝视或其他分支造成的总敌视概率：

| 两种物品合计数量 N | 本次库存检查触发概率 |
| ---: | ---: |
| 0 | 0%，不抽库存随机数 |
| 1 | 0.05% |
| 8 | 0.4% |
| 16 | 0.8% |
| 32 | 1.6% |
| 64 | 3.2% |
| 128 | 6.4% |
| 256 | 12.8% |
| 512 | 25.6% |
| 1000 | 50% |
| 2000 及以上 | 100% |

概率是 `N / 2000`（0 < N < 2000），**不是每秒概率**。原版旧 AI 空闲末影人会在每次旧 AI 更新中搜索玩家（`on.java:63-70`）；现代保留原生目标 Goal 的调度节拍，因此不能把表中的概率直接换算成固定几秒触发。低数量连续未触发是正常情况，手测无需用超过正常库存容量的物品数量制造必定触发。

需要缩短观察等待时，可以用 `/tick rate 200` 加速，测试完成后用 `/tick rate 20` 恢复。加速不会改变每次有效检查的概率。

字节码确认原作每类数量与两类求和都使用 Java `int`，无饱和封顶；正常物品数量下按上表计算。即使 `N >= 2000` 已必定触发，原作仍消费一次 `nextInt(2000)`。库存为 0 或负数时不消费它。主手立即分支也不消费库存随机数，但候选前面的 `nextInt(3)` 仍会消费。

## 立即锁定与追击边界

物品分支设置 `bt = 5`，随后同一次 `findPlayerToAttack` 执行 `if (bt++ == 5)`，马上返回玩家并进入敌视状态（`tg.java:60-66,82-91`）。所以物品触发成功没有额外 5 tick 倒计时。普通凝视的旧版计数从 0 开始需六次成功检查；本批保留现代普通凝视节拍，不迁移整套旧 AI。

已锁定目标后，拿走、丢出或交出末影物品不会直接调用清除仇恨。本实现保留现代原版追击、冻结、传送和怒气结束行为，不把“是否还携带”持续套在已锁定目标的凝视逻辑上。原作旧 AI 也没有专门的交出物品即停手判断，但它的通用寻路刷新/完成分支可能重新选择并清空目标（`on.java:134,197-210`）；本批没有移植该旧寻路重选行为。因此不承诺交出物品后永远追击，也不承诺立即停手。

现代范围继续使用原生 `TargetingConditions`、隐身可见度、阵营与 NeoForge 可见性扩展，并保留不可攻击自身乘客的保护。基础距离严格小于 64 格。R196 使用攻击者半身高度到玩家位置的距离并严格比较范围，潜行乘 0.8，隐身再乘 `0.7 × max(0.1, 已占用护甲槽比例)`（`abw.java:4067-4080`、`uf.java:998-1004`）。现代隐身有效范围保留原生的距离起点、修正后边界比较、至少 2 格范围及可见性扩展接口；这些细节属于明确的现代差异。声音沿用原生敌视状态同步反馈，不再额外发送来源玩家位置的凝视声，以免客户端叠播。

## 手动验收

在测试世界、平整且无遮挡的区域操作，保持生存模式、夜间、无雨。使用有正常 AI 的末影人；示例不添加 `NoAI`：

```mcfunction
/time set night
/weather clear
/gamemode survival
/mite curse clear @s
/clear @s minecraft:ender_pearl
/clear @s minecraft:ender_eye
/item replace entity @s armor.head with minecraft:carved_pumpkin
/summon minecraft:enderman ~ ~ ~8 {PersistenceRequired:1b}
```

佩戴南瓜或背对末影人，避免普通凝视混入结果。不同用例之间使用新的末影人，先结束上次追击，再清理主副手和相关库存；不要拿已经锁定目标的末影人测试“是否会新触发”。晴天和雨水都可能干扰末影人的停留与传送，检查时保持上述条件。

- **主手立即触发**：在没有诅咒的情况下，主手拿 1 个珍珠；应不依赖凝视或库存随机等待，开始主动敌视。再用末影之眼重复。
- **副手适配**：主手拿普通物品，仅副手拿珍珠或末影之眼；应同样立即触发，主手物品不消耗。
- **普通库存随机触发**：将 16 或 64 个物品按正常堆叠放入背包，主副手均不持有这两种物品；保持南瓜或背对，观察可随机触发。少量重复未触发不能直接判为故障；要结合自动随机边界测试检查概率。
- **两种物品合计**：珍珠与末影之眼分放背包，确保不在手上；应使用两种数量之和，而不是只统计其中一种或仅统计物品栈数。
- **空库存对照**：没有相关诅咒、主副手和背包均无两种物品、佩戴南瓜或不凝视时，不应因本规则触发。
- **普通凝视对照**：清空相关物品与诅咒，卸下南瓜，再直视一只新的末影人；普通凝视仍应正常激怒它。
- **视线遮挡**：先建立完整不透明遮挡，再生成新的末影人并手持珍珠。遮挡始终阻断视线时不应隔墙因携物锁定；末影人绕到墙外或传送至可见处后，正常触发不属于穿墙。
- **容器排除**：玩家库存和双手清空，仅把物品放在箱子、末影箱、合成格、鼠标上或背包中的收纳容器内部，保持无凝视；这些位置不触发本条库存计数。
- **追击后交出物品**：先以手持触发，再收起或丢出物品；允许继续追击，不应把交出物品当作立即清除仇恨的手段。
- **诅咒回归**：用管理员诅咒测试命令施加“末影人敌视”时，其 1/3 分支仍先于物品判断；完整墙体仍阻止获取候选。普通凝视、已锁定后的注视冻结与传送保持现代原生行为。
- **联机最近候选**：较近的合法可见玩家无物品且不凝视，较远玩家携带物品；本轮先检查较近者。较近者离开或不可见后，较远者才能成为本轮候选。创造/旁观玩家不应用于阻挡合法候选。

自动验证应覆盖随机阈值、零数量不抽签、诅咒优先、主副手、槽位排除、最近候选、视线与原生 Goal 实际锁定；实际运行结果由本轮测试报告记录。
