# R196 来源货单与现代村民

开发署名：NingMeng123。来源：本地 R196 `ub.java:290–414,434–468,525–599`。本文件说明普通世界可生成的来源货单和现代接入，不把未运行的验证写作通过。

`SourceVillagerTradeRules` 完整枚举 `ub.q` 的75个可达候选：旧农夫13项、图书管理员8项、牧师11项、黑匠31项、屠夫12项。不是只补铜装备；还包括普通买卖、砂砾加工、附魔书和牧师的铜/铁装备附魔服务。静态买入价格表中未被 `q` 调用的种子、腐肉、珍珠等条目没有加入；旧 `Offers` 迁移分支的祛魔瓶和已移除金属小刀也没有加入。

现代职业、工作站、等级、升级、补货、商人经验、声誉折扣及已有货单继续使用原生流程。每个现代等级额外执行一次来源 `q(1)` 式候选选择；读取已有高等级村民时补齐已达到等级的次数，保存来源职业、已处理等级与已抽到的来源条目。重复打开界面、保存、重登、补货不会重新抽取或重复追加；新等级至多增加一条未拥有的来源货单。真实职业变化与原生清货单同步清除来源标记，因此失业后重新取得同一职业，即使失业期间没人打开交易，也会补充新货单；加载保存职业的过程独立保护原标记，避免把正常重载当成换职业。已有现代货单不被替换。来源货单初始可交易7次，随现代补货恢复；不重建旧版“交易最后一项再逐条扩货”的职业生命周期。

每项先按来源概率 `base + sqrt(已有来源货单数)×0.2` 判断；超过0.9时反射为 `0.9−(value−0.9)`。入池者等概率选一项，空池使用来源的买金锭兜底。来源条目去重，不覆盖已有现代报价。分拆到现代职业后，各候选的入池概率与价格仍按来源，但**整个职业池的最终选中分布、每名村民扩货次数及随机数调用顺序不声称等同旧版**；这是保留现代职业结构的明确适配。

所有普通区间按旧版上界不包含的整数抽取。买入先把区间两个端点分别限制到真实来源堆叠上限，再抽取：小麦18..21因此成为固定16，白羊毛14..21成为固定8。单绿宝石购买多件商品的产量和普通正价格同样保留来源上限处理。砂砾加工收4砂砾+1绿宝石，出售4或5燧石，符合当前砂砾上限4。旧单项书籍/装备的随机生成继续使用38种来源附魔。

附魔书原交易**确实消耗1本普通书及绿宝石**，不是免费把任意书转换：`ub.java:329` 为 `new abl(new ye(yc.aN), new ye(yc.bJ,var6),var11)`，其中 `aN` 为普通书。来源随机选择一种附魔和合法等级，绿宝石费用 `2+nextInt(5+等级×10)+3×等级`，最高71。

现代只有两个成本槽，每槽绿宝石上限32。因此原价≤32时保留“1普通书+原价绿宝石”；原价33..64时用两个合法绿宝石堆支付完整原价，此高价分支不另收普通书；原价65..71限制为两槽可容纳的64。不能把所有高价书压为32。此处的少量降价与高价书普通书成本豁免是两槽容量适配，明确区别于原作。实际界面展示全部支付项，不暗扣玩家其他格子的物品。

牧师附魔服务消耗指定的原始装备和2..4绿宝石，产出新生成的对应来源装备，附魔原始能量5..19并走现有来源材质压缩/选择。来源本身不是铁砧合并，不复制交入装备的名称、损伤或其他附魔。

验证入口：`SourceVillagerTradeRulesTest` 核对75项范围、概率反射、端点截断和附魔书32/33/64/65/71边界；`SourceVillagerTradesGameTests` 遍历真实注册物品生成全部报价，检查现代货单共存、原生保存读取及补货、不重复追加，使用真正 `MerchantMenu` 点击完成铜镐/砂砾加工和各价格边界附魔书付款。上述验证均已执行通过，实际结果见[本轮统一验证](testing/r196-parity-implementation.md)。

手测使用普通职业村民反复打开界面，已有报价应保持；升级后最多多出一项来源报价。工具匠/盔甲匠/武器匠有机会提供对应铜装备，牧师有机会提供带原装备成本的附魔服务。每名村民是随机货单，单个村民没有出现某项不代表该项缺失。保存重进与正常补货不应反复刷新货单。附魔书高价分支应显示两个绿宝石成本，并能用两堆各不超过32的绿宝石完成。
