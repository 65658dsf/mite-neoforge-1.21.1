# R196 难度体系来源与现代适配

开发署名：NingMeng123。原作：Avernite。版本基准为本地 `MITE 1.6.4 R196.zip`；发布包与相关原始 class 的 SHA-256、可供校验使用的数值夹具见 [难度规格](../spec/difficulty-system.json)。

## 固定极难与原版难度编号

R196 没有增加第五种世界难度。`assets/minecraft/lang/MITE.lang:40` 将 `options.difficulty.hard` 翻译为 `Extreme`，而实际世界难度编号始终是原版困难的 **3**。这不是极限模式；`hardcore` 仍是独立存档字段，不会因启用极难而增加永久死亡规则。

| 入口 | 实际来源行为 |
| --- | --- |
| 客户端配置 | `aul.java:83,112,122,224–226,344–345,424–425`：固定编号 3，构造、加载、切换和显示均不采用用户写入的其它难度 |
| 设置按钮 | `avw.java:27–33`：禁用难度切换；极限模式文字另行处理 |
| `/difficulty` | `aj.java:26–28`：只回复命令不可用，不执行其下方遗留的 0～3 解析辅助方法 |
| 集成服务器 | `bkz.java:109–111`：难度获取直接返回 3 |
| 独立服务器 | `is.java:102,215–217`：服务器属性写入 3，难度获取直接返回 3 |
| 所有维度 | `net/minecraft/server/MinecraftServer.java:785–791`：设置方法忽略传入难度，为四个已存在的世界写入 3，并启用怪物和动物生成 |
| 世界与存档 | `js.java:175–177` 保留极限模式提升至困难的旧分支；`WorldInfoShared`、`acd` 保存极限模式和其它世界设置，不提供另一套可增长的世界难度字段 |

已检查原始 class 的 `javap -c -p`：集成服与独立服难度获取方法均仅包含 `iconst_3; ireturn`；服务器设置方法在 offset 23–24 使用 `iconst_3; putfield js.r`，没有读取传入参数；命令执行方法只构建不可用提示。这些是实际启用路径，不能因为解析方法、原版四档文本或极限模式分支仍然存在就认定默认可切换。

现代版本沿用 `Difficulty.HARD` 的编号与协议。服务端是唯一难度判定来源，客户端设置、创建世界参数、`server.properties` 与指令不能将运行中的世界降为和平、简单或普通。现代怪物和结构继续使用原有接口，极限模式单独保留。

## 区域紧张度公式

`abw.java:4549–4570` 的 `b(double,double,double)` 将坐标向下取整后调用 `I(int,int,int)`。该函数返回无量纲的区域紧张度，和现代 `DifficultyInstance` 的数值定义不同。

```text
hard = difficulty == 3
tension = 0
if position is valid and its chunk is loaded:
    tension += clamp(float(inhabitedTime) / 3600000F, 0, 1) * (hard ? 1 : 0.75)
    tension += rawMoonPhaseFraction * 0.25
if difficulty < 2:
    tension *= difficulty / 2F
return clamp(tension, 0, hard ? 1.5 : 1)
```

实际生产路径固定 `difficulty=3`。普通月相输入范围为 0～1，故实际最大值为 **1.25**；字节码的最终上限仍保留 **1.5**，不能把两者混为一谈。刚进入且尚无居住时长的区块也保留月相贡献；新月时为 0，满月时为 0.25。居住 1,800,000 tick 后区块项为 0.5，居住 3,600,000 tick 后为 1；20 TPS 下后者相当于 50 小时。

除先将 long 时长转换为 float，再进行浮点除法之外，不做整数截断。2 tick 的区块项为 `Float.intBitsToFloat(0x3515217d)`；3,599,999 tick 的区块项为 `Float.intBitsToFloat(0x3f7ffffb)`，尚未达到 1。源码没有总天数增加的基础项，也没有玩家等级、附近玩家人数、最高装备或访问下界后的通用倍率。日期或玩家进度影响个别生物／结构时，应继续使用各自已经确认的规则，不能再乘一次未经来源证明的难度倍率。

原 `abw.f:805–806` 的有效位置为 `0 <= Y < 256` 且区块已加载。现代适配使用目标维度的实际高度范围，因此主世界负数高度与地底世界都能正常计算；未加载的区块返回 0，不为了查询难度而额外生成或加载区块。

## 月相和时长来源

`abw.x:1948–1949` 使用 `aei.a` 的原始相位数组 `[1, 0.75, 0.5, 0.25, 0, 0.25, 0.5, 0.75]`。`aei.a(long):103–104` 的相位索引是 `(int)(worldTime/24000 + 1) % 8`：tick 0 对应 0.75，tick 168000 对应满月 1。这一输入不是渲染用月光亮度，不受下雨、蓝月、血月或丰收之月的独立月光加成影响。

`R196DifficultyRules.phaseFraction(long)` 对非负世界时间保留上述八相循环。对现代命令可能设置的负数时间，采用 `floorDiv` 与 `floorMod` 连续延伸周期，避免原源码的负数组下标；这属于明确的现代输入边界适配。对 `Long.MIN_VALUE`／`Long.MAX_VALUE` 也不会发生相位偏移加法溢出。

`jq.java:28–30,36–61` 在第一名玩家开始观测区块时记录世界时间，最后一名玩家停止观测时结算；`jp.b:32–43` 每次间隔超过 8000 世界 tick 时刷新所有正在观测的区块。累加的是时间差，不会因两名玩家同时停留而翻倍。`aee.java:257,426` 将其写入并恢复为 `InhabitedTime`。现代接入使用现代区块已有的居住时长及保存机制，不另建一份会重复积累的计数器。

## 实际消费紧张度的规则

| 调用 | 启用行为 |
| --- | --- |
| `og.bw:851–876` | 装甲生成概率 `0.15 * tension`；材质基础 `nextInt(2)`，随后三次各 9.5% 升一档；困难时每个后续装备位置有 10% 概率停止 |
| `og.enchantEquipment:971–976` | 附魔概率 `0.1 * tension`；能量 `int(5 + tension * nextInt(18))`；`ye.randomizeForMob:895–901` 的启用路径实际调用 |
| `tt.a:32–41` | 困难难度下蜘蛛群组药水强化概率 `0.1 * tension`；同组共享强化数据 |
| `tw.a:257–288` | 领袖僵尸概率 `0.05 * tension`；命中后设置增援和生命属性。随机击退抗性的 `[0,0.05F)` 加值独立抽取，不再乘紧张度 |

共用服务端入口提供同一套紧张度，已复刻的装备、蜘蛛和僵尸逻辑继续从该入口读取。现代后续新增的生物保留自己的原版行为，不将旧版紧张度强行当作其 `DifficultyInstance`，也不全局替换现代的区域难度对象。

普通僵尸、僵尸村民、僵尸猪人的生成初始化也仅匹配这三个原版实体 ID。`tw.az:37–43` 在构造时给增援概率设置 `nextDouble() * (double)0.1F`；`tn.az:22–27` 继承后将其基值设为 0。`tw.a` 后半段没有第二次重抽该基值，也没有现代 `nextDouble()*1.5*localMultiplier` 的额外总乘法索敌距离加成。仅保留 `og.a:978–980` 的高斯 `FOLLOW_RANGE` 基值乘法加成；`tw.a` 本身的第一次属性抽样直接用于击退抗性，然后抽取领袖概率。

现代 `Mob.finalizeSpawn` 的默认基值加成来自世界随机源的 `triangle(0,0.11485)`，不等于 R196 的实体随机源 `nextGaussian()*0.05`。窄注入在调用现代父流程前先安装源高斯修饰符，使用父流程已有的“修饰符已存在”判断跳过三角分布；原生生成原因记录和现代左右手设置继续执行。该处理不改变其它生物的父流程。

属性对应已与官方 1.6.4 未被 R196 覆盖的 `tp.class` 静态初始化字节码核对：offset 56 的字符串为 `generic.knockbackResistance`，offset 69 写入 `tp.c`，因此该项不能误标为护甲。源 `tw.a` offset 261 乘数是 float 提升后的 `0.05000000074505806D`，现代实现保留这项类型转换。

`tn.a:155–159` 明确调用 `super.a(group)`，随后仅清除村民标志，故猪人同样参与固定可拾取物品、击退抗性和领袖抽样；基础援军 0 不代表完全禁止领袖增援加值。现有猪人专属黄金武器、无随机护甲和成年规则继续使用各自接口。`SourceZombieDifficultyMixin` 保留 NeoForge 原生生成元数据、群组和事件链，替换这些来源已确证的难度字段；尸壳、溺尸以及已有独立初始化的冤魂均不进入此分支。已生成实体从存档恢复时不重跑初始化，不破坏旧存档属性。

## 玩家受到的伤害

`uf.java:967–985 attackEntityFrom(Damage)` 没有按和平、简单、普通、困难档位再次缩放普通怪物伤害。只在爆炸时调用 `damage.scaleAmount(1.5F)`；已核对 class 字节码 offset 61–75。本次保留正常伤害事件、取消、免疫和防具流程，只在现代 `Player.hurt` 真正调用的 NeoForge `IScalingFunction.scaleDamage` 位置替换默认缩放。不能修改已被 NeoForge 置为不可执行分支的旧原版难度代码来假定实现完成。

已有 `R196ExplosionCalculator` 只实现 `abr` 爆炸基础公式，尚未包含 `uf` 的玩家倍率，因此这里对玩家再乘一次 1.5。普通怪物近战、箭矢、玩家攻击和环境伤害不额外乘 HARD 系数。其他模组显式提供自定义 NeoForge 缩放函数时保留其结果，不再叠加默认源规则。

## 验收边界

自动化数值夹具覆盖 0／1／2／3 的完整遗留分支、空区块、无效位置、2 tick、半额与临界居住时长、超额钳制、原始月相及负数／最大 long 时间。运行集成应另验证服务端启动、修改指令、存档重进、客户端同步、跨维度及 1.21.1 的负高度。公式中没有传入玩家等级，等月相且等居住时长时，世界第 1 天、第 9 天和第 1,000,001 天的区域值相同。
