# R196 自动使用与物品补货

开发署名：NingMeng123。依据本地 Minecraft 1.6.4 MITE R196 发布包，目标为 Minecraft 1.21.1 NeoForge。

本批补入 AUM、两种自动模式的绿色快捷栏提示、吃喝间隔，以及真实物品耗尽后的自动换持和补货。原有 AHM 的同类方块匹配、现实 5 秒超时和原生挖掘规则继续使用 [既有说明](auto-harvest-input.md)。

## 操作

AHM：先单独按住攻击键开始挖掘，再按使用键，先松使用键再松攻击键。继续瞄准同类方块可自动挖掘；单击攻击键、单独使用键、打开界面或换栏会退出。该模式不会自动连打生物。

AUM：主手持有可吃喝物品，先单独按使用键，再按攻击键，随后释放两键。物品会继续使用，下一次攻击键取消；取消键也不会在同刻误触发攻击或开始持续挖掘。饱食或营养已满而不能摄入时，模式可保持等待，能合法摄入后再继续。它不绕过反胃、水下、女巫禁食、物品冷却或服务端摄入资格。

两种模式互斥，生效时选中快捷栏的背景和边框变绿。失焦、菜单、聊天、死亡、睡眠、断线、切换世界或按键绑定后都清理状态。两种模式均按实际攻击/使用绑定判断，重绑定后不限定鼠标按钮。

AUM 只支持主手 EAT/DRINK 动作；普通方块放置、拉弓、武器格挡和副手自动使用没有加入。自动重复使用直接进入原生主手物品使用事务，瞄准箱子或生物时不会自动开箱、交易、喂养或放置物品；玩家实际按使用键时仍保留正常原生交互。

## 来源与现代边界

- `bdc.java:414–440` 和 `EnumItemInUseAction.java:12–13` 确认 AUM 只接受吃喝；`atv.java:1565–1591,1611–1639` 提供保持使用、组合按键和取消路径。
- `avj.java:133–138` 的来源着色只关联 AUM。本批为两个模式都绘制绿色背景与边框，属于用户指定的界面补充；不替换原物品模型、数量或耐久显示。
- `bdi.java:312–320`、`bdc.java:339–344`、`uf.java:2291–2307` 在吃喝完成后限制下一次摄入，间隔为现实 1000 毫秒。客户端原生 Finish 事件登记截止时间，在 `MultiPlayerGameMode.useItem` 进入原生预测、发送使用包及启动本地进食状态之前检查下一口是否就绪，不会打断已经开始的使用。这不是服务端新增的强制冷却；`/tick rate` 不缩短现实间隔。
- AUM 可在空手时短暂等待补货。最后一份汤、药水或奶返回容器时，只允许该次真实完成事件记录的容器等待确认；手动换物仍取消。同物品的服务端自动换栏可保持 AUM，普通手动换栏清理它。

## 自动换持与补货

旧 `ud.java:61–145,702–708`、`jv.java:1446–1452`、`bcw.java:1156–1168` 和 `atv.java:1596–1600` 共同实现“上一件物品用完后选相似物品”；不是根据准星自动选最佳工具。

新版由真实服务端物品使用、放置、食用完成、释放弓或三叉戟、挖掘损坏、近战损坏入口登记主手的前后快照。手动丢弃、背包移动和副手消耗不会触发。保持物品时不补满已有栈。

来源优先级为：同物品 100 分；来源允许的同类工具/弓 99 分；方向性的备用工具按来源类列表递减；容器、砂砾转铲及木棒转木棍/骨头使用对应来源低分。不同材质钓竿没有额外同类回退。药水内容和符文石符号分别匹配旧 subtype，不因物品 ID 相同而自动换成另一种药水或符号。

按“当前快捷栏位置往右、绕回左侧、最后背包”的顺序扫描，只有更高分替换候选，同分保留先遇到者。同物品的背包候选因此可能优先于快捷栏的相似工具。快捷栏候选可立即切换；背包候选至少等待现实 250 毫秒，且只有当前槽为空时才整栈移入。空碗、空桶等返还物不会被覆盖或丢弃。没有可完成的候选时结束等待，登记现实 3000 毫秒后过期。

库存变更只在服务端主线程进行，执行前重新核对人物、选中槽和原动作后栈快照。打开界面、手动换栏、死亡或睡眠会取消；候选整栈移动，保留名称、附魔、品质、损伤和其他组件。普通玩家背包、聊天和菜单通过只传开/关的界面状态包暂停本人的自动动作；打开时清除待补货，暂停期间即便上一口稍后才完成也不登记，关闭不会恢复旧请求。服务端仅通知合法换栏结果，客户端不能申报库存内容或要求服务器生成物品。未持久化短期输入/补货状态，重连不会恢复自动操作。

## 验证入口

规则测试为 `AutoUseStateTest`、`IngestionDelayTest`、`AutoRestockRulesTest`，覆盖手势顺序、取消、容器等待、1000 毫秒边界、槽位顺序和方向性替代。

`AutoRestockGameTests` 通过真实 ServerPlayer 和原生事务验证投掷、放置、食用、挖掘及近战损坏；另覆盖计时、菜单、换栏、容器余物、符文、钓竿与组件守恒。`AutoHarvestInputAudit` 在无窗口环境检查实际 Minecraft/Gui/MouseHandler 变换、原生挖掘链、限定吃喝入口、绿色底框和现实计时；该检查不等于已经观察游戏画面。

2026-10-23 修正长按使用键连续进食时第二口动画卡住的问题：原先客户端在 `LivingEntityUseItemEvent.Start` 取消间隔内的下一口，`LocalPlayer.startUsingItem` 却仍设置使用标记，原生使用包也仍发送，导致客户端与服务端状态不一致。现在在原生物品使用事务入口提前拦截，普通长按与 AUM 共用此入口，主副手按实际物品判断；间隔内消费本次输入而不启动物品使用，避免主手等待时继续尝试副手的盾牌或桶。保留原有食用时长、现实一秒间隔及非吃喝物品的使用行为。喷溅/滞留药水虽继承 `DRINK` 动作，但实际是即时投掷，明确排除于摄入间隔和 AUM 资格之外。

本次专项验证：新增客户端变换检查在旧实现上因延迟取消 Start 事件而失败，修复后构建、1,722 项 JUnit 和客户端变换检查通过，确认间隔检查先于物品预测和使用包发送，普通长按与 AUM 共用入口且覆盖主副手。日志为 `build/verification/continuous-eating-before2.log`、`build/verification/continuous-eating-after.log`，结果为 `build/verification/continuous-eating-after.json`。检查未创建游戏窗口，实际游戏内连续进食仍需按下方步骤复测。

上述验证均已执行通过，完整结果及发布包见[本轮交付验证](testing/r196-parity-implementation.md)。

## 手动验收

1. 生存模式按先左后右开启 AHM，松开后继续挖同类方块，确认选中槽绿色，点击左键取消后颜色恢复。看空气超过现实 5 秒应结束。
2. 降低饱食/营养，主手拿多份苹果，按先右后左开启 AUM，松开双键。应自动连续进食，每次完成后至少隔现实 1 秒再开始；单击左键立即取消，且这次取消不攻击或挖掘准星目标。
3. AUM 时瞄准箱子、村民和动物，应只吃喝。分别用药水、奶、汤测试；尝试用弓、方块、盾牌开启，不应锁定这些动作。打开界面或切出窗口后回来不应恢复自动使用。
4. 快捷栏放两组相同食物，第一组最后一件用完后应自动换持同种物品。汤和药水返回的容器应保留，快捷栏下一份相同食物可继续 AUM；只有背包有下一份且当前槽有空容器时，不应覆盖容器强行补货。
5. 用完最后一枚雪球或最后一块方块，测试快捷栏自动切换及背包空槽补入。对带自定义名称、附魔或品质的备用工具检查组件保留和总数量。
6. 用不同符号符文石或不同药水测试，不应自动换成另一符号/内容。手动丢弃物品、副手消耗、打开箱子、手动换栏和重连都不应开始自动搬运。
7. 主手拿多份种子或苹果，持续按住使用键吃至少三口；每口完成后应等现实一秒再正常开始下一口，动画应重新开始，物品每口只减少一份。分别测试中途松开再按、切换快捷栏、主副手吃喝及汤/奶/药水，确认没有卡住的进食标记；弓、盾牌和普通方块交互正常。
