# R196 食用作物机制来源核对

署名：NingMeng123。版本基准：本地 `MITE 1.6.4 R196.zip`，复刻基线 `52dc38309f8cea754fc626e8f5a9b5f69aef36df`。

本文件记录独立提取的原版证据，具体实现与手测完成度由对应实现文档记录。结构化规则、原始 class SHA-256、反编译文件 SHA-256、方法范围及规范化方法 SHA-256 见 [crop-source.json](../spec/crop-source.json)。未执行旧版游戏，也未复制旧版方法正文。

## 覆盖与调用链

- `aqz` 注册的小麦、胡萝卜、马铃薯、洋葱均继承 `anr → BlockGrowingPlant → BlockPlant → aqz`；死亡方块继承 `BlockCropsDead`，停止随机刻且无掉落。
- 依据 `anr.updateTick` 和 `javap -p -c anr` 校对真实分支、随机调用顺序；依据 `BlockBreakInfo`、`aqz.dropBlockAsEntityItem` 继续追到最终生成物品，避免只看子类便误判掉落。
- 血月额外感染已由月相功能接入。本轮只须调用共享入口，不能再抽第二次 25% 感染。
- 耕地 `aof`、种植物品 `yv/yw`、骨粉 `xl`、粪便 `ItemManure`、降雪 `js.placeSnowfallAt` 及农业附魔的调用也纳入核对。

## 生存与成长

种植需要耕地。原作全部四种作物内部年龄都是 0～7，成熟为 7，显示帧数并不等于内部年龄数。胡萝卜、马铃薯显示映射为 `0,0,1,1,2,2,2,3`，洋葱为 `0,1,1,2,2,3,3,4`。

植物是否合法与能否成长使用不同光照：存活检查当前位置未扣天光衰减的亮度 8～15，露天可免除这一检查，所以露天夜晚不会仅因黑暗自毁；成长及自然感染读取上方一格计入天光衰减的邻块亮度，成长只接受 15。移除支撑、邻居变化和随机刻均可能先触发合法性检查。有玩家在 16 格内时非法植物请求 `was_not_legal` 掉落再移除；附近无玩家则直接移除。

成长公式按以下顺序相乘：

1. 正下方耕地湿度为 0 时直接得到 0，否则从 1 开始，加上九宫格耕地贡献；原始 metadata 为 0 的耕地贡献 1，非 0 贡献 3，非中心格再除以 4。
2. 出现同种对角作物，或东西与南北两个轴都有同种作物时，总值除以 2 一次。
3. 正下方耕地施肥时乘 1.5。
4. 温度以生物群系基础温度为准，最适区间为 0.8～1.2，超出区间每差 1 降至 0。普通作物的湿度成长倍率始终为 1。
5. 乘全局成长倍率 0.25，再乘同种作物邻接倍率。

邻接倍率：没有四向同种邻株为 0.5，至少两个为 1；只有一个时，若该邻株再连接另一株同种作物则为 1，否则孤立的两株为 0.75。它与九宫格拥挤减半同时生效。

注意耕地贡献判断的是原始 metadata，而不是单独湿度：干燥但已施肥的相邻耕地 metadata 为 8，仍贡献 3；正下方干燥耕地则依然触发成长为 0 的前置规则。现代状态拆分后必须保留这一效果。

健康、未成熟且亮度恰好 15 时，`nextInt((int)(25 / growthRate) + 1) == 0` 增长一个年龄。仅成功增长后再抽 `nextInt(256)`，抽到 0 且下方仍为施肥耕地时清除肥力。成熟植物仍继续随机刻，以便染病。

## 干旱、病害与治疗

真实处理顺序是：合法性 → 计算成长率 → 干旱 → 已染病的死亡/传播 → 血月额外感染 → 日常感染 → 成长 → 肥力消耗。

成长率为 0 且土壤附近没有水、冰或雪等原作灌溉源时进入干旱分支，每随机刻 5%。幼株变成保留年龄的死亡作物；成熟作物按干旱原因掉落后消失。即使此次 5% 未中，也不继续尝试感染或成长。

已染病作物先抽 1/64 死亡，成熟年龄 7 降为 6；存活时再抽布尔值，一半停止，一半按 `dx → dy → dz` 顺序各抽 -1～1 的邻居。目标不是中心、区块已加载且为任意种活的未感染 `anr` 时传播，所以小麦与根菜之间可以交叉传播。原作没有限定只感染同一品种。

日常病害概率为：

`基础概率 × max((1 − 到温度区间[1.0,1.2]的距离) × 高湿倍率, 0) × (1 − 上方亮度/16)`

基础概率普通作物 0.0005，马铃薯 0.001；生物群系 downfall 严格大于 0.85 为高湿，高湿倍率 1.5，否则 1。病害温度区间与成长最适区间不同。晴天亮度 15 仍保留 1/16 的感染因子，并非完全免疫。

血月的额外 25% 露天感染只适用于原作集成服务器：`bkz.V()` 返回 false，专服 `is.V()` 返回 true。专服仍保留日常感染和已有病株传播。血月 RNG 的抽取先于专服/遮挡检查，顺序不能误写。

骨粉只治疗活的病株，保留原年龄，不催熟健康作物；死亡作物不能治愈。粪便给耕地施肥，不直接增加作物年龄。

默认骨粉右键入口 `xl.tryFertilize` 仅派发草方块或 `anr`，不能通过点击耕地治疗其上方作物，也不向瓜藤派发。虽然 `aof.fertilize` 的白染料分支和 `aqq.fertilizeStem` 中存在名义上的 2～5 龄催熟代码，正常物品调用链无法传入骨粉；水容器与粪便调用这些入口时又不会进入白染料分支。因此上述方法作为未启用分支记录，默认复刻不能把它改成可达功能。

蓝莓同样需要区分正常成长与不可达的施肥方法。`aqz` 实际注册的 249 号 `BlockBush` 是 `BlockGrowingPlant` 的直接子类，不属于 `anr`。其果实内部年龄为 0～3，正常随机成长路径可达：在森林/森林丘陵的基础温度 0.7、光照 15 时，每随机刻以 `0.1 × 1 × 1 × 0.25 = 0.025` 的概率增长一龄。`BlockBush.fertilize` 虽写有白染料增加 1～2 龄的分支，`xl.tryFertilize` 却既不识别 `BlockBush`，也不调用该方法，耕地分支同样不向它派发；全部归档调用者检索没有发现可达调用。因此默认骨粉右键未熟蓝莓应不催熟、不消耗物品、不表现成功施肥，不能因为方法存在就启用。对应新增规则 `blueberry.registered_growth_baseline` 与 `fertilizer.blueberry_unreachable` 及 `BlockBush` 原始 class、反编译文件、14 个相关方法哈希均单独列入结构化证据。

## 收获与破坏原因

| 状态或原因 | 小麦 | 胡萝卜/洋葱 | 马铃薯 |
|---|---|---|---|
| 健康年龄 0，玩家收获 | 1 种子 | 1 对应蔬菜 | 1 马铃薯 |
| 健康年龄 1～6，玩家收获 | 无 | 无 | 1 毒马铃薯 |
| 健康成熟，玩家收获 | 1 小麦，不额外给种子 | 75% 给 2，25% 给 3 | 75% 给 2，25% 给 3 |
| 活的病株 | 无 | 无 | 1 毒马铃薯，仍受最终破坏原因影响 |
| 死亡作物 | 无 | 无 | 无 |
| 爆炸 | 无 | 无 | 无，包括中期或病株 |

普通作物只接受玩家收获、干旱、降雪、自落四种原因；成熟自落被再次排除。非法支撑、流水冲毁、踩踏等不会给普通成熟产物。毒马铃薯子类会绕过该原因门槛，但仍进入最终掉落函数；其中植物材质遭爆炸的概率被清零，所以不能据子类 override 认定炸病薯可掉物。

降雪路径会在替换雪层前显式传入 `snowfall`：健康年龄 0 返回种植物，成熟返回正常产量，中期普通作物无产物，中期或病害马铃薯给毒薯。踩踏使用 `trampled`，并不等于 `self_dropped`；牛的父类踩踏入口直接抑制掉落调用。

根菜 2/3 产量在旧版用 `Math.random()`，而大多数生命周期概率用世界随机数。现代实现为了服务器可重放测试改用 `RandomSource` 时，应把它记为等分布的随机源适配，不宣称与旧版同种子逐次结果一致。

## 农业附魔

原作丰收 `harvesting`（93）和肥沃 `fertility`（82）均为 Uncommon，权重 25，难度 10，最高 V。有效预算的最小等级成本为 `1 + 10 × (等级 − 1)`。原作候选选择没有现代 JSON 的 `max_cost` 上界，现代成本区间须作为适配记录。二者都接受锄、鹤嘴锄、镰刀，能从正常附魔台及书的候选池选到，并未设宝藏限制；只排除同一附魔重复，不与时运或精准采集互斥。

丰收仅在实际有效的工具上影响作物成熟产物。每个基础产物独立以 `0.5 × 等级/5` 概率再给 1 个；V 为每个基础产物 50% 概率额外一个。原版时运未参与此公式。

肥沃在锄/鹤嘴锄有效收获成熟、未死作物后，以 `等级/5` 概率给土壤补肥；镰刀只对精确 `anr` 类型的小麦执行此钩子，不能扩大到全部根菜。锄及鹤嘴锄耕地成功也按同样肥沃概率使新耕地施肥。旧版这几处使用 `Math.random()`。

## 默认模式与现代适配边界

原作种植物品确实存在 FARMING 职业检查，但前提是启用了技能系统；专服启动甚至在读取 `professions` 后立即强制关闭。不能因为类名或条件存在，就给默认复刻添加等级或职业种植门槛。

现代甜菜不存在于 R196，保留 `AGE_3` 与其物品 ID，再明确套用所选食用作物的气候、疾病、土壤规则，属于现代适配。火把花和第三方 `CropBlock` 不应因继承原版类就被强制改成食用根菜的成长与产量；共享染病状态底座可继续提供兼容。

本次证据以 `anr` 食用作物为中心；瓜藤、甘蔗、仙人掌、可可、菌类的完整生命周期需要各自来源规则，不因继承 `BlockGrowingPlant` 就宣称完全相同。这里对 `aof` 灌溉、施肥、干燥和跳踩的记录用于核对耕地联动，并不替代这些独立子系统的验收。
