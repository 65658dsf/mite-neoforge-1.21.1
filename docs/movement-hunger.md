# 移动食物消耗

开发署名：NingMeng123。来源为 R196 `uf.java:1499–1547`，液体上浮额外费用见 `of.java:1829`；普通跳跃 `uf.java:1465` 没有现代额外跳跃食耗。

| 动作 | R196 食物消耗 |
|---|---|
| 头部浸水 | 三维距离先 `Math.round((float)sqrt(dx²+dy²+dz²)×100F)`，再 `.015F×厘米数×.01F` |
| 仅身体在水中 | 水平距离以相同厘米舍入，系数同上 |
| 攀爬 | 仅上升时 `(float)dy/10F`，不舍入厘米 |
| 地面行走/潜行 | 水平厘米数，`.01F×厘米数×.01F` |
| 地面疾跑 | 水平厘米数，`.05F×厘米数×.01F` |
| 睡眠/空中 | 没有距离费用 |
| 划船 | 每刻 `abs(forwardInput)×.01F`；漂流不收费，倒划照收 |
| 水/熔岩中按住上浮 | 额外每刻 `.01F`，独立于距离费用 |

保留上述分支优先级。水中游泳姿势不会再叠加现代游泳费用；爬梯时不能把横向位移算成行走。原生 `ServerPlayer.checkMovementStatistics` 的行走、疾跑、潜行、游泳、鞘翅等统计完整保留，仅替换其食物消耗调用。现代跳跃运动和统计也保留，去掉来源没有的 `.05/.2` 跳跃附加费用。现代鞘翅、骑马、炽足兽、矿车等新增移动行为沿用其原生运动，不凭空增设 R196 不存在的费用。

食物消耗进入已有的 `causeFoodExhaustion`，不绕过饱和度→营养储备→饱食的既有消费顺序，也不全局套用耐力附魔折扣。

划船使用现代原生输入包传给服务端的 `zza`；服务端每次真实 Boat.tick 只向操作者收一次，不按船移动距离收费，也不向乘客收费。旧版在客户端申报 hunger 数字的路径被现代服务端计算取代。

上浮只有 boolean 意图载荷，不接受客户端指定数量或他人目标。客户端按真实上浮输入、实际液体、非骑乘和生存状态发送变化，按住时每10刻保活。服务端再检查水/岩浆、玩家生存状态、非骑乘，每个实际服务端 tick 最多收一次；40刻没有保活失效。松键、断连、重生、跨维度清理输入。连续发包、松开重按或同刻重复回调不能叠扣。跨维度输入清理保留该刻已计费标记，避免同刻双扣。

自动验证入口为 `MovementHungerRulesTest` 和 `MovementHungerGameTests`。后者直接调用原生统计、跳跃与 Boat.tick，验证无现代重复食耗；液体按键验证真实浸水、无按键不扣、同刻重复消息上限和清理。验收结果以本轮实际构建记录为准。

手动测试时关闭无关饥饿效果，用 AppleSkin 观察行走开始消耗、疾跑比之前慢一半、水中按住上浮比单纯水平漂流额外消耗、静止浮水未按上浮键不增加该项费用。坐船漂流与主动前划/倒划对比；乘客不收费。切维度、重登后不应凭旧按键持续扣食物。基础代谢仍会正常发生，不能把基础代谢当成移动重复计费。
