# 基础挖掘进度与 R196 硬度适配

开发者：NingMeng123。本文依据本地 MITE R196 发布包的原始字节码及运行时注册数据，记录本轮实现选择；实际游戏验收另行记录。[007](testing/007-mining-level.md) 是此前仅叠加等级倍率时的历史结果，其挖掘计时不代表本轮基础公式。

## 原始公式与边界

设 `H` 为挖掘硬度、`S` 为已经过工具、环境及等级修正的强度。R196 在 `uf.java:831–862` 按以下顺序计算；每个中间量和运算均使用 Java `float`：

```text
H == 0               → 进度 1
H < 0 或 S <= 0      → 进度 0
relative = H / S
relative < 0.0029296875f → 进度 1
否则                 → (1.0f / relative) / 512.0f
```

`uf.getRelativeBlockHardness` 字节码偏移 37–45 先处理零硬度，46–70 拒绝负硬度或非正强度，71–98 计算 `H/S` 并作严格小于判断；`getRelativeStrVsBlock` 偏移 31–35 求倒数，`getDamageVsBlock` 偏移 9–13 再除以 512。因此纯公式中 `H=0,S=0` 仍返回 1，不能把判断次序当成可互换。

瞬破阈值本身为 float bits `0x3b400000`。令 `S=1`，硬度为前一相邻 float `0x3b3fffff` 时进度为 1；等于阈值时进度 bits 为 `0x3f2aaaab`，后一相邻值 `0x3b400001` 时为 `0x3f2aaaaa`，后二者都需要两次累加。

不能把原版进度简单乘 `30/512` 当作精确复刻：那会保留现代原始硬度及错误工具分母，还缺少严格瞬破边界。也不能把浮点顺序改写成 `S/H/512`；位级验收向量 `H=0.1f,S=3.0f` 的正确进度为 `0x3d6fffff`，改写后是 `0x3d700000`。

## 0 级开局基准

以下条件为生存、0 级、空手、站在地面、不在水中、无药水效果、食物能量正常，强度 `S=1`。五类原方块均为采集等级 0、材料不要求工具，且没有便携例外。次数通过逐步 float 运算及 float 进度累加取得。

| 方块 | R196 实际硬度 | 每次进度 | 有效累加次数 | 20 TPS 理论基准 |
| --- | --- | --- | --- | --- |
| 泥土 | 0.5 | 0.00390625 | 256 | 12.8 秒 |
| 草方块 | 0.5 | 0.00390625 | 256 | 12.8 秒 |
| 砂 | 0.4 | 0.0048828125 | 205 | 10.25 秒 |
| 砂砾 | 0.6 | 0.0032552082557231188 | 308 | 15.4 秒 |
| 树叶 | 0.2 | 0.009765625 | 103 | 5.15 秒 |

原始注册为 `aqz.java:2262–2263,2272–2273,2278`，与 `reference-data/runtime-registry.json` 中方块 ID 2、3、12、13、18 的 `aqz.cG` 一致。砂砾实际注册使用 `0.6f`（`aqz.<clinit>` 偏移 767–770），没有使用另一个未接入注册的 `BlockHardness.gravel=0.8f` 常量。砂砾第 307 次进度为 `0.9993464946746826`，第 308 次为 `1.0026017427444458`。

旧客户端由 20 tick/s 计时器驱动（`atv.java:76,673–675`），持续挖掘每游戏 tick 累加一次（`bdc.java:190`）。START 本身将进度设为零，正常首次按下可在同 tick 的后续持续输入中累加一次；完成后另有 5 tick 连挖冷却和换目标建立过程。表中是单块有效累加基准，不能不加区分地当作任意输入测试的总 tick 数。

## 现代接入选择

| 项目 | 本轮行为 |
| --- | --- |
| 进度入口 | 替换 `BlockBehaviour` 的通用破坏进度计算，使用上述 R196 运算顺序；方块专用覆写保留，例如竹子的剑破坏行为 |
| 原木资格 | 011 在查询现代强度前检查原木工具资格，不合格进度为 0；服务端最终破坏也检查当前主手。默认范围为明确的 40 种原版原木及变体，见 [原木门槛适配](log-harvest-adaptation.md) |
| 强度输入 | 取得一次现代玩家挖掘速度；工具、环境与 `BreakSpeed` 修正继续生效，其中已包含一次食物能量检查及等级倍率，公式中不重复应用或再次查询速度；空条减速见 [饥饿采集适配](mining-hunger-adaptation.md) |
| 有效硬度 | 既有草、砂、原木、矿石、作物与功能方块适配之后，按 [R196 方块硬度审计](r196-block-hardness-audit.md) 补齐明确旧版对应方块的实际注册硬度及半砖状态；玩家挖掘、工具耐久等共用该有效硬度。没有旧版对应的现代新增方块继续使用原始硬度 |
| 已一致的方块 | 现代泥土 0.5、砂砾 0.6、原版树叶 0.2 无需额外映射；不因它们属于某个广泛标签而改写其他土类或模组方块 |
| 取消与非正速度 | 接入层在调用纯公式之前拒绝已取消或非正速度，即使硬度为零也不破坏；这是保留现代事件取消语义的明确差异 |
| 黑曜石速度（2026-10-28） | 普通黑曜石通过工具资格检查后使用原版 `S / 50 / 30` 进度；铁镐在饱食、0 级、落地、无附魔及药水效果时需 188 tick，20 TPS 下约 9.4 秒。速度保留现有经验、饥饿、附魔和环境倍率及事件取消；耐久独立读取 R196 有效硬度 2.4，每块损耗 240，不能误用计时所需的现代硬度 50。哭泣黑曜石沿用原规则，注册硬度及爆炸抗性保留 |
| 模式 | 创造与旁观保留现代行为 |
| 其他行为 | 保留现代工具效率、环境修正、服务端 STOP 的 0.7 容差和控制器 5 tick 连挖冷却；掉落默认沿用现代规则，010 的砂砾燧石分支例外见 [燧石开局适配](flint-start-adaptation.md) |

红沙不是该 R196 原始砂方块的亚型，将其有效硬度设为 0.4 属于现代适配。旧版树叶只含橡木、云杉、白桦、丛林四类；现代其他树叶使用其自身原始硬度，不据此声称已提取了它们的 R196 规则。

010 的原木硬度来自 R196 `arj.java:11–15`、`BlockHardness.log` 与 `EnumMaterialHardness.wood=1.2f`。现代原木、木块、去皮变体及菌柄统一接入这一阶段属于现代适配，不修改第三方命名空间的原木。0 级、食物正常、燧石短斧强度 2.5 时，每次进度 bits 为 `0x3b855555`，需要 246 次有效累加；详见 [燧石开局适配](flint-start-adaptation.md)。本项不倒改 008 的历史测试数据。

局部有效硬度不修改方块全局硬度、爆炸抗性或地形生成，只改变玩家挖掘计算。硬度和爆炸抗性是不同属性，不能把局部挖掘修正扩展成物理系统调整。

## 未覆盖的规则

基础进度功能恢复通用公式与开局硬度对应关系，继续采用现代强度输入；后续 [009](testing/009-mining-hunger.md) 加入无食物能量时的速度惩罚，[011](testing/011-log-harvest.md) 加入原木工具门槛。2026-10-28 补齐明确旧版对应方块的硬度映射；现代新增方块、其他采集与饥饿行为仍按各自适配范围处理，不能宣称全量采集系统已经还原。保留的现代服务端容差也不等同旧版完整客户端与服务端协议。
