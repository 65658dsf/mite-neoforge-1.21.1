# 029 饱和度与饱食度的消耗顺序

开发者：NingMeng123。用户要求先消耗饱和度，再消耗饱食度。2026-10-14用户已确认本次测试正常并授权提交，以下步骤保留作为复测说明。

## 原因与修复

020的AppleSkin饱和叠层显示既有营养储备N及种子缓冲B。服务端此前虽先消费B，随后仍执行R196原始的饱食S优先规则，导致普通食品补充的饱和层还在、饥饿条本体已经减少。

当前统一顺序为 **种子缓冲B → 营养储备N（饱和层）→ 饱食度S**。每累计4点耗竭，每tick最多扣一项的一单位；最后一点N耗尽的那次不会同时扣S，下次消耗才扣S。不为普通食品再创建一份原版饱和度，食品S/N数值及微量营养摄入保持原值。

原R196 `ux.java:45–58` 并非严格N优先；本次顺序按用户明确要求适配。`ux.java:64–73` 的N清空饥饿条件随之调整为S、N同时清空才积累饥饿伤害，避免有饱食度时提前饿伤。伤害累积速度与难度生命下限保留来源公式。恢复仍需要N并使用原慢恢复公式，N清空但S仍有值时既不饿伤，也不会凭S免费回血。

旧存档版本1、同步协议2不变。原 `mite_nutrition_hunger` 字段继续兼容读写，但不再累计或决定扣哪一储备。保存、重进和换维度使用同一服务端规则；已有饱食、营养和种子缓冲不会因升级重新填满。

## 用户手测

由你保存退出并重新启动更新后的测试客户端，或替换测试实例中的 `build/libs/mite-0.1.0.jar`。本批不自动操作游戏。建议使用可开指令的测试存档。

1. 设置生存状态与两项储备：

   ```mcfunction
   /gamemode survival
   /mite food set reserves @s 6 2
   /mite food set saturation @s 0
   /mite food status @s
   ```

   跑动、跳跃或等待代谢。前两次单位扣减应为 **S6/N2 → S6/N1 → S6/N0**，饱和轮廓先减少，鸡腿本体保持；下一次才变S5/N0。状态命令中的“营养”是N，“种子饱和缓冲”是B。没有AppleSkin时也可用命令验证顺序。

2. 再设置S6/N1/B0，吃一个小麦种子，B应为1。消耗顺序应为 **S6/N1/B1 → S6/N1/B0 → S6/N0/B0 → S5/N0/B0**。吃其他食品不得重复补入第二份饱和储备。
3. 设置S6/N0/B0，保持安全环境约一分钟：仍有饱食度时不应饿伤，受伤后也不会因只有S而自动回血。再将S/N均设0，普通难度逐渐降低到来源生命下限，困难允许致死；这项只在可丢弃的测试存档验证。
4. 设置S6/N2/B1，保存退出再进入，核对状态及扣减顺序。重复吃面包、熟肉、牛奶，确认数值和容器返还正常；蛋白质、脂肪、植物营养依然按原规则代谢。
5. 若需缩短等待，使用 `/tick rate 200`，结束后恢复 `/tick rate 20`。观察操作和实际速度时使用20TPS；湿冷、营养不良和回血会改变耗竭累积速度，但不会改变扣减顺序。
