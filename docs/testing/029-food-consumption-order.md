# 029 饱和度与饱食度的消耗顺序

## 当前规则（2026-11-23）

每累计 4 点耗竭，服务端先看原版饱和度（种子缓冲 B）。B 有剩余时本次只扣最多 1 点 B。B 为零时，饱食值 S 和营养值 N 在同次扣减中各扣 1 点。某项已耗尽时，剩余一项继续扣减。

| 画面与状态字段 | 实际储备 |
| --- | --- |
| AppleSkin金色饱食叠层 | 营养N与种子缓冲B，显示为按容量限制的N＋B |
| 鸡腿饥饿条 | 饱食值S，对应原生 `foodLevel` 和状态命令的“饱食” |
| 状态命令的“营养” | 独立营养N |
| 状态命令的“种子饱和缓冲” | 原生饱和度B |

S 或 N 有剩余时可自然回血。B 耗尽当刻起，自然回血进度乘 `0.5`，清醒和卧床均适用。按相同的 N＋B 和其他加成比较，若有 B 时的清醒速率为 1，B 为零时清醒为 0.5，有 B 时卧床为 8，B 为零时卧床为 4。S、N 均为零时开始积累饥饿伤害。

保存字段 `mite_nutrition_hunger` 作为旧档兼容数据保留，耗竭计时统一使用 H。回归入口为 `FoodConsumptionOrderGameTests`、`NutritionGameTests`、`RestLifecycleGameTests` 和 `NutritionRulesTest`。

### 当前复测

1. 执行 `/mite food set reserves @s 2 3` 和 `/mite food set saturation @s 1`。用 `/mite food status @s` 核对每次单位消耗为 **S2/N3/B1 → S2/N3/B0 → S1/N2/B0 → S0/N1/B0 → S0/N0/B0**。
2. 从 S3/N2/B0 重测。前两次扣减应同时减少 S 和 N，第三次只扣最后一点 S。用 B0.5 重测时，第一次扣减清空 B，第二次才扣 S 和 N。
3. 启用自然回血并在有遮蔽的床上休息。对照缓冲耗尽前后，验证睡眠快进也使用每刻扣减后的 B。比较时考虑 B 本身提供的营养加成。
4. 分别设置 S6/N0/B0 和 S0/N6/B0，观察只有一项储备时仍可回血。将 S 和 N 均设零后，核对自然回血停止且开始积累饥饿伤害。保存、重进或切换维度后可继续核对扣减顺序。

测试实例使用当前配套构建文件，版本以工程配置为准。

#### 原因与修复

020的AppleSkin饱和叠层显示既有营养储备N及种子缓冲B。服务端此前虽先消费B，随后仍执行R196原始的饱食S优先规则，导致普通食品补充的饱和层还在、饥饿条本体已经减少。

当时的顺序为 **种子缓冲B → 营养储备N（饱和层）→ 饱食度S**。每累计4点耗竭，每tick最多扣一项的一单位；最后一点N耗尽的那次不会同时扣S，下次消耗才扣S。不为普通食品再创建一份原版饱和度，食品S/N数值及微量营养摄入保持原值。

原R196 `ux.java:45–58` 并非严格N优先；本次顺序按用户明确要求适配。`ux.java:64–73` 的N清空饥饿条件随之调整为S、N同时清空才积累饥饿伤害，避免有饱食度时提前饿伤。伤害累积速度与难度生命下限保留来源公式。恢复仍需要N并使用原慢恢复公式，N清空但S仍有值时既不饿伤，也不会凭S免费回血。

旧存档版本1、同步协议2不变。原 `mite_nutrition_hunger` 字段继续兼容读写，但不再累计或决定扣哪一储备。保存、重进和换维度使用同一服务端规则；已有饱食、营养和种子缓冲不会因升级重新填满。

#### 用户手测

由你保存退出并重新启动更新后的测试客户端，或替换测试实例中的 `build/libs/mite-0.1.0.jar`。本批不自动操作游戏。建议使用可开指令的测试存档。

1. 设置生存状态与两项储备：

   ```mcfunction
   /gamemode survival
   /mite food set reserves @s 6 2
   /mite food set saturation @s 0
   /mite food status @s
   ```

   跑动、跳跃或等待代谢。前两次单位扣减应为 **S6/N2 → S6/N1 → S6/N0**，饱和轮廓先减少，鸡腿本体保持；下一次才变S5/N0。状态命令中的“营养”是N，“种子饱和缓冲”是B。没有AppleSkin时也可用命令验证顺序。

2. 再设置S6/N1/B0，吃一个小麦种子，B应为1。消耗顺序应为 **S6/N1/B1 → S6/N1/B0 → S6/N0/B0 → S5/N0/B0**。吃其他食品不得重复补入第二份饱和储备。
3. 设置S6/N0/B0，保持安全环境约一分钟：仍有饱食度时不应饿伤，受伤后也不会因只有S而自动回血。再将S/N均设0，普通难度逐渐降低到来源生命下限，困难允许致死；这项只在可丢弃的测试存档验证。
4. 设置S6/N2/B1，保存退出再进入，核对状态及扣减顺序。重复吃面包、熟肉、牛奶，确认数值和容器返还正常；蛋白质、脂肪、植物营养依然按原规则代谢。
5. 若需缩短等待，使用 `/tick rate 200`，结束后恢复 `/tick rate 20`。观察操作和实际速度时使用20TPS；湿冷、营养不良和回血会改变耗竭累积速度，但不会改变扣减顺序。
