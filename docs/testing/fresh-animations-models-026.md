# 0.2.6 模型动画与女巫贴图回归

开发与验证：NingMeng123，2026-10-20。

## 修复范围

- 普通骷髅、远古骷髅、远古骷髅守卫、骷髅领主、远古骷髅领主采用标准骨架模型入口，补上原先缺失的 Fresh Animations 待机与走路。
- 极难版骷髅僵尸保留原 64×64 皮肤和粗四肢，只从隐藏的标准骷髅采样骨骼姿态。
- 女巫领主、流浪女巫保留原生 64×128 几何、UV、红眼与连通帽子，单独映射 FA 头部和帽子运动。
- 四种方块生物主体采用与原网格相同的标准史莱姆入口；相位苦力怕改用独立的紫眼遮罩，避免 FA 改写末影人眼睛布局后让其眼睛消失。

完整 29 种主模组与 45 种扩展生物的静态模型覆盖表见 [模型覆盖审计](../fresh-animations-model-coverage.md)。没有资源包对应模型或几何不兼容的特殊生物仍保留原生动作；本轮没有宣称其全部接入 FA。

## 构建隔离

本轮工作区存在其它并行开发的未提交改动。交付构建使用 `build/verification/fa-followup-main` 和 `fa-followup-extension` 中的 Git HEAD 快照，仅覆盖本轮模型、审核及版本文件，未把其它未提交功能打入本轮包。可选 EMF、ETF、Better Combat 和 Player Animator 由独立测试实例提供，不随交付打包。

## 客户端验证

主模组的 `FreshAnimationsCombatClientAudit` 从四列扩展为待机、走路、前摇、命中、恢复五列，六类报告异常的骷髅全部要求实际执行 EMF 动画，且真实走路渲染必须不同于待机。骷髅僵尸另将隐藏动画模型识别为姿态来源；可见几何和皮肤不从驱动模型复制。护甲、衣物、共享模型隔离、攻击结束恢复和玩家取消淡出继续验证。

扩展 `MobRenderRegressionAudit` 调用新的 `WitchFreshAnimationsAudit`，比较全部 15 个原生女巫方块的坐标与 UV，验证真实 FA 头部映射、帽子原始支点不漂移、步行姿态变化和暗光头像中的红眼像素。完整审核还检查相位苦力怕眼部发光与其它特殊外形。

本轮运行输出位于 `build/verification/fa-followup-*`，不将历史失败 JSON 或 Gradle 正常退出计为模型审核通过；实际结论以对应 JSON 的状态和失败列表为准。

主客户端本轮 50 行实体、250 个样本通过；包含 6 类报告异常的骨架与 4 种方块，保留玩家和其它极难版人形怪的战斗兼容回归。扩展在有 FA、无 EMF 两个独立实例中，分别通过 45 个纹理读取及 15 个重点 GPU 绘制；两女巫原生方块/UV、真实 FA 头部、帽子连接与红眼检查通过，相位苦力怕的发光差异恢复可见。

新增 `SkeletonZombieModelAudit` 检查骷髅僵尸 7 个原生方块的坐标与 UV 严格等于 Humanoid 64×64，以窄四肢 Skeleton 64×32 作为负控；有 FA 时要求真实采样生效。同时对照旧 SkeletonModel，验证无动画分支中 `swimAmount=0.5`、头部初始角 0.7 的连续两帧，全部 7×9 个骨骼变换严格一致，避免清空姿态破坏原生插值。

主模组 1666 项 JUnit、扩展 30 项 JUnit 及两边 `build compileGametestJava` 通过。本轮没有进行多人实玩；保留原生动作的特殊物种详见覆盖审计表。

最终通过报告分别保存为 `fa-followup-combat.json`、`fa-followup-witch-fa.json` 和 `fa-followup-native.json`。发布 JAR 已核对版本、署名、主模组依赖范围及新增模型/紫眼资源，不含审核器或第三方动画库。
