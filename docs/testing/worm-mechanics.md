# R196 蚯蚓与箱内堆肥

作者：NingMeng123

依据本地 R196 发布包的 1185 个反编译 Java 文件核对，蚯蚓是物品，不是可放出的生物。`wormRaw` 就是箱子代码所称的活蚯蚓；原作没有蚯蚓实体、寿命倒计时、饥饿死亡或繁殖规则。箱内工作不会消耗活蚯蚓，也不会把它们转成肥料或熟蚯蚓。不新增独立堆肥桶。

## 箱内处理流程

箱子收到一次真实方块随机刻后，先数本箱中的生蚯蚓。没有活蚯蚓则不处理，已有浮点堆肥值也保留。若开头已有至少 1 的待转换堆肥值，只尝试转换为粪肥后结束本次检查。

其余情况下，每只活蚯蚓尝试一次。每次重新扫描当前可用饲料槽位，等概率抽一个槽位；该饲料价值为 `v` 时，成功概率为 `1 / int(100 × v)`。成功才消耗一份饲料并加 `v`；蚯蚓数量保持不变。例如小麦每次成功贡献 0.5，单次尝试成功率为 1/50；纸每次贡献 0.1，成功率为 1/10；干草块每次贡献 4.5，成功率为 1/450。饲料为空则结束剩余尝试。

消耗前同时检查粪肥、所有返还物及其堆叠上限。即使本次只增加不足 1 的浮点进度，也要求有位置容纳一份粪肥。最后一份饲料消耗后空出的槽位可以使用；空间仍不足则保持整箱库存与堆肥值不变。瓜种子、南瓜灯的种子和火把、汤的碗等一起按原子操作提交，避免满箱丢容器或只生成部分返还物。

每次成功进食后，按已有空间尽可能把每个完整堆肥单位转为一份粪肥，小数部分留下。本实现沿用方块实体持久化数据中的 `mite_worm_compost` 浮点键，保存、退出和重新加载后继续，不因打开箱子、搬运物品或每次检查而清零。

普通箱子、陷阱箱和已有金属箱子使用同一处理。双箱的两半分别统计自己的库存与堆肥值：左半的蚯蚓不会吃右半的饲料，也不会借用另一半空间。打开箱盖不暂停堆肥；无需添加漏斗循环或新机器。

## 本轮接入与现代边界

本轮补齐原作植物方块、纸、容器和瓜类返还，纠正鸡蛋、奶和种子等禁止项，并一次性验证全部产物的库存空间。箱子改接原生方块随机刻，删除方块实体每 tick 按 `1/4096` 模拟抽样的路径，避免两个入口重复消耗。

随机刻由真实区块引擎调度，受 `randomTickSpeed` 和原生区块随机刻范围约束；`randomTickSpeed=0` 时不会进食，不为离线或未获得随机刻的箱子补算时间。未打开的现代战利品箱跳过处理，保留首次玩家开箱的战利品上下文。蚯蚓多会增加同次检查的尝试次数，不会把箱子改成每 tick 必定进食。

草块沿用玩家收获入口：令 `f = min(14, min(3, Fortune) + 雨中时的12)`，以 `1/(16-f)` 概率将原有泥土替换为一只生蚯蚓。晴天无时运为 1/16，雨中无时运为 1/4，最终上限为 1/2。冻结判断采用现代生物群系在当前位置的 `coldEnoughToSnow`，包括高度温度；精准采集保留原生草块掉落，不额外赠送蚯蚓。

钓鱼继续使用已接入的原作逐刻咬钩概率、水体几何检查、晨昏与蓝月修正。生蚯蚓只在快捷栏 0–8 生效，放更多只提供后续次数，不重复叠加倍率；成功捕获时消耗首个快捷栏蚯蚓堆中的一只。等待、未咬钩、挂住实体或被现代钓鱼事件取消均不扣饵。已有生、熟蚯蚓食物数值、16 堆叠、32 tick 食用和火烹饪入口保持不变。
