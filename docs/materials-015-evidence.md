## 金属与碎片配方

`aae.java:5–8,46–49` 注册七种金属、五种碎片的双向换算：

- 铜、银、金、铁、远古金属、秘银、艾德曼：九粒填满 3×3 得一锭；一锭无序拆成九粒。原版铜、铁、金块拆九锭继续保留，现代涂蜡铜块同样保留。
- 九枚绿宝石、钻石、石英、黑曜石碎片填满 3×3，分别得到一个对应整宝石或黑曜石块；对应完整物品可无序拆成九碎片。
- 九枚玻璃碎片得到的是 **一块玻璃板**，玻璃板拆九碎片；不是完整玻璃方块。`aae` 引用 `aqz.bv`，其注册在 `aqz.java:2361`，旧 ID 102。
- 已有燧石四碎片与整燧石互换保持不变；不能套用九换一。

`RecipeHelper.java:59–63` 对 `ItemIngot`（包含 `ItemNugget` 子类）提前返回，故七种金属换算没有金属等级工作台门槛；九格形状本身仍需要 3×3。配方所存 `BLACKSMITHING` 位不等于默认职业封锁：发布包运行时 `professions_suppressed=true`，实际检查受 `wd.java:152` 的技能开关控制。

锭上限 8 与一次拆块产出 9 有实际冲突：现代原版严格配方编解码器不接受这种结果。本批使用限定材料的 `mite:bulk_material` 配方保存九锭产量；结果/光标允许暂存一批 9，存储槽分为最多 8。背包/工作台转移与自动合成器需要专项验收，不能把注册成功当作无损转移证明。

制作耗时尚未复刻。`bex.java:450–457,497–503` 的难度压缩、最小周期、等级和工作台修正仍是独立待实现系统。`ItemIngot` 的 `material.durability * 100F` 及粒的 `/9F` 是组件制造难度；物品 `xp_reward` 是熔炉输出经验元数据，二者都不能写成换算配方会奖励经验。当前这些配方使用现代即时合成。

## 完整玩家筛取概率树

原始入口为 `aoo.dropBlockAsEntityItem`，源码 `aoo.java:16–57`。字节码关键位置：初筛 `nextInt` 在偏移 61，燧石/矿物分流在 79，整燧石的 16 分支在 88；矿物树自 147 开始，下界转换自 319 开始。概率来自实际分支，未通过抽样估计。

旧 metadata 1 为村庄道路，直接走普通掉落；爆炸或非玩家采集同样直接返回。玩家资格来自 `BlockBreakInfo.java:205` 的破坏原因与 `uf` 实体检查，时运取自 `BlockBreakInfo.java:273`。精准采集在上游 `jw.java:146–149` 走方块自身掉落，不进入筛取。没有从本方法找到额外的高度、生物群系、职业或铲子条件。

令 `F` 为时运，`D = 12 − 2F`。旧版只限制 `F ≤ 3`；本批对异常负附魔额外夹到 0，安全范围为 0–3，对应 D 为 12、10、8、6。

1. 初次 `nextInt(D) > 2` 返回砂砾。
2. 否则 `nextInt(3) > 0` 进入燧石分支，再以 `nextInt(16) == 0` 出整燧石，其余出碎片。
3. 余下矿物分支依次检查七个 `nextInt(3) > 0`：铜、银、金、黑曜石、绿宝石、钻石、秘银；七次均为 0 才出艾德曼粒。每个叶结点产一个对应物品，随机调用长度随分支变化。

| 普通砂砾结果 | 无条件概率 |
| --- | ---: |
| 砂砾 | `1 − 3/D` |
| 燧石碎片 | `15/(8D)` |
| 整燧石 | `1/(8D)` |
| 铜粒 | `2/(3D)` |
| 银粒 | `2/(9D)` |
| 金粒 | `2/(27D)` |
| 黑曜石碎片 | `2/(81D)` |
| 绿宝石碎片 | `2/(243D)` |
| 钻石碎片 | `2/(729D)` |
| 秘银粒 | `2/(2187D)` |
| 艾德曼粒 | `1/(2187D)` |

F0 的固定例为砂砾 `3/4`、燧石碎片 `5/32`、整燧石 `1/96`、铜粒 `1/18`、艾德曼粒 `1/26244`。全部概率相加为 1。原矿物树没有铁粒、远古金属粒或玻璃碎片；注册这些材料不表示砂砾可以产出。

下界砂砾保留同一棵随机树，随后将铜、银、秘银、艾德曼粒转换为金粒，将黑曜石、绿宝石、钻石碎片转换为石英碎片。金粒总概率为 `703/(729D)`，石英碎片为 `26/(729D)`；砂砾、燧石和燧石碎片概率不变。转换不增加随机调用。源码内部出现的爆炸特殊表达式已被入口的爆炸提前返回挡住，不能据此宣传“炸砂砾筛矿”。

本批普通与下界砂砾分别用持久方块 ID 表达。下界生成替换现代 `minecraft:ore_gravel_nether` 的目标方块，保留现代大小、分布与世界生成器；普通砂砾搬到下界不会自动变为下界砂砾。旧村庄道路 metadata、旧下落算法和完整 R196 世界生成不属于本批。现代掉落事件还尊重取消、创造/旁观、`doTileDrops` 和精准采集；保留其他模组的额外掉落，数据包已取消普通掉落时不强制补发。

`MineralGravelRulesTest` 按运行时提出的 RNG bound 展开每个真实分支，以 `BigInteger` 约分分数累加，不给短分支补假随机数，不用 Monte Carlo 或浮点容差。独立期望表覆盖 F0–3 普通/下界全部枚举、上下越界时运、旧 API 等价；原 `FlintGravelRulesTest` 继续单独验证燧石分支和时运边界。数学测试证明概率树，不替代玩家实际采集、掉落实体、联机或存档测试。

## 宝石献祭

`ItemRock.java:19–44` 按完整物品身份取值：旧染料 metadata 4（青金石）25、石英 50、绿宝石 250、钻石 500，其余 0。`getExperienceValueWhenSacrificed` 字节码偏移 20、30、42、55 分别直接载入这四个常量。碎片虽然继承 `ItemRock`，其身份不在四项内，献祭经验为 0。

右击函数在服务端消耗手持数量 1，然后调用 `uf.s` 加经验；字节码偏移 36–44 确认顺序，没有创造模式免消耗分支。`uf.java:1622–1633` 转入加经验方法并强制禁止该途径治疗；献祭不是经验球，不触发经验球拾取。青金石的实际入口是 `xl.java:72–80`，旧版仅在没有选中方块时委托给 `ItemRock`。

现代使用原版四个独立物品 ID，在物品右击事件中服务端消耗并计入统一总经验，支持现代双手事件、排除旁观、保留已取消交互，提示每个物品的经验值；声音与表现使用现代资源。该事件适配不表示逐项复刻旧染料的方块交互优先级。不会把蓝色染料、碎片或合成过程视为献祭来源。
