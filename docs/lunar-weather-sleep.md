# 月相、天气与睡眠

开发者：NingMeng123。以下来源均为本地R196发布包的实际反编译文件，日历统一调用 `LunarCalendar`，不额外维护客户端月相计数器。

当前版本按用户追加要求启用[血月白昼降雨、夜间干雷与血红天空](lunar-weather-adaptation.md)。下方 13000 刻的描述保留作为 R196 来源证据，运行时血月全天保留雷暴，夜间停雨且仍有真实闪电，不受关闭天气循环影响。

## 实际来源与边界

- `js.java:180–195`：`isBloodMoon(false)`时全天不开始入睡、不推进睡眠时间；并非仅在月亮升起后禁止。原版R196有“躺在床上、保持清醒”的独立状态，现代版没有这一独立状态，本次保留原生设置出生点后拒绝入睡，并在血月到来时停止已有睡眠；不复刻旧版清醒卧床界面。蓝月、丰收月和幻月不增加此限制，原版距离、遮挡、怪物、维度等检查继续有效。
- `abw.java:4258–4275`：天气日为 `(time+6000)/24000+1`，日界在未调整时刻18000；`isBloodMoon`等月相判断则是 `time/24000+1`。不能用天气日替代月相日。
- `abw.java:5314–5336`：天气日小于2不生成事件。每个天气日先消费一个随机整数，随后最多尝试3次；每次只有 `nextInt(4)==0`继续，第一次失败直接结束循环。雨开始于天气日首刻加 `nextInt(24000)`，持续 `6000+nextInt(12000)`刻。
- 普通雨事件的开始或结束位于血月/蓝月全天时剔除；开始、结束、开始+6000、结束−6000落在丰收月夜间时同样剔除。夜间沿用日历的13000至23000，包含两个端点。保留来源逐个端点判断，不替换成另一个推测的整区间判断。
- 血月天气日额外安排从月相日时刻0开始、持续13000刻的强制雨/雷暴。**强制暴风雨在白天至13000之前，不是整段血月夜晚**。例如第32天从744000开始，757000结束；事件区间为左闭右开。
- `abw.java:5346–5376`：前一天及当天的事件按来源嵌套顺序合并，相距不超过6000刻也会合并；保留第一个已有雷暴段，之后按开始时刻排序。
- `WeatherEvent.java`：普通合并事件的风型先按开始刻重新播种选择0至2；同一开始刻重新播种后1/4概率追加雷暴，持续 `min(2000+nextInt(4000),事件时长)`。1/4概率贴靠开始或结束，其余情况在雨区间内随机放置；有雷暴时风型为3。当前使用这些雷暴时段；旧版独立风场的视觉/物理不由此天气模块虚构实现。
- `abw.java:2864–2885`：雨、雷强度每tick向目标值改变0.01，过渡最多约100刻。因此13000之后可短暂残留衰退中的雨声/雨幕；不在边界瞬间清零。
- `js.java:782–805`：每个活动区块的原生闪电候选概率，血月全天为1/20000，其他时段为1/100000；来源实现仍须实际降雨、雷强度及目标合法。原版血月夜没有强制雷暴不等于一定打雷；现代夜间干雷扩展见下方。
- `acq.java:187–189`、`abw.java:4354–4392`：血月允许沙漠等无普通降水地区受雨及成为雷击目标；冰冻区域保持雪，不把雪误作雨。遮天及地表高度检查仍有效。

## 现代适配

原排程随机种子使用世界创建时间。1.21.1没有同语义的稳定世界创建时间字段，本移植使用已持久化的主世界种子替代，保留 `java.util.Random(seed+天气日)`的其余调用顺序、概率、时长及合并逻辑。相同现代种子的逐日事件可复算，保存重启后无需新增随机状态或保存格式；不宣称与1.6.4相同种子的具体雨日一致。每个主世界仅缓存最近查询天气日的少量事件及当前事件。按 `abw.updateWeatherFlags`保留尚未结束的跨日雨段，当前段失效后才重新查询当天事件；重进游戏时也按来源算法重新查询。

非血月的 `doWeatherCycle=true` 时由来源事件驱动主世界雨/雷目标，并复用现代原版每tick插值及维度定向同步包；关闭天气循环则保留手动命令。血月全天保留雷暴，白昼降雨、夜间停雨；昼夜严格共用 `LunarCalendar.State.night`，13000～23000（包含端点）为夜间，23001 起黎明恢复降雨。退出后恢复来源排程或血月前冻结的天气，覆盖状态会保存。其他维度的原天气实现保持原有行为。

血月沙漠降水共用 `LunarWeather.precipitation`，服务端 `Level.isRainingAt`、`ServerLevel.tickPrecipitation`及客户端雨幕/雨声调用同一判定。它不改写生物群系定义，不令主世界以外的干燥群系下雨。白昼真实降雨可进入现代炼药锅和方块受雨流程；夜间雨量逐渐退至零，不再有雨幕、雨声、降雪或炼药锅接雨，但保留雷声、真实闪电、现代避雷针和合法落点检查。旧版所有天气相关农业/世界机制由对应系统另行移植。

睡眠限制通过NeoForge开始/继续睡眠事件接入，并在原生服务器“足够深睡眠”分支前额外检查血月，防止修改睡眠人数比例或直接令玩家卧床后跳过血月，同时避免原生跳夜后的清雨分支误触发。

## 自动验证范围

`LunarWeatherRulesTest`包含5个纯规则测试：天气日6000偏移、由独立Java随机序列提取的三组字面雨/雷暴时段、13000边界与第128天蓝月排除、来源端点晴窗、重复构建和结束区间。

`LunarWeatherSleepGameTests`覆盖原生天气tick及0.01衰退、蓝/丰收窗口、沙漠天窗/遮挡及真实炼药锅受雨、真实服务器床交互和出生点、继续睡眠事件及非主世界隔离，另有血月昼夜边界、冻结天气保存／前后跳时及稳定天气无重复广播。夜间干雷修正需验证停雨后真实雷声、闪电和保存恢复。测试在 `finally`恢复世界时间、天气、覆盖状态、游戏规则、临时方块及生物群系，避免多刻血月影响其他测试。最终执行结果由本批总验收记录补充，新增测试存在不代表已经运行通过。

当前手测：第32天 `/time set 750000`观察白昼雷暴和血红天空；设762000后等待约100刻，检查夜间停雨且雷声、闪电仍有效；设767001检查黎明恢复降雨；设768000退出血月后观察天气恢复，并尝试血月睡床；第128天 `/time set 3066000`观察不触发血月覆盖且可正常睡眠。测试期间跳时会改变天气，不应用于已有生产存档的长期进度验收。持久存档、多人睡眠人数和客户端雨声/雨幕仍需要用户实机检查。
