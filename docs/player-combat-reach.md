# 玩家近战、触及与空手反伤

开发署名：NingMeng123。来源基准为本地 R196，本文只记录这三项已选实现；旧工具格挡不在本次范围内。

## 等级近战

`uf.java:558–563` 的近战等级修正为：正等级 `0.005 × 等级`，零及负等级 `0.02 × 等级`。原公式没有独立裁剪，但 `uf.java:520–538` 的自然等级最高为 200，因此原作近战等级倍率最高为 2。2026-10-18 按用户补充要求，现代实际等级继续增长，近战收益最多按 200 级计算；保留负等级修正。

`uf.java:1041–1072` 的实际顺序是：正的攻击属性 → 暴击 1.5 倍 → 等级倍率 → 银制打亡灵 1.25 倍 → 木棒/短木棒/战锤打骷髅 2 倍 → 加附魔伤害 → 悬浮在液体中且伤害大于 1 时压缩为 `1 + (伤害−1)/2`。技能默认关闭；未把默认关闭的格斗技能当成必需条件。`nn.java:2294–2345` 中 `getBlockRestingOn` 实际忽略参数并转到 `getBlockRestingOn3`，后者在不着地时直接返回空，因此悬浮判定实际等价于未骑乘、未着地且处于水/熔岩。

保留新版攻击冷却与 NeoForge 暴击事件。`SourceEnchantmentPlayerMeleeMixin` 读取已冷却/暴击的基础伤害与独立附魔项，把 R196 材料修正延后到等级之后，按上述顺序计算。附魔增伤不会再被等级、暴击或材料乘一次。新版横扫保留，使用同一个最终主攻击基数，每个副目标仍须满足本次近战触及。

## 触及

来源：`uf.java:1971–2039`、`yc.java:937–958`、`Raycast.java:461–484`。

| 操作 | 生存基础值 | 判定点及加成 |
|---|---:|---|
| 方块采集/使用 | 2.75 | 方块中心到眼睛下方 0.625 或 0.25 两点之一；仅对当前方块有效且满足采集等级的工具加触及 |
| 近战 | 1.5 | 眼睛到实体碰撞点；加主手触及及双方脚下高度差修正 |
| 实体交互 | 2.5 | 眼睛到实体碰撞点；加高度差，不加工具触及 |

高度差在 `[-0.5,0.5]` 内为零；超出部分每格增加/减少 0.5，修正限制在 `[-1,1]`。`sq.java:433–435` 使船的交互距离固定 2.5；`uj.java:289–291` 使火球近战触及另加 2。创造模式三种操作固定 5，覆盖高度及这些特殊目标修正。

工具触及沿用 `MiteTools.Definition`。木棍、骨头近战加 0.5，但并非有效挖掘工具。现代石、钻石、下界合金工具按对应 R196 工具类别取同一触及值。现代三叉戟和重锤明确按近战武器保护主手，近战触及加 0.75；不会因此在石头等错误方块上获得工具触及。有效性同时核对 `SourceMiningRequirements` 的真实材质门槛，现代通用 Tool 组件声称“能挖”不能绕过高阶金属块要求。新版副手使用方块时检查副手工具，挖掘和普通近战只看主手；Better Combat 双持攻击使用当前实际挥击的手。副手没有实体交互触及加成。

客户端保留新版碰撞/遮挡射线，按 R196 的 16 格选择射线先选最近碰撞，再用共用规则过滤。可交互但不可近战的实体仍能被选中，实际点击会按操作再次判断。服务端包分开验证攻击、普通交互和具体交互坐标；具体坐标必须有限且处于目标碰撞箱。服务端没有可信客户端射线时，普通交互/近战使用目标可选碰撞箱的最近点作为现代延迟容差，不添加原版额外一格距离。方块开始挖掘、完成采集、右键使用均重新验证当前手持物，防止中途换工具或移远后完成。远距离伪造方块坐标在读取区块前拒绝。

外部模组主动修改的原版范围属性以相对 1.21.1 默认值的增量保留；旧存档中可能显式保存的 `mite:tool_reach` 属性会扣除，避免与新目标规则叠加。R196 工具默认不再持有无条件的两种范围属性。

### Better Combat 玩家距离

安装 Better Combat 2.4.0 后，玩家攻击仍遵守 MITE 原有的 `1.5 + 工具触及 + 高差/特殊目标/外部属性` 上限。默认同高普通剑在安装和未安装 Better Combat 时均为 2.25 格，匕首为 2 格，镰刀为 2.5 格。Better Combat 自身的武器范围、当前招式 `rangeMultiplier` 和体型范围也必须满足；短招式不会借用较长的 MITE 上限。两套距离在生存模式都先应用倍率、再扣固定值，不相加、不重复乘算；创造模式的 MITE 上限仍为 5 格，同时保留 Better Combat 本身更短的范围限制。

客户端在 Better Combat 的扩展范围计算后应用设置，同时扩大候选实体查询及选择射线，最终候选再按 MITE 上限过滤。服务端在真实 Better Combat 请求内保存交换主副手前选定的武器和招式，同时验证眼睛到目标可选碰撞箱的 MITE 距离、肩部射线起点到目标碰撞箱的 Better Combat 距离；双持和连击不会借用另一只手或另一招的范围。普通原版攻击包和直接调用 `Player.attack` 不会借用已完成请求的范围。未安装 Better Combat、空手或没有武器攻击配置时继续使用原规则。持械怪物仍沿用其既有 R196 距离上限。

同时修正 Better Combat 2.4.0 的碰撞箱分离轴零值判断：平行轴的叉积可能为 `(0.0, -0.0, 0.0)`，其 `Vec3.equals(Vec3.ZERO)` 为假，原算法随后把两个零长度投影错误判断为分离，造成已经重叠的挥砍箱漏选目标。兼容 mixin 仅按 `lengthSqr() == 0` 跳过零轴，保留原有非零轴、角度、射线遮挡和实际距离限制。真实客户端回归覆盖四个正方向及两个斜向的范围内、范围外目标。

伐木附魔的额外垂直原木属于服务端已经验证的内部采集。主原木仍须正常触及；每个附加位置只在原事务成功、原木类型、附魔次数、手持物及世界权限通过后取得精确位置的单次许可。许可在进入真实破坏事件前消耗，并在返回/取消/异常时清空；网络开始/停止包、普通手动破坏及事件重入均不能复用。附加采集继续经过原版破坏事务、保护事件、掉落和独立工具磨损。

## 弱击和手部损伤

`yc.java:1527–1529`、`of.java:2234–2236`：工具基类 `xj`、木棍和骨头保护主手。拿着普通物品、弓或方块不等于保护。现代工具通过既有耐久工具注册适配；副手木棍和盾不保护挥击的主手。

`uf.java:2540–2542`：没有保护主手，且生命严格小于 2、食物能量耗尽、或攻击属性严格小于 1 时只能弱击。食物能量沿用既有 R196 饱食/营养资源，不把原版饱和度误当能量。`of.java:607–616`：弱击保留普通击退的 0.6 倍，NPC 再取原版 R196 0.8 倍、土元素再取 0.4 倍；不进入生命损失、吸收、护甲磨损或受伤免疫事务。现代击退事件及抗性保留。允许攻击尝试的耐力消耗继续由既有 `EnduranceMeleeMixin` 负责。

`og.java:1502–1520`（已核对字节码）的目标回调发生在主伤害返回后、附魔触发前，即使目标免疫或仅被弱击仍执行。无保护主手时：普通生物仅在以攻击者为目标且攻击者非弱击时有 12.5% 手伤；史莱姆/岩浆怪/胶质怪先取 100%；随后若正以攻击者为目标且攻击者非弱击，概率又被独立的 `else if` 覆盖为 12.5%。烈焰人与火元素始终为 100%。手伤为 1，岩浆怪为 2，胶质怪按种类为 2/3/3/4；与体型无关。即使概率为零也消耗一次目标随机数。

`nb.java:179–183` 将手伤标为不可格挡、绕过普通护甲，保留防护附魔/药水；`mite:hand_damage` 使用同一正常伤害管线，护甲不因手伤磨损。`EntityGelatinousCube.java:377–381` 还在手伤之后腐蚀主手物品，该回调已从旧的“hurt 成功才腐蚀”位置移到实际主近战回调，覆盖免疫目标及弱击；普通史莱姆沿用胃液、四类胶质怪沿用各自化学类型。

弱击沿用原生击退事件、抗性及玩家友伤规则；只有实际改变了速度时才标记原生 `hurtMarked`，由 `ServerEntity.broadcastAndSend` 将速度同步到受击玩家自己的连接。不会为同步而扣生命或添加受伤免疫帧；取消及完全抗性不产生错误速度包。

## 验证

`SourcePlayerCombatRulesTest` 与 `SourcePlayerCombatGameTests` 覆盖独立算术/阈值与实路径用例，包括正负等级、199→200 的最后一次收益增长、201/312/403 及极大等级的伤害封顶、暴击/银/钝器顺序、弱击不伤生命护甲、营养能量、主副手保护、烈焰与免疫布丁回调、有效工具与金属材质门槛、现代三叉戟/重锤保护与错误方块不加触及、高差/船/火球、真实交互包校验、开始/完成挖掘重验、真实玩家连接的弱击速度同步与取消/抗性边界。既有伐木实路径用例另验证超手动触及的附加采集、保护事件取消及单次许可无法泄漏。

原始 R196 实现阶段未操作用户客户端。2026-10-19 的 Better Combat 修复使用独立实例进行自动客户端审核，没有打开用户现有存档。

Better Combat 玩家距离修复由 `BetterCombatPlayerReachGameTests`（`mite_bettercombat` 命名空间）验证真实攻击请求、原版攻击包分派、实际伤害、主副手条件、物品距离属性、招式倍率、体型、配置及请求上下文清理。`-PmiteBetterCombatPlayerReachAudit=true` 可在独立 `-PmiteClientDirectory` 下运行真实客户端候选选取审核；该审核只创建新的临时平坦世界，记录 `TargetFinder` 与 MITE 校验结果后自动退出。

2026-10-19 验证：构建与 1641 项 JUnit 通过；安装 Better Combat 2.4.0、Simply Swords 1.70.2 的 34 项专项服务端测试通过，未安装扩展的 1966 项服务端回归通过。真实客户端有扩展 38 项、无扩展 3 项审核均通过并正常退出，包括普通剑 2.1 格命中、2.4 格拒绝和双持范围属性不可跨手借用。审核等待临时世界就绪后再执行，避免过早退出时的区块卸载竞态。日志与 JSON 位于 `build/verification/bettercombat-player-*`，包括修正分离轴之前的真实漏选记录。交付包为 `build/releases/mite-0.2.0-bettercombat-reach-fix.jar`。
