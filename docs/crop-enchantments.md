# 作物农业附魔实现

开发署名：NingMeng123。原始规则及哈希见 [crop-source-evidence.md](crop-source-evidence.md)、[crop-source.json](../spec/crop-source.json)。

新增 `mite:harvesting`（丰收）和 `mite:fertility`（肥沃）数据，由 `CropAssetsProvider` 生成，均保留 R196 权重 25、最高 V、有效预算最小成本 `1+10×(等级−1)`。源算法没有最大预算截止值；现代 `max_cost` 使用常量 `2147483647`，经本地 1.21.1 `Enchantment.Cost.CODEC` 的普通 `Codec.INT` 范围确认。现代铁砧费用 2、主手槽位为适配项。二者加入普通附魔台、可交易、随机战利品及非宝藏标签，工具支持表包含原作锄/鹤嘴锄/镰刀及全部六种新版锄，不新增与时运或精准采集的互斥。

`AgriculturalEnchantments.harvesting` 提供服务端统一的每单位额外掉落概率：有效工具的附魔等级除以 5，再乘 0.5；具体抽取由共享作物掉落处理完成。锄与鹤嘴锄适用于已纳入的食用作物，镰刀限小麦。铲子即便现代工具数据标记其挖作物较快，也不参与丰收或肥沃。第三方火把花等不在食用作物集合的方块不会被这两个农业钩子接管。

肥沃监听真正的 `BlockDropsEvent`，只接受正常玩家收获、成熟且未死亡、工具有效的作物；活的病株也可使耕地恢复肥力。它排除干旱、踩踏等共享原因作用域，尊重取消的掉落事件。成长阶段与死亡状态直接使用原方块状态，无额外玩家或世界保存表。

耕地肥沃监听 `BlockToolModificationEvent`，在未取消、非模拟、服务端的 `HOE_TILL` 最终输出为耕地时改变将要放置的状态。客户端、预览检测、取消的转换、错误工具或权限拒绝不消耗该概率。这样原版锄与已存在的 MITE 锄/鹤嘴锄真实交互路径均可接入，不依赖测试专用入口。

NeoForge 在计算默认改土结果前先发事件，事件初始输出仍是原始泥土。原始泥土、草方块、土径且其他模组未改结果时，先通过不重新发事件的方块扩展求原生结果，再附加肥沃状态；其他模组的替代输出与取消继续有效。

原 R196 根菜产量和肥沃概率使用 JVM 全局 `Math.random()`；现代以服务端世界随机源抽取来便于验证，保持概率而不承诺同种子抽样序列。新增 GameTest 覆盖实际掉落实体中的丰收效果与时运排除、活病株/幼株/死亡作物的肥沃边界、真实原版锄和 MITE 鹤嘴锄改土、模拟和外部取消。

无窗口测试由主任务统一运行；本文件不代表已通过客户端手动验收。
