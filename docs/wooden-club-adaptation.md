# 木棒与木制装备来源适配（012）

开发者：NingMeng123。版本依据为本地 MITE 1.6.4 R196 发布包。本文区分原始事实与已确定的现代方案，不声明构建、自动测试或游戏实测已经通过；固定数值与验收预期见 [结构化规格](../spec/r196-wooden-club.json)。

## 木棒对应哪件原作物品

R196 同时注册 `yc.cudgelWood`（ID 1024，`ItemCudgel`）和 `yc.clubWood`（ID 1025，`ItemClub`）。`aam.java:5` 的武器材料表把木材列中原本的剑配方产物设为 `clubWood`；`cudgelWood` 则有另一条独立配方。因此本轮“把木剑改为木棒”对应 **Wooden Club**。

发布包唯一语言文件 `assets/minecraft/lang/MITE.lang:169–170` 分别写作 Wooden Cudgel、Wooden Club，没有可核验的中文条目。“木棒”是本次中文命名，不冒充原包译名；Cudgel 不在本轮新增范围。

| 原作物品 | 配方 | 平均品质耐久 | 工具攻击加值 / 玩家总基础攻击 | 触及加值 | 可旧式格挡 |
| --- | --- | --- | --- | --- | --- |
| Club | 竖排木板、木板、木棍，1×3 | 400 | +2 / 3 | 0.5 | 是 |
| Cudgel | 竖排木板、木棍，1×2 | 200 | +1 / 2 | 0.25 | 否 |

来源为 `yc.java:235–236`、`ItemClub.java:6–28`、`ItemCudgel.java:6–45`、`xj.java:35–58,218–220`、`EnumEquipmentMaterial.java:6`、`uf.java:94–96`。原木材的耐久系数为 0.5，Club 的组件数为 2，因此 `4×2×0.5×100=400`；它不是 400 次攻击。

## 配方、注册与常规来源

现代沿用 `minecraft:wooden_sword` 的注册 ID，将该物品的名称、外观和行为改为木棒。配方保留竖排 2 木板加 1 木棍，产出 1 木棒；木板采用现代木板兼容范围，允许不同种类混合，是对旧 `aqz.C` 任意木板子类型的扩展。1×3 配方需要三行网格，不能在背包 2×2 合成。原配方见 `aam.java:5,9`，运行时注册记录 order 370：`[5:32767,5:32767,280:0]`，难度 185，CARPENTRY 标记，`bench_material=null`；没有特殊工作台材质字段不等于能放进 2×2。

R196 发布包的运行时物品表没有旧木剑 268、木镐 270、木斧 271、木锄 290；木铲 269 仍注册并有制造配方（`yc.java:31`、`aal.java:5`，配方 order 362）。本轮遵循用户指定范围：

- 木镐、木斧退出普通合成、创造物品栏、创造搜索和常规战利品来源。
- 保留 `minecraft:wooden_pickaxe`、`minecraft:wooden_axe` 注册及已有/命令给予物品的兼容，不删除存档中的物品。现存木斧仍受 011 原木门槛，不能因来源改动获得原木采集资格。
- 不扩大删除木铲、木锄。木铲有原作依据；现代木锄的保留是明确的范围选择。
- 木剑 ID 继续可读写，但承载木棒；使用重新绘制的新版风格材质，不复制旧贴图。

这些措施处理常规获取入口，不是全局禁止命令、已有物品或所有第三方数据包输出。木镐退出后，矿物第一把镐的常规获取路线留待后续金属阶段完善，不能将当前状态称为完整生存进度已经打通。

## 战斗与磨损

现代木棒采用平均品质基准：耐久 400、满冷却普通攻击总基础伤害 3、每次成功攻击基础磨损 25、附魔能力 10。保留现代木剑的 **1.6 次/秒攻击速度与冷却机制**；它不是 R196 原始攻击间隔。伤害 3 指无暴击、无附魔附加伤害、无效果与其他修正的基准，不是每次点击都固定扣 3 点生命。

`ItemCudgel.getBaseDecayRateForBreakingBlock/getBaseDecayRateForAttackingEntity` 均返回 `0.25f`，Club 继承该行为。`xj.java:145–180` 的普通磨损计算为：

```java
// 原始 Java float 顺序
decay = 100.0f * 0.25f; // 25
blockCost = H == 0.0f ? 0 : max(max((int)(H * decay), (int)(decay / 20.0f)), 1);
attackCost = max((int)(100.0f * 0.25f), 1); // 25
```

原破坏入口只对可损坏工具、非便携、非创造、正硬度且工具基础速度大于 1 的目标扣损；这与挥空、错误工具目标或任意右键都不同。无耐久附魔等修正时，Club 连续 15 次成功命中后损伤 375，第 16 次达到 400 后损坏。原作品质、诅咒及耐久附魔还可改变实际耐久或消耗，不能把该固定向量用于所有附魔状态。

原玩家伤害路径 `uf.java:1063–1064` 在目标是 `tr`（EntitySkeleton）、持物属于 `ItemCudgel` 或 `ItemWarHammer` 时将已有伤害乘 2；Club 是 Cudgel 子类，因此生效。字节码 191–217 检查这两项后 `fconst_2; fmul`，220–224 才加附魔附加伤害。普通零级 Club 对原骷髅的基础结果为 6；没有“全部亡灵翻倍”的分支。

现代把此目标范围明确映射为 Skeleton、Stray、Wither Skeleton、Bogged 四类。流浪者、沼骸等新增目标属于现代适配；僵尸、尸壳、溺尸、僵尸猪灵等亡灵不能仅因亡灵分类获得翻倍。通过现代 `Item.getAttackDamageBonus(target, damage, source)` 对这四类返回额外的 `damage`，在附魔伤害合并之前加上同量伤害；不把最终受伤事件中的全部伤害统一翻倍。独立测试须检查普通目标基准 3、骷髅家族基准 6及非骷髅亡灵仍为 3，并排除护甲、受伤无敌帧、暴击和未满冷却造成的混淆。

目标判断采用 `AbstractSkeleton` 继承关系：默认覆盖上述四种原版骷髅，同时接受继承该类的模组实体；骷髅马不在此范围。

没有证据支持木棒自带额外击退。`uf.java:1088–1093` 使用普通击退附魔及冲刺加值；默认木棒不应额外赠送一次击退。原 Club 的右键格挡、触及加值及旧版完整伤害处理，本轮不一并宣称还原。

## 采集、附魔与维修边界

原 Cudgel/Club 的有效材质列表为 cake、coral、glass、ice、pumpkin（`ItemCudgel.java:8`、`akc.java:636,657–667`）；还必须通过 `xj.java:125–138` 的等级检查，才有强度 2。木材工具等级为 0，**旧整玻璃和冰的方块门槛却是 1**（`aol.java:9`、`aov.java:12`），因此原木棒实际不能采集这两块。旧玻璃板、蛋糕、南瓜、南瓜灯门槛为 0，实际有效。列表没有原木、木板或蜘蛛网；无效工具目标按原 `uf.java:789–803` 回退空手。

本轮明确采用 **21 个原版高效目标**：蛋糕；南瓜、雕刻南瓜、南瓜灯；玻璃板和 16 色染色玻璃板。现代变体是显式适配，基础强度为 2，其他目标为 1。整玻璃、遮光/染色玻璃和各类冰不获得木棒高效采集；由于本轮尚未迁移全局最低采集等级，它们仍使用现代默认强度，不能宣称已还原旧版强度 0 的禁采结果。高效目标保留现代原始硬度和对应掉落规则，磨损仍按上述 `H×25` 后转整数、至少 1 的顺序计算。旧玻璃板/蛋糕/南瓜/南瓜灯的硬度分别为 0.1/0.5/0.6/1.0，对应原磨损 2/12/15/25，现代硬度不同就不能沿用这些结果。

旧 coral 材质只确认出现在工具有效材质列表，未取得活跃旧方块映射证据，**不据此默认加入全部现代珊瑚**。上述旧蛋糕、整玻璃、玻璃板、冰、南瓜和南瓜灯的类及继承链均未覆写 `isPortable`，沿用 `aqz.java:1687–1688` 的 false，没有遗漏这些旧已有目标的便携免磨损例外。木棒不获得 `AXE_DIG` 或剑类蜘蛛网特殊采集能力，011 的原木门槛继续适用。

原木材附魔能力是 10（`EnumEquipmentMaterial.java:6`，由 `xj.java:209–210` 返回）。原自然附魔允许击退、抢夺、耐久和眩晕（`abd.java:21–22`、`abe.java:33–35`、`aas.java:16–21`、`EnchantmentStun.java:16–17`）；不允许自然锋利、亡灵杀手、节肢杀手、火焰附加或效率（`aar.java:73–84`、`abc.java:21–22`、`aat.java:16–17`）。这是物品资格，不表示每种附魔必定出现在一次附魔结果中。

现代将木棒移出 SWORDS 标签，并结合 `supportsEnchantment` / `isPrimaryItemFor`，只允许击退、抢夺、耐久、经验修补、消失诅咒这五项物品附魔资格；移出自然锋利、亡灵杀手、节肢杀手、火焰附加和横扫之刃范围。经验修补和消失诅咒是适配；新眩晕附魔未实现。支持某附魔也不代表附魔台可以产生所有宝藏附魔。命令或既有物品写入的附魔组件继续兼容，不自动清除；这不承诺绕过现代 `/enchant` 命令本身的物品资格限制，也不将自然附魔限制误写成删除附魔系统。

原 `getRepairItem()` 对木材返回 null（`yc.java:886–909`），虽然 Club 的 `getRepairCost()` 字段为 4，也不能据此编造“4 木板修满”的配方。原两件同类物品合并修复另有规则（`aaf.java:263–320`），包括两件受损、同品质、未附魔等条件；本轮禁用材料维修，保留现代合并修复，不宣称该旧公式已完整迁移。
