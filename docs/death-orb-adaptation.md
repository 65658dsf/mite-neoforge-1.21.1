# 死亡经验球规则与现代适配

开发者：NingMeng123。原始规则以本地 R196 发布包为依据，本文记录目标行为与实现选择；实测证据另见逐功能测试记录。

## 原始证据

- `of.aB()` 在尸体 `DeathTime==20` 时分球，玩家死亡球的 Age 设为 −18000（字节码偏移 163–166），并记录死亡玩家名字。
- `oa.l_()` 对有归属的球仅寻找同世界的归属玩家（偏移 149–216），不会转而吸引陌生人。有效吸引距离为 8 格。
- `oa.b_(uf)` 在拾取前校验名字；正常球无归属限制。经验入口位于授权检查之后。
- `oa.l_()` 每次球更新增加 Age，到 6000 删除（偏移 573–594）。死亡球因此存在 24000 个实体更新 tick，普通球 6000；卸载、离线期间不消耗球龄。
- `oa.a(by)` / `b(by)` 保存球龄和归属。旧版没有经验球合并逻辑。

原死亡延迟依赖旧玩家尸体继续更新：提前重生移除旧对象可能丢球；到点前退出则保存 DeathTime，重进死亡状态后才继续计时。原版到点时才读取尸体位置、经验与游戏规则。

## 当前实现

| 项目 | 现代行为 |
| --- | --- |
| 掉落入口 | 在 NeoForge 经验掉落事件处理完毕后，只将玩家奖励转入延迟队列；其他生物仍走原版入口 |
| 归属身份 | 用玩家 UUID 代替大小写敏感的名字；重生、重登与改名不改变所属身份 |
| 延迟与位置 | 死亡时记录最终奖励、位置与归属，等待该位置可进行实体更新的 20 tick；入队当 tick 不计数，未加载区块不强制加载 |
| 快速复活与退出 | 每维度 `SavedData` 保存队列，独立于尸体；正常保存重进保留剩余延迟，不依赖玩家在线 |
| 分球 | 采用新版原版面额拆分，直接构造球、写入归属，再加入世界；不使用会提前合并的 `ExperienceOrb.award` |
| 拾取 | 在拾取事件、冷却和经验修补之前拒绝非所有者；所有者继续原版修补与剩余经验流程 |
| 吸引 | 两端都只跟随同维度、8 格内、存活且非旁观的所有者；每 tick 清理失效目标 |
| 寿命 | 有归属球服务端 Age 从 0 数到 24000，客户端等待服务端移除，普通球保持 6000；所有权同步到客户端，避免不同端更新速度导致提前消失 |
| 合并 | 任意涉及死亡球的合并都禁止，包括同一玩家的球；普通球保留新版合并功能 |

寿命 24000 tick 在正常 20 TPS 下约 20 分钟，按实体实际更新计算。保存重进保留 Age，不重置寿命；客户端年龄可能与服务端不同，最终删除由服务端同步决定。

归属使用版本 1 的 `mite:death_orb_owner` Data Attachment（version、owner UUID），持久化并同步到跟踪客户端。延迟队列存于各维度的 `mite_death_orbs` SavedData，版本 1 保存每笔奖励的 UUID、坐标、数量、剩余 tick 和最后处理 tick。正常发放后删除待处理项；实体生成事件如果取消某个球，不反复重试该取消结果。

## 明确差异与边界

固定死亡时奖励/位置、独立持久延迟队列及 UUID 身份属于现代适配，解决立即重生丢球、改名失去归属等旧版边界。不能把普通保存流程的正确性宣称为异常断电下的跨文件原子事务：队列和实体存档仍遵循 Minecraft 的正常保存机制。

本功能保留新版球碰撞与拾取可达性规则。旧版从球中心向玩家身体三个高度投射窄物理射线、特殊忽略铁栏杆等细节尚未移植；经验球的其他物理和受伤规则仍按现代版本处理。
