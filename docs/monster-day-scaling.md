# 怪物随日期成长

开发者：NingMeng123。更新：2026-10-23。

## 设置入口与默认行为

模组菜单选择 **MITE: Modern → 配置 → 怪物成长基准与公式**。生命和攻击分别编辑；鼠标滚轮可查看完整表单。界面直接读取当前有效设置，默认每天增加当前周期参考生命的 **0.5%**、本体攻击的 **0.25%**。`0.5` 是百分数，传入公式的 `rate` 为 `0.005`。

初始生命和初始本体攻击基准设为 `0` 时，沿用每个实体原有属性，不维护怪物名称名单；非零值则覆盖参与成长的实体初始属性。生命基准范围 `0–1024`，攻击基准 `0–2048`。手持武器加成在本体成长之后加入，不参与下一次基准结算。

默认每次**血月结束后的次日**，以该次血月结束时计算出的属性作为新周期的 `base` 和 `reference`。第 32、64、96、160 天结束后，分别从第 33、65、97、161 天使用新基准；第 128 天为蓝月，不重设基准，因此第 97 天开始的周期持续 64 天。此规则也适用于后续蓝月。各维度共用存档曾经到达的最高主世界日期；调回时间不会降低进度。

骷髅的首周期参考生命默认至少为 `20`。普通 6 血骷髅仍从 6 血开始，但首周期每天增加 `20 × 0.5% = 0.1` 生命；第 33 天基准变为实际结算的 `9.2`，之后每天增加 `9.2 × 0.5%`。这一例外仅影响首周期参考生命，不再永久维持虚拟 20 血基准。

默认公式下的例子：

| 历史最高日期 | 本周期已过天数 | 已结算血月 | 初始 20 血怪物 | 初始 6 血骷髅 | 本体攻击倍率 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 | 0 | 0 | 20 | 6 | 1 |
| 33 | 0 | 1 | 23.2 | 9.2 | 1.08 |
| 65 | 0 | 2 | 26.912 | 10.672 | 1.1664 |
| 97 | 0 | 3 | 31.21792 | 12.37952 | 1.259712 |
| 129（蓝月后） | 32 | 3 | 36.2127872 | 14.3602432 | 1.36048896 |
| 161 | 0 | 4 | 41.2076544 | 16.3409664 | 1.46126592 |

例如本体攻击为 3、武器增加 6：第 33 天本次近战基础伤害为 `3 × 1.08 + 6 = 9.24`。其他原生属性修饰、状态、附魔、护甲、韧性、抗性继续按原流程计算。

## 可编辑公式

完整计算有两个阶段，生命和攻击各自提供两项可编辑公式。**血月基准公式**在每次血月结束时结算下一周期基准；**周期内公式**用该基准计算当前属性。默认两项表达式相同，但传入的周期和血月次数不同：

```text
base + reference * rate * days
```

将血月参与计算的过程完整展开，默认规则为：

```text
base[0] = initial
reference[0] = initial（骷髅生命取 max(initial, skeleton_reference)）

每次血月结束，以 n 表示此前已经结算的血月次数：
base[n+1] = base[n] + reference[n] * rate * 本次完整周期天数
reference[n+1] = base[n+1]

当前属性 = base[n] + reference[n] * rate * 距最近血月结算的天数
```

血月基准公式中的 `days` 通常是 32，跨过蓝月后是 64；`day` 为该次血月结束后的次日，`blood_moons` 为本次结算前的次数。结算后次数加一，周期内公式再以新 `base`、新 `reference`、重计的 `days` 和更新的 `blood_moons` 运行。血月的影响体现在这一递推中，不能把 `base` 当成永远不变的初始属性。

例如初始生命 20、`rate=0.005`：第一次血月结算 `20 + 20 × 0.005 × 32 = 23.2`；第二次以 23.2 为基准结算 `23.2 + 23.2 × 0.005 × 32 = 26.912`。界面同时显示完整递推步骤、两项实际表达式，以及最近一次血月结算和当前周期的试算输入。

| 变量 | 含义 |
| --- | --- |
| `base` | 周期内公式取当前周期基准；血月公式取待结算的上周期基准。首次取实体原始属性或非零配置基准 |
| `initial` | 第一次计算前的初始基准，后续血月不改变它 |
| `reference` | 本周期增长参考值；首周期骷髅取 `max(initial, skeleton_reference)`，血月后取实际结算基准 |
| `rate` | 本项每日百分数 `/ 100 × 总体增长倍率 × 本项增长倍率` |
| `days` | 周期内公式取最近一次血月结算后经过的完整天数；血月公式取待结算周期的完整长度，通常 32，跨蓝月时为 64 |
| `day` | 本次计算使用的历史最高日期，从 1 开始；血月递推时使用当次结算日期 |
| `blood_moons` | 此次公式执行前已经完成基准重设的血月次数；蓝月不计入 |

支持十进制、科学计数法（如 `1e-3`）、括号、一元正负号，以及 `+ - * / % ^`。`^` 表示乘方、按右结合计算；`-2^2` 为 `-4`。函数支持：

- `abs(x)`、`sqrt(x)`、`log(x)`（自然对数）、`exp(x)`、`floor(x)`、`ceil(x)`。
- `min(a, b)`、`max(a, b)`、`pow(a, b)`、`clamp(value, minimum, maximum)`。

例如，每周期按日复利，可以将周期内公式和血月基准公式都改为：

```text
base * pow(1 + rate, days)
```

为了避免刚进入周期便额外跳变，通常应让公式在 `days = 0` 时返回 `base`。总体及分项倍率只乘入 `rate`；自定义公式如果忽略 `rate`，将不受这些倍率控制，倍率为 0 也不会自动关闭其中自行定义的增长。

## 校验、试算和失败保护

公式最多 512 字符，限制解析深度及运算数量，仅支持上述算术变量与函数。不会执行 Java、JavaScript、脚本、文件或网络调用。未知名称、括号或参数错误、除以零、非法函数定义域、非有限中间值或结果，以及负结果都会被拒绝。生命结果必须大于 0；本体攻击可以为 0。

输入后会同时校验生命与攻击两页的四项公式：先解析语法，再对代表性实体属性、配置的增长倍率、零倍率以及多个日期执行实际计算，包括多轮血月递推和蓝月边界。错误会标明属于生命/攻击的血月基准或周期内阶段。试算区可填写任意原始属性和日期，生命页还可切换骷髅规则；界面显示最近一次血月公式的结算输入和新基准、当前周期公式及其 `base`、`reference`、`days`、`day`、`blood_moons` 和有效增长率。试算结果显示的是应用原生属性上限之前的数值，实际生命仍受 Minecraft 1.21.1 的 1024 点限制。

任一配置、公式或当前试算不合法时，保存按钮禁用；状态栏显示原因，悬停可查看完整错误。校验成功后，保存时再次校验才写入。重置仅改变当前草稿；取消或 Esc 不写入。试算原始属性、日期和骷髅开关不写入配置。

直接修改 TOML 后也会在重载时重新校验，失败时保留上一份有效的怪物设置和增长倍率，避免发布损坏配置。有限样本无法证明任意自定义函数在所有未来日期都有效，因此每次实际运行仍检查定义域和有限结果；意外失败时回退默认线性公式。自定义公式每次最多递推 4096 次血月，超过预算也回退；默认公式使用有界运算，不受这一递推预算影响。当前界面试算若触发回退，会禁止保存并提示原因。

TOML 新增 `health_blood_moon_formula` 和 `damage_blood_moon_formula`；默认空字符串表示沿用对应的 `health_formula` / `damage_formula`，因此升级前的自定义公式保留原有的血月结算行为。专页会显示解析后的真实表达式，保存时将两阶段分别写入；此后修改某阶段仅影响该阶段。重置恢复两页全部四项公式。

## 生效和保存

- 参与范围为原版及其他模组的非 Boss `MONSTER` 分类和 MITE 敌对蝙蝠；末影龙、凋零及标记为 `c:bosses` 的模组 Boss 不参与生命和攻击成长，也不受成长设置的初始属性基准覆盖。普通动物、原版蝙蝠、凶狼、村民和玩家不参与。
- 旧存档中已获得日期生命增益的 Boss，在加载或下一次刷新时移除该增益和成长记录，保留原有受伤比例及其它属性修饰。
- 已存活怪物也会根据日期和配置更新生命，保留原有生命比例；同日重复刷新、重载和跨维度不叠加。
- 本体近战攻击在独立属性副本中成长后再加入装备属性，作用域结束后恢复，原始属性不会被反复改写。
- 箭、法术、有怪物归属的爆炸等其他攻击使用日期攻击倍率；环境伤害、玩家和动物伤害不成长，爆炸范围不改变。
- 血月装备材质只在新生时选择，与存活个体属性成长分别处理。
- 单机保存后即时生效；联机客户端显示服务端同步设置，只有服务器管理方可以修改。

## 手动验证

请使用测试存档；历史最高日期不能通过调回时间降低。

1. 在第 1 天生成普通僵尸和普通骷髅，确认初始 20 与 6 生命。设置页应显示生命每日 `0.5`、攻击每日 `0.25`，完整血月递推说明以及独立的血月基准、周期内公式，默认均为 `base + reference * rate * days`。
2. `/time set 774000` 到第 33 天，约一秒内旧个体应分别变为 23.2 与 9.2 生命；第 65 天应为 26.912 与 10.672。
3. 第 129 天检查蓝月没有重设基准，试算应显示 `days=32`、`blood_moons=3`；第 161 天应为 `days=0`、`blood_moons=4`。
4. 修改基准和公式并查看试算，再取消；重进界面应仍为先前保存值。保存有效配置后，旧个体应更新且保持受伤比例。
5. 分别输入 `base / 0`、`unknown + base`、`sqrt(-1)`、不闭合括号及负结果，确认出现错误且无法保存。修改另一页为非法公式后，切回本页也不能保存。
6. 用 `base * pow(1 + rate, days)` 观察复利结果；对比自定义公式完全忽略 `rate` 时的倍率行为。
7. 在原始生命 6、骷髅规则开启的试算中检查第 33、65、161 天，确认后续基准为真实生命。给怪物装备武器，确认武器额外攻击不加入成长基准。
8. 将生命血月基准公式改为 `base + 10`，周期内公式保持默认：第 33 天基准应为 30，第 34 天生命为 30.15；第 65 天基准为 40。输入非法血月公式应无法保存，不能因周期内公式有效而通过。
