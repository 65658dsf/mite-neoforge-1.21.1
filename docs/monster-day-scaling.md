# 怪物随日期成长

开发者：NingMeng123。更新：2026-11-20。

## 设置入口与默认行为

除原版凋零和末影龙外，敌对怪物的生命与攻击默认每天各增加当前周期参考值的 **0.5%**。第 1 天使用初始属性，第 2 天获得第一次增量。在 **MITE: Modern → 配置 → 怪物成长基准与公式** 中，生命页与攻击页可分别调整基准、每日百分数、周期内公式和血月基准公式。每日百分数填 `0.5`，总体和分项倍率均为 1 时，公式使用的 `rate` 为 `0.005`。

所有怪物保留各自出生血量，普通骷髅为 6 血。`health_base` 统一设置首周期增长参考生命，默认为 `20`，旧配置的 `0` 也按 `20` 处理，范围为 `0–1024`。攻击首周期以怪物自身的本体攻击为参考。配置项 `damage_base` 默认为 `0` 时沿用该值，设为正值可指定起始本体攻击，范围为 `0–2048`。近战武器加成在本体攻击成长后加入。

默认每次**血月结束后的次日**，以该次血月结束时计算出的属性作为新周期的 `base` 和 `reference`。第 32、64、96、160 天结束后，分别从第 33、65、97、161 天使用新基准；第 128 天为蓝月，不重设基准，因此第 97 天开始的周期持续 64 天。此规则也适用于后续蓝月。各维度共用存档曾经到达的最高主世界日期；调回时间不会降低进度。

所有怪物的首周期参考生命默认统一为 `20`，每天增加 `20 × 0.5% = 0.1` 生命。初始 30 血怪物第 2 天为 30.1 血，普通 6 血骷髅第 2 天为 6.1 血。骷髅第 33 天基准变为实际结算的 `9.2`，之后每天增加 `9.2 × 0.5%`。旧字段 `skeleton_reference` 保留配置读写兼容，计算统一使用 `health_base`。

默认公式下的例子：

| 历史最高日期 | 本周期已过天数 | 已结算血月 | 初始 20 血怪物 | 初始 6 血骷髅 | 本体攻击倍率 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 | 0 | 0 | 20 | 6 | 1 |
| 2 | 1 | 0 | 20.1 | 6.1 | 1.005 |
| 33 | 0 | 1 | 23.2 | 9.2 | 1.16 |
| 65 | 0 | 2 | 26.912 | 10.672 | 1.3456 |
| 97 | 0 | 3 | 31.21792 | 12.37952 | 1.560896 |
| 129（蓝月后） | 32 | 3 | 36.2127872 | 14.3602432 | 1.81063936 |
| 161 | 0 | 4 | 41.2076544 | 16.3409664 | 2.06038272 |

例如怪物本体攻击为 3、武器增加 6，第 1 天近战伤害为 9，第 33 天为 `3 × 1.16 + 6 = 9.48`，第 65 天为 `3 × 1.3456 + 6 = 10.0368`。其他原生属性修饰、状态、附魔、护甲、韧性、抗性继续按原流程计算。

骷髅箭矢也逐日增长。普通骷髅的锈铁箭按持弓规则减半后，第 1 天基础命中为 2.5 点，第 33 天为 2.9 点，第 65 天为 3.364 点。跨过蓝月后，第 129 天约为 4.527 点，第 130 天约为 4.546 点。目标护甲和抗性在此基础上结算。

## 可编辑公式

生命和攻击各有两个阶段。**血月基准公式**在每次血月结束时结算下一周期的属性基准，**周期内公式**用该基准计算当前属性。两阶段的周期和血月次数分别取值，默认都使用以下表达式。

```text
base + reference * rate * days
```

将血月参与计算的过程完整展开，默认规则为：

```text
base[0] = initial
生命 reference[0] = health_base（默认 20，旧值 0 也取 20）
攻击 reference[0] = initial（初始本体攻击）

每次血月结束，以 n 表示此前已经结算的血月次数：
base[n+1] = base[n] + reference[n] * rate * 本次完整周期天数
reference[n+1] = base[n+1]

当前属性 = base[n] + reference[n] * rate * 距最近血月结算的天数
```

血月基准公式中的 `days` 通常是 32，跨过蓝月后是 64；`day` 为该次血月结束后的次日，`blood_moons` 为本次结算前的次数。结算后次数加一，周期内公式再以新 `base`、新 `reference`、重计的 `days` 和更新的 `blood_moons` 运行。血月的影响体现在这一递推中，不能把 `base` 当成永远不变的初始属性。

例如初始生命 20、`rate=0.005`：第一次血月结算 `20 + 20 × 0.005 × 32 = 23.2`；第二次以 23.2 为基准结算 `23.2 + 23.2 × 0.005 × 32 = 26.912`。界面同时显示完整递推步骤、两项实际表达式，以及最近一次血月结算和当前周期的试算输入。

| 变量 | 含义 |
| --- | --- |
| `base` | 周期内公式取当前周期基准，血月公式取待结算的上周期基准。首次取 `initial` |
| `initial` | 第一次计算前的初始基准，后续血月不改变它 |
| `reference` | 本周期增长参考值。首周期生命取 `health_base`，默认 20，攻击取起始本体攻击。血月后两者各自取其结算的新基准 |
| `rate` | 本项每日百分数 `/ 100 × 总体增长倍率 × 本项增长倍率` |
| `days` | 周期内公式取最近一次血月结算后经过的完整天数；血月公式取待结算周期的完整长度，通常 32，跨蓝月时为 64 |
| `day` | 本次计算使用的历史最高日期，从 1 开始；血月递推时使用当次结算日期 |
| `blood_moons` | 此次公式执行前已经完成基准重设的血月次数；蓝月不计入 |

支持十进制、科学计数法（如 `1e-3`）、括号、一元正负号，以及 `+ - * / % ^`。`^` 表示乘方、按右结合计算；`-2^2` 为 `-4`。函数支持：

- `abs(x)`、`sqrt(x)`、`log(x)`（自然对数）、`exp(x)`、`floor(x)`、`ceil(x)`。
- `min(a, b)`、`max(a, b)`、`pow(a, b)`、`clamp(value, minimum, maximum)`。

例如，每周期按日复利，可以将周期内公式和血月基准公式都改为：

```text
base * pow(1 + rate, days)
```

为了避免刚进入周期便额外跳变，通常应让公式在 `days = 0` 时返回 `base`。总体及分项倍率只乘入 `rate`；自定义公式如果忽略 `rate`，将不受这些倍率控制，倍率为 0 也不会自动关闭其中自行定义的增长。

## 校验、试算和失败保护

每条公式最多 512 字符，限制解析深度及运算数量，仅支持上述算术变量与函数。不会执行 Java、JavaScript、脚本、文件或网络调用。未知名称、括号或参数错误、除以零、非法函数定义域、非有限中间值或结果、非正生命或负攻击结果都会被拒绝。

生命和攻击的四项公式一起校验。先解析语法，再对代表性实体属性、配置的增长倍率、零倍率以及多个日期执行实际计算，包括多轮血月递推和蓝月边界。两页均可填写原始属性和日期进行试算，例如普通骷髅的原始生命填写 6。界面显示最近一次血月公式的结算输入和新基准、当前周期公式及其 `base`、`reference`、`days`、`day`、`blood_moons` 和有效增长率。实际生命默认受 Minecraft 1.21.1 的 1024 点限制。

任一配置、公式或当前试算不合法时，保存按钮禁用；状态栏显示原因，悬停可查看完整错误。校验成功后，保存时再次校验才写入。重置仅改变当前草稿；取消或 Esc 不写入。试算原始属性和日期独立保留在当前界面。

直接修改 TOML 后也会在重载时重新校验，失败时保留上一份有效的怪物设置和增长倍率，避免发布损坏配置。有限样本无法证明任意自定义函数在所有未来日期都有效，因此每次实际运行仍检查定义域和有限结果；意外失败时回退默认线性公式。自定义公式每次最多递推 4096 次血月，超过预算也回退；默认公式使用有界运算，不受这一递推预算影响。当前界面试算若触发回退，会禁止保存并提示原因。

TOML 中留空的 `health_blood_moon_formula` 和 `damage_blood_moon_formula` 分别沿用 `health_formula` 和 `damage_formula`。这样只设置周期内公式时，血月也会按对应的表达式结算。

旧配置首次升级时，若每日攻击增长为 `0.25`、攻击增长倍率为 `1` 且两项攻击公式都使用默认表达式，每日攻击增长会更新为 `0.5`，并沿用原有的本体攻击基准。手动填入与旧默认完全相同的组合也会触发这次更新，升级后可重新设为 `0.25` 并长期保留。若旧攻击公式无法执行，首次升级会用默认公式修复相应阶段，保留有效的生命配置和成长倍率。

## 生效和保存

- 成长适用于原版及其他模组的 `MONSTER` 分类生物和 MITE 敌对蝙蝠，唯一豁免的是原版凋零和末影龙。MITE Modern ITE 的僵尸领主（`modern_ite:zombie_lord`）、僵尸精英领主，以及带有 `c:bosses` 标签的其他敌对怪物，都按相同日期规则增长生命和攻击。普通动物、原版蝙蝠、凶狼、村民和玩家不参与。
- 凋零和末影龙保留自身的生命和攻击基准。若旧存档中这两种生物带有日期生命增益，加载或下次刷新时会清除该增益和成长记录，并保留原有受伤比例及其他属性修饰。
- 已存活怪物也会根据日期和配置更新生命，保留原有生命比例；同日重复刷新、重载和跨维度不叠加。
- 本体近战攻击按当前历史最高日期计算，在独立属性副本中加入装备等修饰后结算。怪物重载时沿用已记录的最高进度。
- 怪物射出的箭、法术和有怪物归属的爆炸，按各自基础伤害乘日期攻击倍率，随后结算减伤。相对倍率以 1 作为起点。荆棘反伤、玩家徒手击打怪物造成的手部自伤和无主环境伤害沿用各自的基础伤害。
- 血月装备材质只在新生时选择，与存活个体属性成长分别处理。
- 单机保存后即时生效；联机客户端显示服务端同步设置，只有服务器管理方可以修改。

## 手动验证

请使用测试存档；历史最高日期不能通过调回时间降低。

1. 在第 1 天生成普通僵尸和普通骷髅，确认初始 20 与 6 生命。生命页和攻击页默认每日均为 `0.5`，两页的两阶段公式均为 `base + reference * rate * days`。攻击试算填入原始本体攻击 3，第 2 天应为 3.015。
2. `/time set 774000` 到第 33 天，约一秒内旧个体应分别变为 23.2 与 9.2 生命；第 65 天应为 26.912 与 10.672。
3. 第 129 天检查蓝月没有重设基准，试算应显示 `days=32`、`blood_moons=3`；第 161 天应为 `days=0`、`blood_moons=4`。
4. 修改基准和公式并查看试算，再取消；重进界面应仍为先前保存值。保存有效配置后，旧个体应更新且保持受伤比例。
5. 在生命页或攻击页分别输入 `base / 0`、`unknown + base`、`sqrt(-1)`、不闭合括号及负结果，确认出现错误且无法保存。
6. 用 `base * pow(1 + rate, days)` 观察复利结果；对比自定义公式完全忽略 `rate` 时的倍率行为。
7. 将试算原始生命填写为 6，检查第 33、65、161 天，确认后续基准为真实生命。将原始生命改为 30，第 2 天应为 30.1。对同一无护甲目标比较普通骷髅锈铁箭的直接命中，第 1 天应为 2.5 点，第 33 天为 2.9 点。
8. 将生命血月基准公式改为 `base + 10`，周期内公式保持默认：第 33 天基准应为 30，第 34 天生命为 30.15；第 65 天基准为 40。输入非法血月公式应无法保存，不能因周期内公式有效而通过。
