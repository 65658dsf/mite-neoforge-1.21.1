# R196 方块有效硬度核对

开发者：NingMeng123。核对日期：2026-10-28。依据为本地 R196 发布包的 CFR 输出、`javap -c -p` 和 [实际注册快照](../reference-data/runtime-registry.json)。旧源码路径均相对 `.reference/r196/decompiled/`。

## 黑曜石耐久问题

R196 普通黑曜石实际硬度为 **2.4F**，镐的挖掘损耗率为 **1F**。一次有效挖掘的无附魔基础损耗是 `max((int)(2.4F * 100F), (int)(100F / 20F), 1)`，即 **240**。普通铁镐基础最大耐久为 **9600**，挖一个后应剩 **9360**。

修复前，`MiningProgress.effectiveHardness` 对普通黑曜石回退到现代注册硬度 **50F**；耐久入口复用该结果，实际扣除 `50 * 100 = 5000`。问题在方块硬度映射，工具损耗公式本身与旧版一致。

证据链：

- `aqz.java:2309` 实际注册 `new apq(49).c(2.4f)`；`aqz.java:637–639,654–655` 证明 `.c()` 设置的 `cG` 就是查询结果。
- `BlockBreakInfo.java:285–286` 将方块实际硬度传给损耗计算。
- `yn.java:27–29` 的镐挖掘基础损耗率为 `1F`。
- `xj.java:145–151,171–180` 实现硬度损耗公式和实际调用；`xj.java:35–40`、`yn.java:22–24`、`EnumEquipmentMaterial.java:13` 给出铁镐 `4 * 3 * 8 * 100 = 9600`。
- 实际注册快照中 ID 49 的 `aqz.cG` 为 `2.4`。`javap aqz` 的注册字节码偏移 2090 加载 `2.4f`，2093 调用 `apq.c(F)`；`javap xj` 证明损耗使用 float 乘法再转 int。

**不能使用未接入注册的同名常量。** `BlockHardness.obsidian` 虽为 `8F`，实际黑曜石注册没有引用它；`BlockHardness.cobblestone`、`gravel`、`glass` 等也不能代替实际注册结果。此前 [基础挖掘适配](mining-base-adaptation.md) 已核实砂砾注册为 `0.6F`，而非未使用的 `0.8F` 常量。

## 矿石与现代内容边界

旧煤矿 **1.2**、金矿 **2.4**、铜矿及银矿 **2.5**、秘银矿 **3.5**、艾德曼矿 **4**；铁矿、青金石矿、红石矿、钻石矿、绿宝石矿、下界石英矿均为 **3**。这些实际值已由 `OreBlockRules.hardness` 接入，不能重新用未使用的旧常量覆写。

深板岩矿石沿用同矿种源硬度，是现有明确的现代适配；普通深板岩没有 R196 对应，不应假称提取了其旧值。哭泣黑曜石、染色玻璃及染色玻璃板、现代石材和现代木种等同理：必须区分直接旧对应与明确的现代扩展。已有原木适配已将原版新木种及菌柄纳入 `1.2F`；这不自动授权将所有现代木制方块都归为旧木板或旧栅栏。

旧砂岩的亚型没有动态硬度变化。`aqh.java:9–10,35–41` 的旧 `smooth` 亚型使用 `sandstone_smooth` 侧纹，对应现代切制砂岩；现代烧制平滑砂岩不能仅据名称里的 `smooth` 当作同一旧亚型。旧石英的普通、錾制、各轴柱状亚型均为 `0.8F`，现代平滑石英、石英砖另属新增。石砖的普通、苔、裂纹、錾制亚型共享注册的 `1.5F`。旧版本没有现代彩色玻璃方块；各色羊毛和各色陶瓦确实存在，不能混淆。

## 元数据与形状

`BlockSlab.java:100–125` 先按模型方块选取专用基值，再乘 `0.5F`；`BlockDoubleSlab.java:94–95` 为单半砖查询结果乘二。因此不能对所有半砖直接使用完整方块硬度除二，也不能从其静态注册字段读取零。

| 半砖材料 | 单半砖 | 双半砖 |
| --- | ---: | ---: |
| 石质半砖 | 1.2 | 2.4 |
| 砂岩 | 0.5 | 1 |
| 木材 | 0.4 | 0.8 |
| 圆石、砖、石砖、下界砖 | 1 | 2 |
| 石英 | 0.4 | 0.8 |
| 黑曜石 | 1.2 | 2.4 |

特别是**砂岩双半砖为 1，完整砂岩为 0.8；石砖双半砖为 2，完整石砖为 1.5**。旧石半砖使用 `stone_slab_top`、`stone_slab_side` 纹理，现代对应平滑石半砖；现代普通石半砖不能仅据名称中的 `stone` 当成直接旧对应。双石半砖对应完整的旧双层资产，也不能据此将所有现代石材都设为 `2.4F`。

`BlockSlabGroup1.java:6,40–44` 定义旧亚型顺序：石、砂岩、木、圆石、砖、石砖、下界砖、石英；该组木亚型实际禁止，正常木半砖位于 `BlockSlabGroup2`。顶部标志不改变硬度。`BlockSlabGroup3` 对应黑曜石。

楼梯 `aqp.java:12–16` 在构造时复制完整模型硬度，朝向和上下半部不改变硬度。旧木楼梯为 **0.8**；圆石、砖、下界砖楼梯为 **2**；石砖楼梯为 **1.5**；砂岩、石英楼梯为 **0.8**；黑曜石楼梯为 **2.4**。

其他动态查询：

- `arf.java:166–167`：雪层硬度为 `0.05F * 层数`，一至八层对应 `0.05–0.4`；不能把所有雪层固定为注册的 `0.05`。
- `arm.java:287–308`：藤蔓硬度为 `0.2F * max(四个水平面中的藤蔓数量, 1)`；顶部连接不能另算一个旧水平面，零水平面仍按一面计。
- `anr.java:220–221`：作物 metadata 0 硬度为零，普通生长期为 `0.02`，成熟为 `0.04`；染病位可能使零生长阶段不再等于 metadata 0。现有作物适配已处理这一区别。

## 接入范围与验证边界

此前 [基础挖掘适配](mining-base-adaptation.md) 明确只覆写部分开局方块，其他目标保留现代硬度；[016 耐久适配](durability-016-evidence.md) 也明确复用这套局部有效硬度。因此石头原先按现代 `1.5F` 扣 **150** 属于此前已记录的未迁移范围，不能将它当成 R196 的实际石头损耗值。

本轮已将核实的旧对应接入共享的局部有效硬度，保持挖掘、耐久和其他已读取该适配的来源规则一致。纯规则表位于 `BlockHardnessRules`，状态适配位于 `SourceBlockHardness`，完整映射及来源见 [结构化规格](../spec/r196-block-hardness.json)。适配层不修改方块注册硬度和爆炸抗性；普通黑曜石已单独采用的原版钻石镐挖掘时间分支继续保留。现代新增且未明确映射的方块保留既有回退，第三方命名空间不因广泛标签误命中。

便携方块的初始强度 `4H` 同步读取有效硬度，避免进度分母换成旧值而强度仍按现代值计算；0 级处理速度继续为 `1/128`。工具免耗与保险箱所有权判断保持原入口。

放置费用另遵循 `uf.java:2405–2411` 的 `getBlockHardness(0)`：雪层每次按 0.05，藤蔓按 0.2；四种旧木半砖按 0.4；旧石质半砖组 ID 44 的所有材质亚型均按 metadata 0 的石质模型 1.2，不随最终双半砖状态翻倍。这与挖掘时使用实际亚型、层数及连接面数不同。无旧对应的现代方块继续采用既有放置费用。

`MiningProgress.effectiveHardness` 的消费者不只有工具耐久，还包括普通挖掘、装备采集经验、放置与耕地疲劳、怪物挖掘以及部分来源物理规则；验证需要覆盖这些实际调用边界。便携方块另有免工具损耗规则，不能仅凭其硬度推断工具必然扣损。本文记录来源核对，不将静态证据冒称游戏实测；本轮实际构建与 GameTest 结果由主线程记录。
