## 地幔与地核

旧版注册只有一个 `mantleOrCore` 方块（ID 95），metadata 0 为地幔，1 为地核；新版可拆成 `mite:mantle` 与 `mite:core`，行为仍需共用规则。

- 硬度 −1、最低采集等级 100、`alwaysImmutable`、不可携带；不产生自身掉落，也不接受丝触采集。
- 光照来自 `(int)(15 × 0.9)`，实际为 **13**，不是 14。
- `BlockMantleOrCore.updateTick` 随机点燃邻近可燃方块，逻辑与旧熔岩点火一致：随机 0–2 次向上游走；0 次分支检查同层 3 个周边位置上方。
- 水流和水桶试图在其正上方放水时，拒绝放置并产生蒸汽（`apd.java:154`、`wr.java:178`）。这与此前保留现代水桶水源放置行为的适配可同时成立。

需要区分注册参数和启用行为。注册链中的 `.b(6000000)` 已无效果：`aqz.b(float)` 字节码只有 `aload_0; areturn`；`getExplosionResistance` 返回硬度 `cG`。地幔的爆炸保护来自 `alwaysImmutable` 和爆炸代码明确排除（`abr.java:120`、`aci.java:412`），不能把 6,000,000 当作 R196 实际参与计算的爆抗。新版若使用高爆抗确保现代爆炸不移除地幔，应明确这是实现等效保护。

热伤不是“任何位置碰到地幔就受伤”。`nn.java:621` 要求膨胀 0.001 的实体包围盒接触该方块，且满足：

- 地底世界：包围盒最低 Y ≤3。
- 下界：包围盒最低 Y ≤1 或最高 Y ≥123。
- 主世界和其它高度的人工地幔不走这条直接灼烧规则。

满足后执行 `spentTickInFire`（`nn.java:227–265`）：Living 每刻尝试 1 点 IN_FIRE，非 Living 每 10 刻尝试一次（`nn.java:1066`），最终伤害仍经过免疫、护甲及受伤无敌帧。未湿且能燃烧时，火焰计数递增到 0 才开始燃烧。`d(8)` 持续 **170 刻**（8×20+10），火焰保护按 `floor(duration×level×0.15)` 缩短；燃烧期间每 20 刻尝试 1 点 ON_FIRE（`nn.java:422,474`）。玩家初始接触防火计数是 10（`uf.java:2232`）。不能把 170 刻和接触伤害频率都简化为每秒扣一次。

旧下界 `aep.java:117–157` 在 **Y=0** 填地幔/地核方块，`adr.java:133` 只在 Y<1 设 metadata 1，因此底部为地核。顶部 Y≥127−nextInt(5) 是 metadata **0 地幔**，不是地核。新版保留下界生物群系和地形，只移植边界时须记录这一点；传送目的地的 bottomBlock 判断仍只接受下界地核 metadata 1。

地底与下界也禁止睡床，但不会像现代下界床那样爆炸。`anb.java:51` 只有允许睡眠的世界且群系不是 Hell 才调用睡眠；其它条件返回 `tile.bed.mobsDigging` 提示，保留床。现代实现从玩家真实右键交互入口阻止睡眠和爆炸，不改变主世界正常睡眠。

## 普通地狱门与符文门

普通点火门内框固定 **2×3**，外框 **4×5**；非角框架必须为黑曜石，四个角可省略；末地不能点火生成（`aps.java:87–140`）。普通门和符文门共用原版门方块，但 metadata 保存目的地：0 主世界、1 地底世界、2 下界；bit 8 表示符文门。

| 门的位置/条件 | R196 目的地 |
| --- | --- |
| 四角全为同一种秘银/艾德曼符文石 | 当前维度的符文坐标，优先于下面规则 |
| 主世界，底框接触底部基岩 | 地底世界 |
| 主世界，其它高度普通门 | 主世界出生点 |
| 地底世界，底框接触地幔 | 下界 |
| 地底世界，其它高度普通门 | 主世界 |
| 下界普通门 | 地底世界 |

“接触底部”必须同时满足旧版底框 Y≤8，并且框架任意位置的正下方是当前维度 bottomBlock（`aps.java:317`、`abw.java:5699`）。主世界接受基岩；地底世界接受地幔；下界接受地核。在高空摆一块基岩不能通过。1.21.1 主世界把 Y≤8 改为 `Y≤minBuildHeight+8`，这是对应世界高度的适配；地底保留 0 起点。

涉及下界的 X/Z 8 倍换算；主世界↔地底不缩放（`hn.java:320`）。返回门搜寻 X/Z 半径 128，必须指向刚离开的维度，排除符文门。未找到则建立返回门并写反向目的地（`acj.java:19,52`）。源 `aps.updateType` 仅在符文位发生改变时更新 metadata，普通自动反向门不能被每刻位置重判覆盖。普通门生存玩家等 80 刻、创造玩家与其它实体等 0；离开后玩家冷却 10 刻、其它实体冷却 900 刻，持续站在门内会重置该冷却（`nn.java:352,1824`、`uf.java:428`）。符文与出生点门直接走独立流程，不走普通 80 刻等待。实际 R196 的门随机生成怪物被无条件清空候选关闭（`aps.java:47`；字节码核对），不要恢复仅存在于前面分支的 1/100 刷怪。

符文门只传服务器玩家，坐骑/乘客关系会阻止传送。四角值按低轴下角、高轴下角、低轴上角、高轴上角各 4 位拼成 16 位 seed（`aps.java:304`）。seed 0 固定去 X=Z=0；其余用 `java.util.Random(seed)`，原始随机数不含世界 seed，世界 seed 会通过海洋生物群系避让影响最终选取（最多 4 次）。秘银范围 `min(worldRadius/2,40000)/8`，艾德曼范围 `min(worldRadius/2,40000)` 并排除半径内圈。原版找不到安全地点时破坏 Y64/65；新版不能盲目破坏不可变边界，应在有效高度、世界边界和安全落点内完成传送或原地失败，单独标为安全适配。

## 给后续矿物与生态保留的接口

矿物不要把 120 主洞穴偏移加到起点。旧 `WorldGenMinable` 在地底仍用 Y 0–255：艾德曼起点 Y 0–135；其它 BlockOre 有 75% 起点 Y 0–135、25% 起点 Y 0–255。非 BlockOre 统一 0–255。BiomeDecorator 把非砂砾候选数乘 8，艾德曼再乘 2，然后每候选再按 1/10 判定执行；砂砾候选 300，不乘 8且必须有支撑。这些并非“每区块成功生成 300 条矿脉”。源码 `acu.java:302–377`、`afq.java:87,107,114,203`。

新版维度应有独立群系 feature 列表及石头可替换标签，禁止矿物替换地幔、地核和基岩；主世界新版矿物逻辑留待单独迁移。本项先实现进出路径、世界几何、边界和资源接口，矿物概率及真实 MITE 怪物是后续内容。

生态证据已纳入 JSON，避免以后按类名猜测：

- Underworld 子类移除普通骷髅、僵尸、食尸鬼、亡魂、BoneLord；新增洞穴蜘蛛 weight40 / group1–2，Longdead weight40 / group1–2，AncientBoneLord weight5 / group1。父类候选中的其它 MITE 怪物还需各自生成条件过滤；普通骷髅不能标为 Longdead 已复刻。
- 菌丝中心点半径 24、每区块出现概率 1/16；起点 Y 为 144–159 或 144–215，逐层查 1–5，上方空气且脚下与其下方实心，排除沙砾类方块。1/16 尝试巨蘑菇，失败后放棕蘑菇（`BiomeGenUnderworld.java:31`、`abw.java:253`）。
- 默认每区块 16 次地牢尝试，起点 Y140–171；古金属工具/护甲/钱币/唱片箱；刷怪笼 5/6 Longdead、1/6 LongdeadGuardian（`ChunkProviderUnderworld.java:273`、`afp.java:112`）。完整缺失物品与实体齐备前不能直接称已完全还原地牢。
- 每区块 70 次地下泉水候选，local Y=`nextInt(nextInt(120)+8)` 再加 120；相邻自然菌丝区块会阻止这段液体生成（`acu.java:265`）。
