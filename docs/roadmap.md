## 每个小功能的工作单元

固定粒度为一个可以在游戏内独立观察、验证和提交的行为，例如“空手不能采集原木”“一种炉型达到指定热量”“一种配方按时完成”。不把“全部生存”“全部新生物”打包为一个小功能。

每个工作单元依次执行：规格来源 → 实现 → 必要自动测试 → **打开游戏实测** → 记录结果 → **中文 commit** → **push GitHub**。实测失败先修复，不通过不能提交为已完成功能。联机相关工作同时包含客户端连接独立服务器测试；GameTest 不替代可见界面与交互测试。来源索引或文档准备不冒充一个已经完成的玩法功能。

每项状态使用 `planned / implemented / automated_passed / in_game_passed / committed / pushed`；执行证据记录在验收记录中。commit 建议形式：`feat: 限制空手采集原木并增加工具提示`、`fix: 修复重启后重复结算合成输出`。署名统一 NingMeng123。GitHub 账号是 `65658dsf`，具体仓库/分支须由实际 remote 或用户指定确定，不能把账号 URL 当成仓库。

## 关键先后关系

- 原始材料硬度与设备能力 → 采集/维修/炉温 → 全量制造；不能先用材料名排序充当硬度。
- 存储版本与服务端事务 → 玩家状态/耗时制作/自动化；HUD 在稳定的同步载荷上显示。
- 原版配方和掉落来源索引 → 现代装备配方与来源成本 → 交易/结构/自动化来源回归。
- 原作食品与牲畜规则 → 新版食物/作物映射；不能把新食品直接视为零营养或任意营养。
- 维度规则提取 → 生成与安全传送 → 世界进度和完整成长；现代地形保留不代表地下世界可省略。
