## 施咒、延迟与保存

女巫的目标 AI 在候选玩家通过存活、可攻击、阵营、活动范围与视线检查之后，以 `nextInt(4) == 0` 尝试施咒，概率为 25%。这是目标候选检查中的概率，不是每 tick 抽签，也不需要药水命中。追踪同一个目标时的重新搜索也会检查候选。原作 `re.java:68-101`、`qy.java:90-113`；现代接入 `SourceMonsterTargeting.SourceTarget.initiallySuitable`。

女巫已经死亡、玩家已有生效诅咒或待生效诅咒时，不会新增记录。成功后经过 6000 游戏 tick 生效，即正常 20 TPS 下 5 分钟；等待时没有提前通知。`tv.java:279-290`、`js.java:1389-1393,1440-1472`。

每只女巫保存独立的 `int curse_random_seed`。玩家名按 UTF-16 字符位置求和：`hash += username.charAt(i) * i`，首字符权重为 0。女巫种子与 hash 先按 Java `int` 相加、允许 32 位溢出，再作为 `Random` 的 `long` 种子。抽取 `nextInt(64)`，跳过空项，直到命中 ID 1 至 16。因此各类型等概率 6.25%，但确定性序列不能替换为 `nextInt(16) + 1`。`tv.java:18,32-33,262-290`、`Curse.java:8-24,53-60`；已检查发布包字节码的 `iadd` 在 `i2l` 之前。

原作把记录放在各维度共用的 `WorldInfoShared.curses`，保存玩家名、施咒女巫 UUID、类型、生效时刻、是否生效和是否已知。玩家死亡、退出、重进或换维度不会解除诅咒；女巫区块卸载也不会解除。离线玩家不执行生效回调，重新在线后时刻已到便生效。`WorldInfoShared.java:150-156,248-264`、`als.java:30-32,324-325`、`js.java:1440-1472`。

现代版本使用主世界 `SavedData` 保存全局记录，用玩家 UUID 定位玩家，保留施咒时玩家名以决定类型；时钟统一为主世界 `gameTime`。这两项是明确的现代适配：改名不会丢失诅咒，不同维度不会因旧版独立时钟造成计时差异。存档带版本号。玩家附件只同步生效类型和是否已发现，客户端不决定施加、解除或随机结果。

无法憋气的原作 `of.h` 虽调用诅咒检查，但其 `if` 块为空；没有据此额外增加耗气倍率。现代保留 1.21.1 水下呼吸与效果行为，只应用原作 90 点上限。原作 `avj.java:637` 只在水中画空气条；现代原生 HUD 会在陆地空气未满时也画，因此本实现仅在陆地的 HUD 读取处掩去这条诅咒造成的残缺空气条，真实空气保持 90，水下显示不受影响。

食品分类使用原作 `isAnimalProduct` 与 `isPlantProduct`，不拿蛋白质、植物营养或饱和度代替。蛋糕每一口同时检查动物和植物限制。食品在开始、使用期间和完成前重验，避免中途诅咒生效后继续吃掉。现代新增食物的映射在食品证据表中逐项标记；未知其他模组食品不猜测动植物属性，饮用动画仍受禁饮限制。

现代植物映射为 `VineBlock` ×0.2，`BushBlock`、`GrowingPlantBlock`、`SugarCaneBlock`、`BambooStalkBlock` ×0.4。普通地面、梯子和石头不触发。现代亡灵使用 `EntityTypeTags.UNDEAD`，包括新增及保留的新版亡灵。恐惧使用被攻击生物的随机源，在服务端只抽取一次，取消发生在武器耐久、伤害和命中附魔之前。

无法穿甲覆盖四个人形护甲槽（包括放在头部的南瓜和头颅），拦截槽位操作、右键装备和发射器装备，并在服务端 tick 清除其他模组直接写入的护甲。它不禁止副手物品。笨拙同时接入品质合成、材料维修资格和收费路径，继续沿用现有品质选择体验与经验不足禁止制造规则。

## 发现、提示与解除

生效时显示诅咒通知。最初显示“效果未知”，玩家实际触发效果后才显示名称与说明；不在生效瞬间公开随机结果。发现状态保存到世界并同步玩家，首次发现的法术粒子不在重进后重复。原作 `uf.java:2140-2163`、`js.java:1449-1468`、`bcw.java:1126-1140`、`axp.java:62-80,151-161`。

诅咒没有自动过期时间。击杀施咒女巫，解除该女巫施加的全部待生效和已生效诅咒；喝祛魔之瓶解除自己的诅咒，返回空瓶，保留其原有清除状态效果行为。牛奶只清除普通状态效果，不解除独立的女巫诅咒。原作 `tv.java:293-298`、`js.java:1396-1418`、`ItemBottleOfDisenchanting.java:14-34`。现代死亡解除接在已通过可取消死亡事件的 `LivingEntity.die` 尾部，死亡被其他模组取消时不误解咒。

女巫不因远离玩家自然消失，原作 `tv.java:256-259` 的自然消失许可恒为 false；基类校验见 `og.java:608-641`。卸载区块仍可正常保存女巫，诅咒不会因此丢失。现代通过 `MobDespawnEvent` 阻止自然消失，没有定期扫描全世界女巫。

## 独立验收依据

- 确定性选择：女巫种子为 0 时，`NingMeng123 → 5`、`Steve → 15`、`Alex → 13`；种子 `Integer.MAX_VALUE` 配 `NingMeng123 → 3`，覆盖先溢出再扩展的行为。
- 实体 NBT：保存并加载女巫后种子不变；读取种子不消耗 AI 的实体随机序列。
- 候选筛选：石墙遮挡、创造玩家不消费 25% 掷骰；合法可见的生存玩家通过真实目标 Goal 触发施咒。Java 随机种子 0 的首个 `nextInt(4)` 为 2，4096 为 0。
- 生命周期：重复施咒不覆盖现有记录；6000 tick 边界、离线、重登、死亡、换维度、服务器存档重载、女巫区块卸载均按全局记录维持。
- 解除：女巫正常死亡解除，取消死亡不解除；祛魔之瓶能清除禁饮诅咒且不复制瓶子；牛奶不解除。
- 效果：每类分别测试拒绝与允许边界，尤其 90 点空气、75% 恐惧、末影人 1/3、笨拙×2与25 tick下限、植物×0.2/0.4、四护甲槽及末影箱豁免。

测试实现位于 `WitchCursingTest`、`WitchCursingGameTests` 及其余诅咒效果、保存同步测试中；运行结果由实际测试日志记录，本文件不将未执行的测试标记为通过。
