# R196 结构候选分布来源与现代适配

开发署名：NingMeng123。原作：Avernite。基准及各 class 校验值见 [结构分布数据](../spec/structure-distribution.json)。此文仅记录本批候选坐标部分，运行与手测结果由本批总验收文档记录。

主世界继续使用 1.21.1 的地形、洞穴、完整高度、生物群系和建筑模板。候选位置按以下来源调整；村庄日期、制作进度和神庙出生点距离由结构生成入口独立校验。

| 内容 | R196 来源事实 | 现代接入 |
| --- | --- | --- |
| 村庄分布 | `aiw.java:13–14,50–65`：spacing 40、separation 20、salt 10387312 | 保留五种现代村庄与其群系，仅修改原版结构集候选间隔 |
| 神庙、女巫小屋 | `ahh.java:12–13,36–59`：共享 spacing 40、separation 20、salt 14357617 | 三个现代结构集使用相同候选网格，仍由各自群系与距离条件筛选 |
| 矿井 | `agg.java:26–33`：0.5% 抽样、丘陵群系、`nextInt(80)<max(abs(chunkX),abs(chunkZ))` | 纯规则 helper 完成源频率及距离抽样；结构集频率设为 1，避免现代独立抽样再次乘 0.5% |
| 要塞 | `ahq.java:13–23,46–75`：3 座，默认距离参数 512 区块，实际半径 `(1.25+nextDouble())*512`，角间隔 120° | 仅 `minecraft:strongholds` 使用局部候选 Mixin；建筑、实际生成高度、末地入口沿用现代 |

已用 `javap -c -p` 核对 `agg.a` 的 `0.005F`、`canHaveMineshafts` 及严格小于比较，`ahq` 两构造函数的 `32*16` 和三项数组，以及 `ahi` 的 2000 格比较。`agg.e=0.01` 与其配置读取虽然存在，但实际候选方法没有读取该字段，不能误用 1%。

矿井的随机数种子也追踪到实际调用链：`aer.java:17–27` 先以世界种子取两次 `nextLong()`，再用 `chunkX*xMultiplier ^ chunkZ*zMultiplier ^ worldSeed` 重设候选种子。R196 压缩包没有覆盖 `ain`，官方 1.6.4 的 `ain.a(World,int,int,int,int,byte[])` 字节码 offset 26–33 在调用具体结构候选判定前先丢弃一次 `nextInt()`。随后才是 `agg` 的 `nextFloat()`、群系条件和 `nextInt(80)`。本批 helper 完整执行此链，结构集不再自行抽概率。

要塞环中心是坐标原点，而非世界出生点。未调整群系前，半径约 10240～18432 格；优选群系搜索可再移动至周围 112 格内的四格网格。现代默认公式为 `4*d+(random-.5)*d*2.5`，只修改结构集 `distance=512` 会得到错误距离。本批结构集中的 512 仅描述源参数，运行时必须同时使用 `StrongholdDistributionMixin`。

要塞随机数顺序也来自源代码：先取初始角，再取第一半径，随后群系搜索消耗同一随机源，再取第二半径。`acv.java:140–159` 在 X 内层、Z 外层遍历包含边界的 57×57 个 quart 坐标；计数器只在实际选中一个位置时增加，与现代搜索计数方式不同。本批保持这个行为，在单个后台任务中依序计算三座候选，不为每个候选 `fork()` 随机数。群系内容仍取现代 `BiomeSource` 的 Y=0 采样与现代优选群系标签，不复刻旧版 GenLayer 地图。

现代矿井丘陵映射使用 `minecraft:is_hill`、`minecraft:is_mountain`、grove、windswept_savanna、savanna_plateau；另外保留 `minecraft:is_badlands`，让 1.21.1 的恶地矿井仍可在新门槛下出现。此项属于明确的现代内容扩展；不会因地下洞穴群系、普通平原、海洋、河流、森林或沙漠本身而放宽丘陵条件。只采样区块角对应的现代基础地表群系，不加载实际区块。旧版与新版地形、群系内容仍然不同，不承诺旧版同种子地图一致。

下界要塞的旧版候选算法与官方 1.6.4 语义一致，本批保留现代下界布局。已完成的地下世界试炼密室、怪物房、刷怪映射，以及后续版本新增的其它现代结构也继续保留。已生成的区块不回填新的村庄或重新搬迁既有建筑。
