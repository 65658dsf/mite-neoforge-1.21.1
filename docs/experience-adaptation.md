# 经验曲线、死亡与现代接口适配

开发者：NingMeng123。原始依据见 [R196 玩家规格](r196-player-rules.md) 的字节码修正记录。

## 当前独立功能

正等级使用 R196 累计曲线 `T(L)=5L²+15L`，下一等级需求为 `20+10L`。**按用户在 017 批次中的明确要求，移除 200 级封顶，200 级之后继续同一公式升级。** 0–199 级及负等级行为保持不变。关键累计值：1 级 20、2 级 50、5 级 200、10 级 650、35 级 6650、200 级 203000、201 级 205020、312 级 491400、403 级 818090。

`Player.totalExperience` 在本模组中代表当前累计经验，等级和进度从它产生。正经验、直接设置等级、设置级内点数、等级消耗均同时维护三字段；不会每 tick 用原版未扣除成本的历史总经验把等级补回来。

没有另设游戏等级上限；负经验仍最低 −800 点。负经验等级为 `max(floor(XP/20),-40)`，每 20 点恢复一级：−1 点是 −1 级、进度 19/20，−21 点是 −2 级、进度 19/20。经验球先按现代规则修补装备，剩余经验抵扣负经验。保留现代原生 `int` 总经验存储，使用 `long` 中间运算防止溢出；技术存储边界及其影响见下文。

普通死亡时，死亡前经验不足 20 点则重生经验为 `max(XP-20,-800)`，否则重生为 0。死亡时只记录待重生值，真正重生时应用一次；保留背包、旁观者和非死亡复制沿用现代保留规则。原 R196 的高经验分支不写待重生字段，依赖每个新玩家的初值 0；现代实现显式记录 0，避免残留状态。

## 现代行为的明确选择

| 入口 | 行为 |
| --- | --- |
| 经验球、命令加减点数 | 对整数总经验加减，使用宽整数计算避免溢出，跨级更新生命/食物的既有等级来源 |
| `/experience query ... points` | 返回当前等级内的整数点数，不是累计总数；不用浮点进度反算 |
| 设置级内 points | 限制在当前等级的合法级内区间 |
| 添加/设置 levels | 保留进度比例，用 `oldPoints * newCost / oldCost` 的整数除法计算新级内点数 |
| 附魔台、铁砧 | 保留现代设备的等级成本与物品规则；扣级经过统一经验入口，累计数同步减少 |
| 经验修补 | 保留新版经验球先维修、余量再进入玩家经验的顺序；本功能不更改维修效率 |
| 200 级及以上 | 继续升级：200→201 需要 2020 点，201→202 需要 2030 点；经验条、点数查询、等级加减、工具品质扣费使用相同累计模型 |
| 设置超过 200 级 | 正常接受可表示的等级；只有所需总经验超出原生整数存储时才报错，不把截断后的结果宣称为设置成功 |
| 等级采集加成 | 原公式 `1+L*.02F` 在 200 级后继续增加，已去掉 `MiningRules` 的 200 级裁剪；最低仍按 −40 级计算 |
| 负等级命令 | `/experience add ... -N points/levels` 支持减到负值；原版 `set` 命令仍只接收非负参数，设置当前等级内点数也适用于负等级 |
| 创造/旁观 | 内部三字段仍保留同一有符号经验，避免切模式清除债务；HUD 按新版隐藏。旧 R196 创造模式的等级查询把负等级显示为 0，此处是现代适配 |
| 负等级 HUD | 显示原 R196 的红色 `#FF1313` 数字；经验条使用新版普通绿色材质，0 级不显示数字；隐藏 HUD 和乘骑跳跃条仍优先 |
| 死亡经验掉落 | 正累计经验的三分之一，整数截断，不设原版 100 点上限；负经验、保留背包、旁观及关闭 doMobLoot 时为 0 |

### 原版证据与本次变更边界

R196 的 `uf.getHighestPossibleLevel:520` 返回 200，`uf.getExperienceRequired:524` 在超过 200 时返回 `Integer.MAX_VALUE`；但 `uf.addExperience:1646-1648` 只对总经验做 −800 下限保护，并未在 203000 封顶。原始字节码 `addExperience` 偏移 89–117 确认直接 `iadd` 后只检查下限。因此，203000 原本只是达到 200 级的起点，旧 R196 能保持 200 级并继续积累高品质制造费用。此前本工程把它用作总经验硬上限，阻断了例如传奇艾德曼镐 491840 XP、传奇艾德曼战锤 819520 XP，这个限制现已移除。

用户进一步指定**等级也继续提升**，因此本次不仅放开余额，还把曲线延伸到 201 级及以上。这部分是明确的现代适配，不声称原 R196 自己会升到 201 级。原先 `Integer.MAX_VALUE` 阈值引发的无界等级扫描不再使用，等级通过安全二分求得。

为兼容现有 Minecraft 存档、经验网络包、命令与其他模组，本批仍使用原生 `int` 总经验，最大可存储为 **2147483647 点**。它按曲线自然对应 **20722 级、级内 166397/207240 点**；这是整数容量的技术边界，不是新增的游戏等级配置。加点采用 `long` 后夹到存储范围，避免变成负经验；命令显式设置无法表示的等级或级内点数会报错。未来若需要越过这个存储范围，必须一并升级权威总经验、网络、死亡掉落和跨模组接口，本批没有引入不完整的 long 旁路。

独立验收值：491840 总经验应为 **312 级、440/3140**；819520 应为 **403 级、1430/4050**；从 819520 扣 491840 后为 327680，即 **254 级、1290/2560**。免费配方不会因为玩家超过 200 级额外收费；高品质费用仍是实际经验点。现代附魔/铁砧的整级消耗继续沿用原有进度比例规则。

## 事件、保存与同步

点数入口先发送 NeoForge `XpChange`，若跨级再发送一次聚合的 `LevelChange`；等级入口发送 `LevelChange`。取消时保持三字段不变，修改事件数值后重新计算一致的结果；跨多级采用一次聚合事件属于现代适配，不模拟原版逐级循环。原版直接 setter 不发送这些事件，本模组保持此语义。取消经验事件不代表取消整笔附魔或铁砧物品操作。

保存继续使用原版 `XpTotal`、`XpLevel`、`XpP`，当前写入 `mite_experience_version=3`。版本 1、2 已经是整数累计模型，升级时直接读取总经验，按延伸曲线重算等级与进度，不重新用浮点进度转换；旧版曾经丢弃的超额经验无法从现有存档恢复。无标记旧存档按已显示的等级与进度比例迁移。客户端接收现有经验数据包，保留全部整数总数；负数和高正数均可用原版 VarInt 编解码，服务端脏标仍为合法经验范围外的 `Integer.MIN_VALUE`。

真正死亡后，服务端在 `mite:respawn_experience` Data Attachment 中保存版本化的待重生快照；取消死亡不会记录。死亡期间正常保存退出时该快照随玩家保存，读取时不扣款。`PlayerEvent.Clone` 在首次复活经验包之前应用快照，新玩家不保留待处理状态；旧版本已死亡但没有快照的玩家，按其保存的原经验补算。重生状态恢复不发送普通经验获得事件，以免经验奖励拦截器取消死亡惩罚。

死亡球的归属、寿命、合并和延迟掉落详见 [死亡经验球适配](death-orb-adaptation.md)。原作复活倒计时、复活保护、等级对战斗与采集的影响、营养继承仍另行验收。正常保存重登保证不等于进程崩溃或存档写入失败后的防回滚。

实际验证状态与证据另记于逐功能测试记录；本设计文档本身不是测试通过证明。
