# 经验曲线、死亡与现代接口适配

开发者：NingMeng123。原始依据见 [R196 玩家规格](r196-player-rules.md) 的字节码修正记录。

## 当前独立功能

正等级 0–200 使用 R196 累计曲线 `T(L)=5L²+15L`，0–199 级的下一等级需求为 `20+10L`。关键累计值：1 级 20、2 级 50、5 级 200、10 级 650、35 级 6650、200 级 203000。

`Player.totalExperience` 在本模组中代表当前累计经验，等级和进度从它产生。正经验、直接设置等级、设置级内点数、等级消耗均同时维护三字段；不会每 tick 用原版未扣除成本的历史总经验把等级补回来。

运行范围为 −40–200 级、−800–203000 点经验。负经验等级为 `max(floor(XP/20),-40)`，每 20 点恢复一级：−1 点是 −1 级、进度 19/20，−21 点是 −2 级、进度 19/20。经验球先按现代规则修补装备，剩余经验抵扣负经验。

普通死亡时，死亡前经验不足 20 点则重生经验为 `max(XP-20,-800)`，否则重生为 0。死亡时只记录待重生值，真正重生时应用一次；保留背包、旁观者和非死亡复制沿用现代保留规则。原 R196 的高经验分支不写待重生字段，依赖每个新玩家的初值 0；现代实现显式记录 0，避免残留状态。

## 现代行为的明确选择

| 入口 | 行为 |
| --- | --- |
| 经验球、命令加减点数 | 对整数总经验加减，使用宽整数计算避免溢出，跨级更新生命/食物的既有等级来源 |
| `/experience query ... points` | 返回当前等级内的整数点数，不是累计总数；不用浮点进度反算 |
| 设置级内 points | 限制在当前等级的合法级内区间 |
| 添加/设置 levels | 保留进度比例，用 `oldPoints * newCost / oldCost` 的整数除法计算新级内点数 |
| 附魔台、铁砧 | 保留现代设备的等级成本与物品规则；扣级经过统一经验入口，累计数同步减少 |
| 经验修补 | 保留新版经验球先维修、余量再进入玩家经验的顺序；本功能不更改维修效率 |
| 200 级 | 正经验硬封顶 203000，进度为 0；安全的下一等级跨度返回 1，使原版调用不会除零；命令设置正级内点数被拒绝 |
| 设置超过 200 级 | 命令明确报错，不把截断后的结果宣称为设置成功 |
| 负等级命令 | `/experience add ... -N points/levels` 支持减到负值；原版 `set` 命令仍只接收非负参数，设置当前等级内点数也适用于负等级 |
| 创造/旁观 | 内部三字段仍保留同一有符号经验，避免切模式清除债务；HUD 按新版隐藏。旧 R196 创造模式的等级查询把负等级显示为 0，此处是现代适配 |
| 负等级 HUD | 显示原 R196 的红色 `#FF1313` 数字；经验条使用新版普通绿色材质，0 级不显示数字；隐藏 HUD 和乘骑跳跃条仍优先 |
| 死亡经验掉落 | 正累计经验的三分之一，整数截断，不设原版 100 点上限；负经验、保留背包、旁观及关闭 doMobLoot 时为 0 |

203000 的硬封顶是现代安全适配。旧 R196 在 200 级后以 `Integer.MAX_VALUE` 作下一阈值；总经验恰好达到该值会使原版等级扫描无法终止，并且原版经验加法可能溢出。这里不照搬这些异常行为。

## 事件、保存与同步

点数入口先发送 NeoForge `XpChange`，若跨级再发送一次聚合的 `LevelChange`；等级入口发送 `LevelChange`。取消时保持三字段不变，修改事件数值后重新计算一致的结果；跨多级采用一次聚合事件属于现代适配，不模拟原版逐级循环。原版直接 setter 不发送这些事件，本模组保持此语义。取消经验事件不代表取消整笔附魔或铁砧物品操作。

保存继续使用原版 `XpTotal`、`XpLevel`、`XpP`，当前写入 `mite_experience_version=2`。版本 1 已经是整数累计模型，升级时直接读取总经验，不重新用浮点进度转换。无标记旧存档按已显示的等级与进度比例迁移。客户端接收现有经验数据包；负数可用原版 VarInt 编解码，服务端脏标改用合法经验范围外的 `Integer.MIN_VALUE`，避免总经验 −1 与原版脏标相等而漏发。

真正死亡后，服务端在 `mite:respawn_experience` Data Attachment 中保存版本化的待重生快照；取消死亡不会记录。死亡期间正常保存退出时该快照随玩家保存，读取时不扣款。`PlayerEvent.Clone` 在首次复活经验包之前应用快照，新玩家不保留待处理状态；旧版本已死亡但没有快照的玩家，按其保存的原经验补算。重生状态恢复不发送普通经验获得事件，以免经验奖励拦截器取消死亡惩罚。

死亡球的归属、寿命、合并和延迟掉落详见 [死亡经验球适配](death-orb-adaptation.md)。原作复活倒计时、复活保护、等级对战斗与采集的影响、营养继承仍另行验收。正常保存重登保证不等于进程崩溃或存档写入失败后的防回滚。

实际验证状态与证据另记于逐功能测试记录；本设计文档本身不是测试通过证明。
