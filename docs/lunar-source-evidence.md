## 日历与昼夜

`aei.a(long)` 的相位为 `(unadjustedTick / 24000 + 1) % 8`；相位 0 是满月，相位 4 是新月。原始月亮亮度数组为 `[1, .75, .5, .25, 0, .25, .5, .75]`。新世界 tick 0 是相位 1，第一次普通满月是第 8 个未调整日；这与 1.21.1 默认月相相差一天。

特殊月相检查使用未调整总时钟 `abw.I()`；不能先加 6000 再计算特殊日。令 `D = unadjustedTick / 24000 + 1`：

| 名称 | 条件 | 初次及后续示例 | 特殊规则优先级 |
| --- | --- | --- | --- |
| 血月 | `D % 32 == 0 && D % 128 != 0` | 32、64、96、160 | 第 128 天由蓝月替代 |
| 蓝月 | `D % 128 == 0` | 128、256 | 覆盖同日血月 |
| 黄月／收获月 | 在 `unadjustedTick + 192000` 检查血月 | 24、56、88、152 | 第 120 天不算收获月 |
| 月晕／Moon Dog | 在 `unadjustedTick + 192000` 检查蓝月 | 120、248 | 是独立的月环视觉，不是额外血月 |

`getDayOfWorld()` 的文字日期却使用 `(unadjustedTick + 6000) / 24000 + 1`，天气每日窗口也从未调整 tick `-6000` 开始。这里存在两个明确不同的日边界，不能将同一个日期整数套在全部系统上。

昼夜判断 `adjusted = (localTick + 6000) % 24000`，仅 `5000 < adjusted < 19000` 是白天。对非负时钟，未调整 `localTick` 在 `[13000, 23000]` 是夜间，其余是白天；13000 和 23000 本身都属于夜间。不能用原版 `isNight()` 或 `>= 12000` 替代。月升系数在调整时刻不大于 5000 时为 `1 - adjusted/5000`，不小于 19000 时为 `(adjusted-19000)/5000`，其余为 0。

世界实例的血月和蓝月判定先检查主世界。`updateTickFlags()` 也只在主世界调用 `updateMoonFlags()`，因此实际客户端、气候和作物所读的 `*24HourPeriod/Day/Night` 标志均只在主世界生效。收获月、Moon Dog 的直接实例包装方法没有显式维度检查，这是来源的区别；已找到的实际效果均读主世界缓存标志或主世界天空路径，不能据此让下界和地底世界获得特殊天空与天气。

## 月亮、月环与夜间光线

`bfl.a(float)` 使用当日相位选择月亮图格，并按以下 RGB 乘色；太阳保留白色。

| 月相 | 月面 RGB | 额外叠加 |
| --- | --- | --- |
| 血月 | `.6, .2, .1` | `halo_256.png`，半宽 160，红色，基础透明度 `.25 * (1-rain)` |
| 收获月 | `1, .8, .45` | 无额外月环 |
| 蓝月 | `.66, .74, 1` | `halo_256.png`，半宽 160，RGB `.33, .37, .8`，同上透明度 |
| Moon Dog | 普通白色月面 | `ring_128.png`，半宽 80，RGB `.4975, .6275, .85` |

普通月面半宽 20，因此血／蓝色光晕为其 8 倍，Moon Dog 月环为其 4 倍。血／蓝光晕在天球角 `.77` 后线性淡出，到 `.785` 为零；原代码之后可能提交负 alpha，现代实现应明确钳制到零。Moon Dog 透明度为 `.5 * (1-rain)`，天球角 `.18` 至 `.28` 淡入、`.28` 至 `.6` 保持、`.6` 至 `.785` 淡出，其余不显示。

`abw.getMoonBrightness` 的全天月光倍率：血月 `.6`，收获月 `1`，蓝月 `1.1`，其余为 `phaseBrightness * .5 + .75`。当倍率大于 `.75` 且降雨强度为 `R > 0` 时，结果为 `brightness*(1-R) + .75*R`。它是客户端月光倍率，不是修改服务器的方块天光数据，也不是怪物生成所用的基础相位亮度数组。

`bfe.h(float)` 在主世界使用 `M = clamp(moonAscension,0,.2)*5` 将天空光分量乘以 `lerp(1, moonBrightness, M)`。随后在最终光线 RGB 上叠加特殊夜色；令 `A=clamp(1 - blockLight/15*2,0,1)`、`S=skyLight/15`、`C=clamp(moonAscension,0,.2)*S*A`：

- 血月：红乘 `1+5*C`，绿乘 `1+2*C`，蓝不变。
- 收获月：红乘 `1+2.4*C`，绿乘 `1+1.6*C`，蓝乘 `1-.8*C`。
- 蓝月：蓝乘 `1+1.25*C`，绿乘 `1+.5*C`，红不变。

火把等方块光越强，染色越弱；没有天光的地下不该被整体染色。Moon Dog 没有专属月光 RGB。现代光照、暗视、gamma 与 shader 路径不同，应保留上述独立倍率和衰减规则，并明确兼容边界，不把客户端色调误称为服务器亮度修改。

## 天气、沙漠与雷击

`abw.generateWeatherEvents(int day)` 每日原点为 `(day-1)*24000-6000`，第一天不产生天气。普通候选降雨开始于该窗口内任意刻，持续 `6000..17999` 刻。若候选开始或结束在血月全天／蓝月全天，或开始、结束、开始加 6000、结束减 6000 任一点是收获月夜晚，则拒绝该普通候选。

若该日未调整 0 刻属于血月，额外加入从未调整 0 刻开始、持续 13000 刻、全程雷暴的天气事件：**基础事件区间是 `[0,13000)`，不是整夜血月雷雨**。实际天气列表还会合并间隔不超过 6000 刻的事件，并配置随机风及其他雷暴；切勿把“强制血月事件”与合并后的所有雨区间混为一谈。蓝月全天及收获月夜晚没有新普通降雨事件，但不等价于删除所有跨窗口或管理员设置的天气。

`WeatherEvent` 的发生和雷暴区间均左闭右开；`hasStorm()` 检查开始雷暴时刻大于 0。雨、雷强度每刻以 `.01` 渐变；`isPrecipitating(true)` 用雨强度 `>.2`，`isThundering(true)` 用雷强度与雨强度乘积 `>.9`，不是只读天气布尔标志。

血月全天将原本降雨量为零的生物群系纳入下雨、阴天、客户端雨幕及淋湿检测。冻结生物群系仍按雪处理；`acq.canSpawnLightningBolt(blood)` 为 `!snowEnabled && (rainEnabled || blood)`，不应让纯雪气候落雨雷击。`js.g()` 每个活动区块的雷击尝试几率为血月 `1/20000`，通常 `1/100000`，仍要求当前实际降水、雷暴及落点合格。`tm.isValidLightLevel` 和 `nn.d(float)` 的沙漠忽略雨雷亮度例外也在血月全天关闭。

## 睡眠、怪物与动物

- `js.b()` 以血月**全天**阻止睡眠快进，并轻唤醒已经躺下的玩家；原实现不是只在血月深夜禁止入睡。原本普通睡眠开始时刻、所有玩家条件和比赛模式属于独立系统，不据此扩大本次月相变更。
- `tm.isFrenzied()` 仅血月夜晚为真；近战增加未修饰基础攻击的 50%，相关 AI 加快。末影人 `tg.isFrenzied()` 明确恒 false。骷髅领主额外狂暴是独立来源，不能与血月重复乘算。
- `aci.setEligibleChunksForSpawning()` 主世界怪物附近密度下限通常 8；夜间普通满月 10、血月 12。实际密度仍受深度、要塞接近度等规则影响。
- `aci.trySpawningHostileMobs()` 夜间户外生成保留概率：普通 `1/4`、新月 `1/6`、满月 `1/3`、血月 `1/2`、蓝月 `1/54`。蓝月夜晚眼部位置存储天光大于 0 时直接拒绝怪物；这不清除已存在怪物，也不禁止完全遮光地下生成。
- `js.getSuitableCreature()` 血月夜晚放开尸鬼、吸血蝙蝠、怨魂、夜翼、骷髅领主的主世界地表深度限制；亡魂 `EntityWight` 另要求冻结气候，暗影另要求沙漠。其他深层怪物不因血月统一登上地表。
- `aci.calcEffectiveHostileMobSpawningRateModifier()` 血月全天或雷暴时，随机生成率低谷／暂停被提高到至少 1。它不是将正常生成率固定加倍。
- `aci.performRandomLivingEntitySpawning()` 蓝月夜间每 400 刻可以进行动物生成；`trySpawningPeacefulMobs` 对这批动物跳过通常光照检查。仍受动物上限、玩家与出生点距离、地面及碰撞等条件约束。
- `EntityCubic.getCanSpawnHere()` 沼泽立方怪采用基础相位数组，而非特殊月光倍率：满月概率更高，新月的该条路径为零。
- `sf.l_()` 未驯服狼在血月夜间会被标记为对玩家敌对，已有攻击目标倒计时、受伤复仇和女巫伙伴为独立条件。蓝月不让狼忽略已经建立的复仇目标。
- `EntityDireWolf.l_()` 蓝月夜间不执行每刻 `.004`、4 格内玩家的额外主动攻击；`EntityDireWolf.r()` 也不执行其额外随机／近人低吼。这两个额外分支还排除幼年、已驯服和繁殖中的巨狼：`bY()` 从 `sf→oq→rp` 继承，是 `rp.bp>0` 的求偶状态，不是愤怒状态。不是所有狼都永久转为友好，来源也没有为这两个分支额外检查 `isAngry()`。
- `sf.onEntityRightClicked()` 负面的驯服失败在蓝月夜间不引发该次反击；仍消耗骨头并保留失败与冷却，不会保证驯服成功。
- `sc.preysUpon()` 蓝月夜间拒绝猎物；`sc.bl()` 在原 AI 更新路径中清空已有猎物引用。玩家与鱿鱼的独立接触路径没有蓝月特判，不能概括成蓝月鱿鱼绝不伤人。

## 农作物与钓鱼

`anr.updateTick()` 在旱死和已经染病的分支之后、通常的环境病害与生长判断之前，执行血月夜间强化感染：健康作物、随机浮点 `<.25`、**非专用服务器**、`!hasStandardFormOpaqueBlockAbove || isOutdoors`，成功设置枯萎位即结束本次随机刻。`MinecraftServer.V()` 已核对：专用服务器 `is.V()` 返回 true，集成服务器 `bkz.V()` 返回 false；不能误读成“玩家不是创造模式”。是否保留这项旧单人／专服差异必须在移植文档单列。

直接来源作物为小麦 `anr`、胡萝卜 `ani`、马铃薯 `apt`、洋葱 `BlockOnion`。不是所有现代植物都自动受影响；甜菜等现代内容需要明确适配。来源条件不要求能直接看见天空：没有标准完整不透明屋顶，或能沿通路判为室外，任一成立即可感染。单独盖玻璃／树叶不等同于密封实心房间。

已染病作物每次随机刻先有 `1/64` 变为枯死；成熟作物死前退一生长级；否则约一半机会选择周边 `[-1,1]^3` 的一个非零坐标并传染活的 `anr`。骨粉只治病，不恢复已死作物。普通染病作物不掉收获物；**马铃薯 `apt` 覆盖掉落，染病或未成熟时掉毒马铃薯**，不得被通用清空掉落规则吞掉。环境基础病害和旱死不是月相专有效果；收获月没有加速作物生长或额外产量的命名调用链。

`ul.checkForBite()` 在蓝月夜间将有效咬钩概率分母设为 600，其他时段依据距调整 5500／17500 的时间差计算，钳制 `600..2400`。随后才叠加淋雨减半、启用技能且未掌握钓鱼则加倍、每级钓鱼幸运乘 `9/10`、快捷栏生蚯蚓减半。它不跳过水体几何检查、不保证即刻咬钩，也不提高所有战利品等级。技能是否启用必须继承已有真实开关。

## 基线缺口与验收边界

在本次核对前，`R196SpawnRules`、`R196MobSpawning` 已包含生成用日历、血／蓝月主要生成规则；`R196MonsterAi`、`NativeAnimalSpecial032`、`SourceAquatic032`、`R196Wolf` 已包含大部分血月狂暴和蓝月动物逻辑。需要统一日历入口，避免已有系统各自推导导致边界不一致。

明确缺口包括：客户端普通相位差一天；收获月、Moon Dog、月色和月光无接入；特殊天气和血月沙漠雨雷、睡眠限制、血月强化作物感染无接入；钓鱼蓝月判断曾使用 `local>=12000`，与真实夜间 `[13000,23000]` 不一致。已有病害共享代码对原版作物和洋葱采用不同状态，新增月相感染必须复用对应状态并保留死亡、治疗与掉落逻辑。巨狼原有代码已有蓝月随机攻击限制，但来源额外低吼未接入，不能仅因一个蓝月条件存在就认定完全覆盖。

另一个真实差异是 `R196AnimalAi032.potentialPredator()` 的鱿鱼分支此前用蓝月全天判断，导致蓝月白天牲畜也不再怕鱿鱼；来源的 `sc.preysUpon()` 只在蓝月夜晚关闭，应复用同一个蓝月夜间入口。已有 `SourceAquatic032.SquidSwim` 的清目标、玩家独立接触、狼驯服失败不反击均按夜间接线。原版史莱姆自然生成已由 `R196MobSpawning` 接管，资格判断读取 `fractions[moon.phase()]`，无需把特殊月光倍率再套到史莱姆概率。

基础验收至少包含特殊日 24／32／120／128 与相邻日、13000／23000 两个夜间端点及前后 1 刻、蓝月排除血月、月晕排除黄月、非主世界排除、保存重载和跨日、天气区间末端与沙漠／雪地、血月床与在床玩家、遮光地下不染色及火把衰减、健康／染病／死亡农作物和专服分支、钓鱼边界，以及已有生成／狼／狂暴／鱿鱼的回归。客户端画面由用户手测，服务端测试不能替代真实天空、光影或双客户端观察。
