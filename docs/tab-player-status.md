# Tab 玩家等级与延迟

开发者：NingMeng123。日期：2026-10-22。

## 显示规则

按用户要求新增的现代显示功能。按住 Tab，在在线玩家姓名后显示实际经验等级和数字延迟，例如 `NingMeng123  等级 35  42 ms`。英文界面为 `Lv. 35`。

- 等级读取服务端 `experienceLevel`，包括 0 级、负等级及超过 200 级的实际等级；负等级显示红色，其余显示绿色。
- 延迟读取该玩家连接的原生测量值，单位为毫秒；小于 150 ms 为绿色，150–299 ms 为黄色，300 ms 及以上为红色。尚无有效测量值时显示灰色 `-- ms`。
- 首次加入通过原生玩家列表初始化包同步；此后每 20 个服务端 tick 检查一次，只有名称、等级或延迟等显示内容变化时才广播更新。原生连接测量本身有采样间隔，因此每秒检查不等于每秒发起网络测速。
- 全服广播覆盖不同维度及远处玩家，也覆盖创造与旁观模式；退出与重生使用原生玩家列表生命周期，无额外客户端状态缓存。
- 保留队伍前后缀、颜色及其他模组在此前事件优先级设置的自定义列表名称，保留原生头像、排序、旁观斜体、计分板和延迟图标。原生图标刷新频率可能与数字短暂不同。

使用 NeoForge `PlayerEvent.TabListNameFormat` 和 `ServerPlayer.refreshTabListName()`，不增加自定义网络协议或客户端渲染替换。列表布局及原生最多显示 80 人的限制沿用 Minecraft 1.21.1。

## 游戏内复测

1. 服务端更新模组并重新启动；连接后按住 Tab，确认每位在线玩家都有等级及 `ms` 延迟。
2. 使用有权限的命令 `/experience set <玩家名> 35 levels`，确认约 1 秒内更新为 35；再设置 312 级，确认显示实际等级 312。
3. 用测试玩家将经验降为负值，确认列表中的负等级带负号并显示红色；恢复经验后同步恢复。
4. 让另一玩家进入下界或地底，确认双方仍能查看对方等级和延迟；让对方退出重进、死亡重生，确认列表无旧数据或重复后缀。
5. 若使用队伍前后缀或列表昵称，确认姓名格式仍正常，等级和延迟各显示一次。

本功能使用服务端生成列表文字；客户端语言资源随本次模组包提供。最终画面与真实双客户端联机需游戏内验收。
