# 技术架构

维护者：NingMeng123。

## 目标约束

主世界继续采用 Minecraft 1.21.1 的地形生成器、生物群系、山脉和高度，不替换为旧版生成器。洞穴保留现代基础，并按[高层洞穴调整](upper-cave-generation.md)增加高层狭窄自然通道、压低局部 cheese 空腔贡献、收窄3D噪声通道和减少主世界地下含水区域；不宣称洞穴参数完全等同原版。MITE 另通过矿物配置、生物生成、结构门槛、战利品与玩法规则适配现代环境。地下世界注册为独立维度，不替换主世界生成器。

## 数据职责

| 数据 | 存储与同步 | 服务端职责 |
| --- | --- | --- |
| 玩家营养、代谢与相关状态 | 序列化 Data Attachments；显式发包同步 HUD 所需部分 | 计算与验证状态变化 |
| 装备品质和 MITE 物品属性 | Data Components | 合成、维修及耐久判定 |
| 共享成长、世界天数和事件 | 版本化 SavedData | 世界范围进度与维度规则 |
| 加工条件 | 自定义配方及材料标签 | 同一校验供手工、容器和自动化使用 |
| 世界生成 | 1.21.1 数据包配置、NeoForge biome modifiers 与定点 aquifer 注入 | 保留现代地形基础，调整资源、高层洞穴及主世界地下含水区域 |

同一逻辑在单人内置服务器和独立服务器执行。客户端不决定配方是否有效、是否消耗经验、材料是否扣除或物品是否产出。

## 模块边界

- `rules`：可独立测试的规则公式，不依赖客户端。
- `survival`：玩家事件、附加状态和生存机制。
- `content`：方块、物品、材料、生物和注册。
- `manufacturing`：配方、加工事务、容器及服务端处理。
- `world`：现代世界适配、地下世界、事件及共享进度。
- `network`：有限载荷、版本与状态同步。
- `client`：HUD、渲染和屏幕，不从专服路径引用。
- `mixin`：仅存放事件不能实现的定点修改，每个注入关联规则编号和测试。

这些模块是实施边界，不表示均已实现。

## 开发与发布

Java 21、Minecraft 1.21.1、NeoForge 21.1.259、ModDevGradle 2.0.148。构建与自动测试之外，每个功能必须启动游戏完成实测后才允许中文提交并推送。测试数据记录在 `docs/testing`，原始日志及游戏截图保留在被忽略的本地运行目录中。

开发版本仅用于新建测试世界。任何后续保存格式变更必须带版本号并验证重进和服务器重启。发布包排除参考游戏源码及二进制。
