# 第三个血月后的地底生物入侵

开发署名：NingMeng123。

这是用户明确选择的现代适配：主世界到达**第 97 天**后，永久开放地底生物的自然生成。它与严格 R196 的血月当夜放宽规则分别记录；不能把这项扩展描述成原作已有的 `day / 96` 公式。

## 来源与时间边界

R196 `js.getSuitableCreature`（反编译 466–567 行、字节码偏移 0–83 的入口条件）只读取主世界、血月当夜、冰冻群系和沙漠群系，没有第三个血月或第 96 天的门槛。前三个血月是日历第 32、64、96 天，原作在每一次血月当夜都允许部分地下生物突破深度限制。

- 尸鬼、吸血蝙蝠、怨魂、暗翼蝠、骷髅领主：血月当夜放宽选择阶段的深度限制。
- 亡魂：血月当夜的地表还要求寒冷群系。
- 暗影：血月当夜的地表还要求沙漠群系。
- 隐形潜行者、土元素、恶魔蜘蛛、相位蜘蛛、地狱犬和受深度约束的胶质生物：原作不会因为血月就全部开放地表。

旧版蝙蝠家族另有主世界 `Y < 63` 的最终生成资格，所以仅通过选择阶段并不等于能够在高处实际生成。

本次扩展从 `dayTime = 2,304,000`（第 97 天第一刻）开始。日历使用 `max(0, dayTime) / 24000 + 1`，不使用装备旧日期函数的 6,000 刻偏移。第 128 天是蓝月，不算第四次血月；该事实不会改变本次第 97 天的入侵门槛。

## 扩展行为

保留主世界当前群系的全部原有生成条目、权重、分组和顺序，再按实体类型去重追加地底池独有条目。普通主世界群系新增：

原作本来就存在的重复条目会保留。例如沼泽同时有权重 100、分组 1–4 的史莱姆条目，以及额外权重 10、单只的史莱姆条目；本次只防止追加阶段引入新的重复，不会合并这两条源规则。

| 生物 | 选择权重 | 分组数量 |
| --- | ---: | ---: |
| 洞穴蜘蛛 | 40 | 1–2 |
| 远古骷髅 | 40 | 1–2 |
| 远古骷髅领主 | 5 | 1 |

平原源怪物池的总权重从 760 变为 845。权重代表候选选择票数；光照、栖息环境、碰撞、距离、重试、数量上限和分组限制仍会影响最终生成，不能直接当作每刻实际刷出概率。

原有地下生物在解锁后可以进入地表候选。亡魂在 `Y > 48` 仍要求寒冷群系，暗影在 `Y > 32` 仍要求沙漠；二者原来的地下栖息范围不变。胶质生物的石质顶底、木蜘蛛的树木与树叶、土元素等生物的地面材质、光照、液体及碰撞规则继续执行。

吸血蝙蝠、巨型吸血蝙蝠和暗翼蝠在已解锁主世界可以通过旧 `Y < 63` 限制，但仍需要黑暗、无碰撞的实际栖息地。吸血蝙蝠沿用地底的 **1/6** 巨型替代概率；远古骷髅沿用已有的 **1/6** 守卫替代概率。

骷髅领主与远古骷髅领主可以自然生成。原有地底普通刷怪笼和试炼刷怪笼的领主替换规则保持原状。

地底世界、下界、末地与其他维度不会套用这套主世界池合并或地表深度放宽。现代新增生物继续使用原有的候选池和资格检查。

## 保存与联机

进度保存在主世界共享的 `mite_blood_moon_invasion` SavedData，包含版本号、最高到达日历天 `highest_day` 和兼容布尔字段 `unlocked`。同一天反复查询不会重复标记存档需要写入。

服务器每刻观察日期，候选池、实际选择和装备进度读取也能惰性迁移已经超过第 97 天的旧存档。最高到达天数只增加；修改天气、离开血月、死亡、重连、服务器重启或把时间调回早期，都不会撤销已经取得的解锁。其他维度的装备进度读取同一份主世界最高天数，不会另建进度。

## 手测步骤

建议使用一个新的测试存档，依次检查解锁前和解锁后；解锁后回调时间不会恢复初期状态。

1. 第三个血月当夜使用 `/time set 2293000`。原有血月生物仍可出现，但尚未永久开放完整地底池。
2. 使用 `/time set 2303999`，仍处于第 96 天最后一刻。随后执行 `/time set 2304000` 到达第 97 天，永久解锁。
3. 使用 `/time set 13000` 调回普通夜晚。在玩家 24 格外、远离世界出生点的合格黑暗区域观察。可用 `/tick rate 100` 加速观察，结束后执行 `/tick rate 20`。
4. 检查远古骷髅、守卫、洞穴蜘蛛和远古骷髅领主进入自然候选。个别生物有稀有权重，不要求一次夜晚全部出现。
5. 在寒冷群系和沙漠分别检查亡魂、暗影；在黑暗石质顶底空间检查胶质生物。暖平原不会因为解锁获得地表亡魂或暗影。
6. 保存退出、重新进入，再次调回普通夜晚，确认解锁仍存在。检查地底世界、下界原有生成和刷怪笼领主限制。

结构化来源、时间边界、权重和验收项记录于 `spec/blood-moon-invasion.json`。自动验证包含独立规则测试，以及真实生成池、选择、替代、碰撞、照明、自然生成事件、实体初始化和 NBT 回读测试。
