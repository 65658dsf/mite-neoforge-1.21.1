# R196 共享制造计时证据

开发者：NingMeng123。机器规格见 [r196-crafting-time.json](../spec/r196-crafting-time.json)，实际配方难度取自本地提取的 `reference-data/runtime-registry.json`（不随仓库分发）。依据为本地 R196 发布包、CFR 输出及 `javap -c -p` 字节码；本文为来源分析记录，实施与验收见 [016 制造计时](timed-crafting-016.md)。源码位置均相对 `.reference/r196/decompiled/`。

## 核心结论

R196 的背包与工具工作台制造有实际等待过程，最低每批 **25 个游戏 tick**。计时受品质、等级、工作台和笨拙诅咒影响；食物能量为空会暂停，受伤会倒退进度。职业默认关闭，但品质仍启用。现有现代即时合成不能据此视为完整制造复刻。

旧版计时由客户端推进，服务端完成信号没有重算等待时间和品质经验成本。现代移植需要保留已核实的玩家可见规则，补上服务端权威计时、材料及取出校验；不能复制旧客户端信任方式。

## 难度到周期

`RecipeHelper.java:5–54` 按组件顺序用 `float` 累加 `getCraftingDifficultyAsComponent`，配方还可显式覆盖或缩放难度。`aai.java:119–131`、`aaj.java:69–91` 将配方难度传给 `CraftingResult`。这是**整批配方难度**：一次出四个物品，不代表周期要再除以四。动态配方和修复另有结果难度，不能只根据输出物品 ID 决定周期。

先按品质得到 `D`：普通或更差、以及无品质的结果使用基础难度；精良、优秀、卓越、杰作、传奇分别将基础难度乘 2、4、8、16、32。源码实际逐次执行 `float * 2F`；`quality_override` 非空时优先使用覆盖品质。依据 `CraftingResult.java:29–46`、`EnumQuality.java:6–14`。

基础周期 `U`（`bex.java:450–458`）为：

```java
if (D < 25F) U = 25;
else if (D > 100F)
    U = (int)Math.round(Math.pow((double)(D - 100F), (double)0.8F)) + 100;
else U = Math.round(D);
```

字节码确认先 `fsub`、再 `f2d`；指数是 `0.8F` 转 double，实际为 `0.800000011920929`。高难度分支先 `Math.round(double)` 得 long，再转 int 并加 100。不能直接写成全 double 的 `pow(D-100,0.8)` 来宣称位级一致。

最终周期（`bex.java:497–503`、`uf.java:558–566`）为：

```java
if (clumsiness) U *= 2;
period = (int)Math.max((float)U / ((1F + (float)level * 0.02F) + benchModifier), 25F);
```

诅咒先按 int 翻倍，分母两次 float 加法，再 float 除法，最后截断成 int；不是向上取整。制造等级加成没有职业门控。函数自身不夹等级，正常范围由经验系统管理；当前现代经验范围为负 40 至 200。

| 条件 | 工作台修正 |
| --- | ---: |
| 非 `vl` 工具工作台，包括背包 | 0 |
| 工具工作台，但配方没有工作台材料门槛 | 0.2 |
| 有材料门槛，台工具为燧石或黑曜石 | 0.2 |
| 有材料门槛，台工具为铜、银、金 | 0.3 |
| 有材料门槛，台工具为铁 | 0.4 |
| 有材料门槛，台工具为远古金属 | 0.5 |
| 有材料门槛，台工具为秘银 | 0.6 |
| 有材料门槛，台工具为艾德曼 | 0.7 |

顺序很重要：没有材料门槛的配方在最高级台上仍先返回 0.2。修复等没有普通 recipe 对象时，以产物的最硬金属材料代替门槛字段。依据 `bex.java:460–495`。能否制造的材料资格比较 `material.durability`，不是挖掘硬度；GUI 门槛见 `awy.java:168–191`，配方门槛来源见 `RecipeHelper.java:56–85`。

## 食物、受伤与交互

`uf.java:1735–1737` 的能量条件是 `satiation + nutrition != 0`。`MITEContainerCrafting.java:85` 仅在已启动且有能量时执行 `++crafting_ticks`；两者均零则暂停并保留已有进度，不除以五、不按饥饿比例降速。现代单 `FoodData` 如何暂代这两项资源需明确适配，不能把 `foodLevel > 0` 写成旧版原公式。

当前生命值没有进入周期公式，但受伤回退进度。`jv.java:818–822` 发送 `min(round(amount * 10F),32767)`，客户端 `bcw.java:1141–1142` 将该数乘五，从已有进度扣除且最低为零。例如 1 点伤害回退 50 tick，150→100；原进度 30 则归零。`amount` 指伤害回调中的量，不是攻击者的面板伤害。

`wd.java:143–188` 左键先检查结果存在、上半身蛛网、条件职业、铸币余额、维修失败标记、显示禁用标记及损坏组件，然后开始。松鼠标不取消。Shift 点击结果槽在 `uy.java:173` 被排除普通快速转移，仍走制造启动路径；它不会瞬间批量完成。

完成时结果整批入背包，装不下则掉落，再消费输入及处理容器物品（`wd.java:104–134`）。普通消费数为 1，特殊维修可设 `consumption`；材料不是开始时预扣。品质经验成本为零时持续做下一批；正成本完成一批后停止，计数归零（`MITEContainerCrafting.java:85–95`）。

每 tick 经 `checkCraftingResultIndex → modifyStackForRightClicks → updatePlayerCrafting` 重算周期和经验（`wd.java:244–287`），不只在点击时计算。等级、诅咒、工作台 metadata 改变且品质索引未变，已有进度保留；周期缩短可能立即达到完成条件。切品质重置进度，条件变化导致品质索引被夹回时进一步停止。产物栈改变、资格失败、关闭容器也清零；关闭返还或掉出输入。空能量只是暂停。

## 品质、经验与默认开关

`atv.java:156` 的 `professions_suppressed=true` 与 `is.java:86–87` 的配置读取后强制 false，说明发布版默认没有职业封锁。`WorldInfoShared.java:164` 仍读取存档 `are_skills_enabled`，`als.java:296–301` 返回世界字段；开发命令有切换路径。因此技能分支应保存为模式差异，不能全部删成无效代码。

品质独立存在：`yc.hasQuality` 默认 false，工具 `xj`、护甲 `wh`、`wp` 的覆盖返回 true。最低品质索引为 `clamp(average.ordinal + effectiveLevel/10,0,average.ordinal)`，笨拙诅咒先令有效等级减 20。Java 整数除法向零截断：负 9 级仍普通，负 10 至负 19 为劣质，负 20 起为最差。启用技能而缺少适用技能组时，最低品质至多为劣质；没有品质的产物或 `zw` 染色配方则直接不允许制作。

最高品质由物品材料上限和总经验确定：从材料允许的最高品质向下找，选择费用不超过总经验的最高档。总经验不正或缺少启用的技能时，返回最低品质。潜在费用为 `round(D/5F)`，笨拙再乘二；但无品质、普通或更低、以及显式费用豁免的结果实际费用为零。依据 `uf.java:2184–2224`、`wd.java:279–287`。例如基础难度 400：普通费用 0，精良难度 800、费用 160，优秀难度 1600、费用 320。

合并修理使用最低制造难度的一半、保留原品质且标记费用豁免；筋修理采用消费数×50（`aaf.java:311–351`）。铸币还通过 `ItemCoin.java:57–58` 的产物钩子扣面值，拆币回收经验（`wd.java:114–116,133–134`），不能把所有制造经验都概括为同一个品质费用字段。

## 服务端证据与现代移植边界

`uf.java:304–311` 每玩家 tick 更新容器；`MITEContainerCrafting.java:79–96` 只有客户端 `world.I` 分支推进计时、本地完成并发送 `Packet85SimpleSignal(crafting_completed)`。字节码在偏移 122 读取 `world.I`，125 跳过服务端，240–246 才递增客户端计数。完成包携带客户端品质经验成本。

`ka.java:861–867` 只检查当前槽 0 是 `wd`，使用**服务端当前结果栈**完成制造，再扣除载荷整数。字节码偏移 114 调用完成方法，122 取整数，125 取负，126 加入经验。这条路径没有重算计时/费用，也没有重新调用 `canPlayerCraftItem`；不能等同于可以传任意产物，服务器仍使用自己的配方和库存，品质索引也有服务器夹取路径。

完成后锁定变化槽是客户端同步措施：`uy.java:513–541`、`ka.java:975–976`、`bcw.java:1101–1102` 的锁定/解锁消息不构成服务端制造计时。`uf.java:1958–1962` 的基础 clear/reset 为空，实际字段及清除在客户端 `bex`，没有制造进度持久化路径。

另有需要主动修正的缓存边界：`MITEContainerCrafting.java:27–32` 只在结果物品栈不等价时重新初始化槽的 `crafting_result`；比较不包含配方、难度、技能、消费数量。因此相同输出但不同配方可能继续使用旧槽对象。这里只确认控制流，未以具体配方组合实测漏洞。

现代共享入口应由服务端保存配方 ID、完整输入指纹、品质、周期及进度；取出前重新校验、原子消费与扣费，客户端只负责显示和意图请求。Shift、数字键、双击、配方书及容器转移均需经过同一判定。相同输出的新配方也必须重新匹配，不能只比对产物。关闭、断线、死亡、跨维度、满背包、取消和多人同时操作需要明确规则并验证。

现代自动合成器没有原版 R196 的玩家等级、食物、品质选择及经验账户，必须单独规定设备周期和费用方式。新增现代配方的难度也须逐项适配；缺少数据不能默认为即时并宣称完成。本文是制造基础的可追溯规格，不是“全部物品制造已实现”的完成标记。
