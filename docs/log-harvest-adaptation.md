# 原木采集工具门槛适配（011）

开发者：NingMeng123。本文依据本地 MITE 1.6.4 R196 发布包，说明本轮规则、现代适配和验收预期；不声明自动测试或客户端实测已经完成。结构化依据见 [r196-log-harvest.json](../spec/r196-log-harvest.json)。

## 原作的实际限制

R196 原木 `arj` 使用木材材质，并把方块最低采集等级从 0 增加至 1（`arj.java:10–13`、`akc.java:623`）。`akc.requiresTool` 判断“材质要求工具，或方块最低等级大于 0”（`akc.java:324–325`），因此原木不能空手采集；木材材质本身并不意味着所有木制方块都需要斧头。

`uf.getCurrentPlayerStrVsBlock` 的顺序是零硬度、便携方块、持物强度、空手回退，再处理效果、环境、食物和等级（`uf.java:774–828`）。普通物品的 `getStrVsBlock` 为 0（`yc.java:559–560`）；工具必须同时对目标有效且采集等级不低于方块门槛，否则也返回 0（`xj.java:125–138`）。持物强度小于 1 时重新按空手判断，需工具方块得到强度 0，而非一种较慢的正速度。

关键字节码已复核：`uf` 偏移 65 检查便携；113 调用持物强度；122 的分支在强度不足 1 时走 125–133 的递归空手调用；186–199 将 `requiresTool` 转为强度 0 或 1。`xj.isEffectiveAgainstBlock` 偏移 61–70 比较工具与方块等级；`yc.getStrVsBlock` 为 `fconst_0; freturn`。

工具等级计算是：材质门槛为 0 时取 0；金属取材质门槛；其他材料减 1（`xj.java:61–62`，字节码 0–43）。木材工具等级为 0，燧石为 1（`akc.java:623–624`）。R196 默认配方表没有注册木镐、木斧的制造路线（`aal.java:5` 中对应位置为 null），因此现代木斧的具体存留方式属于适配选择，不能称为逐项照搬旧物品。

强度 0 经 `uf.java:831–862` 得到破坏进度 0。正常客户端不发送开始挖掘包，也无法累计到完成（`bdc.java:141–143,190–200`）；正常玩法表现为**方块不能破坏**，不是“挖掉但不掉落”。原服务器对直接收到的完成信号校验较弱：`ka.java:285–288` 直接调用破坏，`jw.java:129–149` 先移除方块，再用强度判定是否掉落。本轮采用更严格的现代服务端校验，不保留这一旧缺口。

## 本轮现代规则

方块标签 `mite:logs_requiring_axe` 明确列出当前 1.21.1 原版 LOGS 家族的 **40 个方块 ID**，涵盖八种树木的原木、木块及去皮变体，以及绯红和诡异菌柄、菌核及其去皮变体。这里的范围扩展到旧版没有的现代方块，不推断这些方块存在 R196 原始对应物。

默认成员取自本机构建依赖中的 `data/minecraft/tags/block/logs.json` 及其子标签，而不是动态引用整个 `#minecraft:logs`，以免其他模组仅加入通用原木标签就被新门槛影响。**1.21.1 的竹块和去皮竹块不属于 LOGS，默认不在本轮限制内。** 数据包可通过该标签显式增删目标方块；第三方方块只有主动加入本标签后才受门槛影响。

对于受限制方块，主手必须非空，且同时满足：

1. `stack.canPerformAction(ItemAbilities.AXE_DIG)`。
2. `stack.getDestroySpeed(state) > 1.0f`，使用工具对目标的基础速度，不以急迫、等级或食物倍率替代工具资格。
3. `stack.isCorrectToolForDrops(state)`。
4. 不属于物品标签 `mite:below_log_mining_tier`；该标签默认仅包含 `minecraft:wooden_axe`。

空手、普通物品、错误工具和木斧因此不能积累原木破坏进度，也不能通过服务端最终破坏入口移除原木。燧石短斧及现代石、金、铁、钻石、下界合金斧可以通过本轮门槛。其他现代斧的放行仅表示适应原木这一阶段，不给它们编造完整 R196 材料等级。

第三方工具按能力、目标速度及掉落资格判定，不按 Java 类名或固定物品白名单判断；数据包可把需要降低原木采集资格的工具加入低阶标签。副手工具不代替主手资格。生存与冒险采集使用此门槛，原版冒险模式附加限制仍然有效；创造、旁观及已取消事件保留既有行为。通过门槛也不撤销其他模组或游戏本身的限制。

服务端在实际破坏时重新判断当前主手与目标状态，覆盖开始挖掘后切成空手、木斧或错误工具的情况；客户端表现与服务端最后判定使用相同资格规则。验证重点是方块保持原状、无方块掉落、无工具磨损，不能只检查客户端裂纹或空掉落列表。

## 保持可游玩的边界

已完成的 [燧石开局路线](flint-start-adaptation.md) 提供砂砾→碎片/燧石、皮革→筋或使用线、木棍→短斧，取得原木不依赖先造工作台或木斧。

木板和工作台不加入默认限制。R196 木板最低等级为 0、硬度 0.8（`art.java:9–13`、运行时注册数据 ID 5）；工作台最低等级为 0、硬度 1.6，且恒为便携方块（`arv.java:13–16,102–103`）。本轮保留现代木斧在木板、家具等未限制目标上的既有用途，不扩大封锁为所有木制方块。

R196 便携方块优先获得至少 `4×硬度` 的强度，在零级正常条件下工作台进度为 `1/128`。本轮**不恢复便携下限或 128 tick 时长**，木板、工作台仅要求不被新门槛额外阻止，继续使用已实现的现代输入与基础进度规则。石头、矿石、泥土、砂砾和树叶等未列入本标签的方块继续使用此前行为；不在本轮移植全部材料等级、错误工具掉落或矿业进度。

原木的有效硬度继续沿用上一功能对 `minecraft` 命名空间 LOGS 成员的 1.2 映射。第三方方块选择加入本轮门槛标签，不会因此自动获得 1.2 硬度；门槛标签与有效硬度映射是不同规则。

## 验收矩阵

以下为固定预期，不是已经取得的测试结果。

| 场景 | 预期 |
| --- | --- |
| 默认目标原木；空手、木棍、整燧石、碎片、剑、镐、铲、锄或木斧 | 进度 0；服务端最终破坏被拒绝；无掉落及磨损 |
| 默认目标原木；燧石短斧、石/金/铁/钻石/下界合金斧 | 门槛放行；原有速度、环境、饥饿、等级及磨损仍各执行一次 |
| 零级、食物正常、落地、无效果；短斧挖硬度 1.2 原木 | 单次进度 bits 为 `0x3b855555`；理论客户端有效 float 累加 246 次，不含输入与连挖冷却 |
| 急迫或高等级；主手仍是错误工具 | 不绕过工具门槛 |
| 副手为有效斧，主手为空或不合格 | 不绕过工具门槛 |
| 先持有效斧挖掘，再切不合格主手完成破坏 | 服务端拒绝，目标仍在 |
| 第三方工具缺 AXE_DIG、速度≤1、掉落资格为 false 或在低阶标签中 | 任一条件不满足均拒绝 |
| 第三方有效斧工具满足全部条件 | 放行，不依赖是否继承 AxeItem |
| 木板、工作台、竹块、石矿、土、砂砾、树叶 | 默认不被本轮门槛额外阻止 |
| 第三方原木只加入通用 LOGS 标签 | 默认不受影响；加入 mite 标签后才应用门槛 |
| 创造、旁观、冒险附加权限、其他已取消事件 | 保留相应模式和原有禁止行为，不被门槛放行所覆盖 |

客户端须验证正常输入下的不合格工具无法破坏、换短斧后可破坏；服务端测试须独立覆盖最终破坏和中途切工具。数据包标签同步/重载及扩展范围应有明确测试，不应将单机截图当作完整联机或兼容性验证。
